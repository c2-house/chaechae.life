### 목차

## 들어가며

Codex나 Claude Code를 쓰다 보면 작업마다 터미널을 열고 어느 에이전트가 어떤 파일을 고쳤는지 오가며 확인해야 합니다. Paseo는 이런 코딩 에이전트를 한 화면에서 실행하고 작업 내용을 살펴보는 개발 환경입니다. 모델 자체가 아니라 **기존 에이전트를 관리하는 인터페이스**에 가깝습니다.

Windows에서 Paseo 0.16.1을 설치하고 별도의 연습 저장소에 Codex를 연결해 README를 수정해봤습니다. 아래 화면은 그 과정에서 직접 캡처한 것입니다. 메뉴와 사용 가능한 모델은 버전과 연결된 계정에 따라 다를 수 있습니다.

## Paseo의 작업 방식

Paseo는 에이전트를 관리하는 데몬과 여기에 연결하는 데스크톱·모바일·웹·CLI 클라이언트로 구성됩니다. 데몬은 작업을 실제로 수행할 컴퓨터에서 돌아갑니다. 데스크톱 앱에는 데몬이 포함되어 앱 실행 시 자동으로 시작됩니다. 반면 원격 컴퓨터를 사용하려면 해당 기기의 데몬과 연결을 따로 구성해야 합니다.

프로젝트는 작업할 폴더이고 워크스페이스는 그 프로젝트에서 에이전트와 작업을 이어가는 공간입니다. 화면에서 에이전트 대화, 파일 편집과 변경 내용, 터미널을 살펴볼 수 있습니다. 공식 문서에는 여러 에이전트를 각각 Git worktree에서 병렬 실행하는 흐름도 안내되어 있습니다. Worktree는 하나의 Git 저장소에서 별도의 작업 디렉터리를 만드는 기능입니다. 이번 실습에서는 단순한 **로컬 작업**을 선택했기 때문에 원래 연습 폴더에 변경이 생겼습니다.

## 설치와 준비

[Paseo 다운로드 페이지](https://paseo.sh/download) 또는 [공식 릴리스](https://github.com/getpaseo/paseo/releases)에서 운영체제에 맞는 앱을 받습니다. 이번에는 Windows x64용 0.16.1을 사용했습니다. 해당 설치 파일은 릴리스에 게시된 SHA-256과 일치했지만 Windows 서명 확인에서는 서명이 없었습니다. **해시 일치는 게시자 서명을 대신하지 않습니다.** 설치 여부는 출처와 운영체제의 경고를 확인한 뒤 판단해야 합니다.

Paseo에는 코딩 에이전트가 포함되어 있지 않습니다. 사용할 공급자의 CLI를 별도로 설치하고 해당 공급자의 인증을 마쳐야 합니다. 이번 환경에서는 기존에 로그인된 Codex CLI 0.166.0을 사용했습니다. 계정 연결이나 요금제 가입 과정은 이 실습에서 새로 진행하지 않았습니다.

먼저 기존 프로젝트 대신 시험용 폴더와 Git 저장소를 준비합니다. 아래 예제는 `README.md`에 여행 준비 목록이 있고, 원격 저장소는 연결하지 않은 상태에서 시작했습니다. 실제 프로젝트라면 작업 전에 변경사항과 백업을 확인하세요.

## 워크스페이스와 첫 요청

Paseo에서 **프로젝트 추가**로 연습 폴더를 선택하고 **새 워크스페이스**를 엽니다. 프로젝트와 실행할 호스트를 확인한 뒤 로컬을 선택합니다. 입력창 아래에서는 에이전트 모델과 권한 설정을 확인할 수 있습니다.

<Image src="/paseo-coding-agent-guide/01-workspace.png" alt="Paseo의 새 워크스페이스에서 연습 프로젝트와 로컬 작업을 선택한 화면" caption="연습 프로젝트의 새 워크스페이스 화면입니다. 권한 설정은 요청 전 다시 확인합니다." />

위 캡처는 설정을 조정하는 중의 화면입니다. 실제 요청 시에는 Codex의 GPT-6.1-Sol과 **Default permissions**를 선택했습니다. 권한 모드는 에이전트가 파일과 명령에 접근하는 방식에 영향을 주므로 화면의 설명을 확인하고 필요한 범위만 허용하세요. 프롬프트에 제한을 적는 것만으로 보안 경계가 보장되는 것은 아닙니다.

다음 요청을 입력하고 전송했습니다.

```text
README.md의 여행 준비물에 출발 전 확인할 항목 3개를 추가하고 변경 내용을 설명해 주세요. 이 저장소 밖은 수정하지 말고 네트워크 접속이나 Git 커밋과 푸시는 하지 마세요.
```

<Image src="/paseo-coding-agent-guide/02-request.png" alt="Paseo 입력창에 README 수정을 요청한 한국어 프롬프트" caption="연습 저장소 안에서만 작업하고 커밋과 푸시는 하지 않도록 요청했습니다." />

작업 중 승인 요청이 표시된다면 어떤 명령이나 파일 접근을 허용하는지 먼저 살펴보세요. 예상 범위와 다르면 승인하지 말고 요청을 좁히거나 작업을 중단할 수 있습니다.

## 변경 결과 확인

응답이 끝나면 대화에서 변경 설명을 읽고 실제 파일의 차이도 확인합니다. 이번 실행에서는 `README.md`의 기존 준비물 세 항목 아래에 다음 세 항목이 추가됐습니다.

```diff
+- 여행지 날씨 및 기온 확인
+- 휴대전화와 보조배터리 충전 상태 확인
+- 출발 전 가스 밸브와 문단속 확인
```

<Image src="/paseo-coding-agent-guide/03-result.png" alt="Paseo에서 README 수정 결과를 설명하는 Codex 응답" caption="작업 응답과 별도로 Git diff에서도 추가된 세 줄을 확인했습니다." />

독자도 프로젝트 폴더에서 `git diff -- README.md`를 실행하면 저장된 파일의 이전 상태와 현재 상태를 비교할 수 있습니다. 이번 연습 저장소에는 원격이 없었고 초기 커밋 이후 새 커밋 없이 README만 수정된 상태였습니다. 에이전트의 설명만 믿고 끝내기보다 실제 변경 파일과 내용을 검토하는 것이 좋습니다.

## 원격 연결과 비용

휴대전화나 다른 컴퓨터에서 보려면 작업을 실행하는 호스트에 데몬이 필요합니다. [공식 시작 안내](https://paseo.sh/docs)에 따르면 페어링용 암호화 릴레이를 사용할 수도 있고 직접 연결이나 VPN을 사용할 수도 있습니다. QR 코드와 연결 정보는 외부에 공개하지 마세요. 원격 연결이 곧 클라우드에서 코드가 실행된다는 뜻은 아닙니다. 파일과 명령은 연결된 데몬 호스트의 권한 범위에서 처리됩니다. 이번 실습에서는 원격 연결을 설정하지 않았습니다.

Paseo와 연결한 에이전트의 과금은 구분해서 봐야 합니다. Codex 사용 가능 여부와 한도는 연결한 OpenAI 계정 및 사용 방식에 따르며 구독에 포함된 사용과 API 사용은 별개입니다. 현재 조건은 [OpenAI Codex 안내](https://openai.com/codex/)와 계정의 사용량 화면에서 확인하세요. Paseo를 설치했다는 이유만으로 모델 사용량이 무제한이 되지는 않습니다.

여러 작업을 한곳에서 확인하고 변경 내용을 검토하고 싶다면 Paseo가 유용한 선택지입니다. 다만 에이전트의 권한·비용은 여전히 직접 확인해야 하고, 이미 단일 터미널 작업으로 충분하다면 새로운 관리 화면이 꼭 필요하지는 않습니다.
