요금표를 비교하거나 실패한 CI 로그를 찾아볼 때는 AI에게 질문하기 전부터 손이 많이 갑니다. 필요한 페이지를 열고, 내용을 복사하고, 파일을 내려받는 일은 여전히 사람이 해야 하기 때문입니다. Aside는 이런 준비 작업부터 브라우저 안의 에이전트에 맡기려는 제품입니다.

**Aside는 여러 사이트와 파일을 오가며 결과물을 만드는 AI 브라우저**입니다. 페이지 요약을 넘어 어떤 일을 맡길 수 있는지, 처음에는 요청 범위를 어떻게 정하면 좋을지 살펴보겠습니다. 공개 요금제 비교부터 CI 댓글 초안, 청구서 수집까지 권한을 조금씩 넓혀가는 예시로 설명합니다.

이 글은 **공식 자료를 바탕으로 한 제품 소개이며, 활용 요청은 실행 결과가 아닌 예시**입니다. 가격과 지원 환경, 개인정보·권한 조건은 2026년 9월 16일 기준입니다. 다운로드 경로 확인과 CLI 설치 스크립트 실행까지만 진행했으며, Aside 앱 설치·계정 연결·실제 업무 수행은 하지 않았습니다.

## Chromium 기반의 독립 브라우저

Aside는 크롬 확장 프로그램이 아니라 **Chromium 기반의 독립 브라우저**입니다. 기존 브라우저에 요약 버튼만 추가하는 확장 프로그램과는 다르게, 탭·브라우저 프로필·에이전트 작업·메모리·비밀번호 관리 기능을 함께 제공합니다. Chromium 기반이라는 점은 [공식 릴리스 노트](https://docs.aside.com/changelog/native)에서도 확인할 수 있습니다.

<Image src="/aside-browser-first-tasks/01-official-intro.png" alt="Windows 다운로드 버튼과 브라우저 제품 예시를 보여주는 Aside 공식 홈페이지" caption="출처: aside.com, 2026년 9월 15일 캡처. 공식 홈페이지의 제품 소개 화면입니다." />

일반적인 챗봇에 ‘이 청구서를 정리해줘’라고 하면 먼저 사람이 파일을 구해 전달해야 합니다. Aside가 제안하는 방식은 ‘이 사이트에서 이번 달 청구서를 찾아 정리해줘’에 가깝습니다. 에이전트가 허용된 로그인 상태와 페이지를 이용해 필요한 자료를 찾는 것입니다.

[공식 소개](https://aside.com/features/browser-agent)는 로그인, 커뮤니케이션, 문서·스프레드시트 작업을 주요 용도로 제시합니다. 서비스마다 전용 API 연동을 먼저 구성하는 대신, 사람이 쓰는 웹사이트를 직접 이용한다는 접근입니다.

물론 **별도 연동이 덜 필요하다는 것과 아무 사이트에서나 반드시 성공한다는 것은 다릅니다.** 페이지 구조 변경, 인증 절차, 권한과 서비스 정책에 영향을 받습니다. 웹 업무의 유연성을 얻는 대신, 결과를 확인하는 과정까지 없애지는 못합니다.

## 개발사와 공동 창업자

개발사는 **Aside Computer Inc.**입니다. [공식 소개문](https://aside.com/manifesto)은 샌프란시스코 기반의 Y Combinator 지원 팀이라고 설명합니다. [YC 회사 페이지](https://www.ycombinator.com/companies/aside)에는 2024년 설립, Fall 2025 배치 참여로 등록되어 있습니다. 2024년은 회사 설립 연도이지, 현재 브라우저의 출시 연도를 뜻하지는 않습니다.

YC에는 공동 창업자로 **Jun Kim(CEO), Chanhee Lee(CPO), Sanghun Lee(CTO)**가 기재되어 있습니다. Jun Kim과 Chanhee Lee는 Airbridge의 초기 엔지니어로 일한 경력도 소개합니다.

검색할 때 혼동하기 쉬운 부분도 있습니다. YC 페이지에는 영업 통화를 듣고 실시간 답변을 제공하던 **과거 제품의 출시 소개**가 함께 남아 있습니다. 지금의 회사 설명과 aside.com은 AI 브라우저를 소개합니다. 오래된 영업 보조 도구 설명을 현재 브라우저의 기능으로 섞어 읽지 않는 것이 좋겠습니다.

## 작업·메모리·비밀번호 관리

### 작업 요청과 결과물

[작업 문서](https://docs.aside.com/help/tasks)는 여러 번의 탐색·검색·파일 작업·승인이 필요한 업무를 대상으로 설명합니다. 페이지 하나를 이해하는 질문부터 여러 사이트를 거치는 작업까지 맡길 수 있고, 생성하거나 수정한 파일은 작업 상세 페이지에서 확인할 수 있습니다.

예를 들면 ‘가격 알려줘’보다 **‘공식 요금표에서 월간 결제액과 무료 한도를 비교하고 각 항목에 출처 링크를 달아줘’**가 좋은 요청입니다. 에이전트가 무엇을 찾아야 하는지와 사람이 무엇으로 완료를 판단할지가 함께 정해집니다.

현재 페이지에서 시작할 때는 사이드 패널을 열고 페이지 첨부를 유지합니다. [사이드 패널 문서](https://docs.aside.com/help/side-panel)에 따르면 첨부에는 제목과 호스트명이 표시됩니다. 엉뚱한 탭이 붙어 있지 않은지 확인하는 것이 첫 단계입니다.

### 작업 맥락을 이어주는 메모리

Aside의 [메모리 기능](https://aside.com/features/memory)은 방문 기록과 작업에서 중요한 맥락을 남겨, 같은 설명을 반복하는 일을 줄이려는 기능입니다. 어떤 사이트에서 어떤 경로가 통했는지 기억하는 사이트별 메모리도 소개합니다.

메모리는 기기에 Markdown으로 저장하며 확인·편집할 수 있다고 안내합니다. [설정 문서](https://docs.aside.com/help/memory)에서는 메모리 생성 여부와 일화적 메모리의 보관 기간을 `Never forget`, `30 days`, `90 days` 중 선택하도록 설명합니다.

매번 작업 배경을 다시 설명하지 않아도 된다는 점은 반복 업무에서 유용하겠습니다. 다만 잘못된 프로젝트나 고객을 연결한 맥락도 남을 수 있으니, 결과가 어긋난다면 메모리를 열어 수정하는 과정이 필요합니다. 기억한 내용과 최신 사실이 같은지도 함께 봐야 합니다.

### Aside Vault와 로그인 승인

Aside Vault는 에이전트가 비밀번호 원문을 읽지 않고, 허용된 사이트에 자동완성을 사용하도록 설계한 비밀번호 관리자입니다. [공식 설명](https://aside.com/features/password-manager)은 사이트별 접근 제어와 사용 로그를 강조합니다.

다만 로그인할 수 있다고 모든 인증이 끝나는 것은 아닙니다. [문제 해결 문서](https://docs.aside.com/help/troubleshooting)는 MFA, 패스키 승인, CAPTCHA, 본인 확인이 나오면 사람이 해당 단계를 완료하고 작업을 재개하도록 안내합니다.

**비밀번호 원문을 숨기는 것과 로그인 후 계정에서 위험한 행동을 하지 않는 것은 별개의 문제**입니다. 처음부터 주 계정의 비밀번호와 방문 기록을 전부 가져오기보다, 공개 사이트나 별도 테스트 프로필에서 동작을 파악하는 편을 권합니다.

## Windows 지원과 설치 경로

2026년 9월 16일 다시 확인한 [브라우저 릴리스 노트](https://docs.aside.com/changelog/native)는 **v1.0.914.1에서 Windows 정식 제공**을 명시합니다. 공식 사이트에서도 Windows 다운로드 버튼을 확인했습니다.

9월 15일 [공식 Windows 다운로드 경로](https://aside.com/api/download/windows)를 확인했을 때는 `AsideInstaller-1.0.914.1-win-x64.exe`로 연결됐습니다.

한편 [시작 문서](https://docs.aside.com/help/get-started)는 아직 macOS 15.0 이상만 안내합니다. 그래서 이 문서 하나만 보고 ‘macOS 전용’이라고 정리하면 최신 릴리스와 맞지 않습니다.

CLI의 설치 환경은 브라우저와 구분해야 합니다. 9월 15일 개발자 문서의 `install.sh`를 검토한 뒤 Windows Git Bash에서 실행해봤습니다. macOS·Linux만 지원한다는 플랫폼 검사에서 중단돼 CLI는 설치되지 않았습니다. **Windows 브라우저 지원을 CLI 셸 설치 스크립트의 Windows 지원으로 확대해 읽으면 안 됩니다.** 반대로 Linux CLI 지원이 Linux용 GUI 브라우저 제공을 뜻하지도 않습니다.

처음 사용하는 분이라면 [공식 다운로드 페이지](https://aside.com/download)에서 브라우저를 설치하는 경로부터 확인하면 됩니다. CLI·MCP 연결은 브라우저에서 작은 작업을 해본 뒤 필요한 경우에 추가해도 늦지 않습니다.

## 처음 시도할 작업 예시

처음부터 ‘내 업무를 전부 처리해줘’라고 요청하면 무엇을 확인해야 할지 막막합니다. **입력과 출력이 분명하고, 잘못해도 복구하기 쉬운 작업**부터 고르는 편이 좋습니다. 공개 자료 읽기, 댓글 초안 작성, 제한된 폴더에 파일 저장하기 순서로 범위를 넓혀볼 수 있습니다.

### 공개 요금제 비교

로그인이 필요 없는 공개 자료부터 시작하면 계정 권한을 주지 않고도 탐색과 출처 정리 능력을 확인할 수 있습니다. 사용 중이거나 도입을 검토하는 SaaS 두 개를 골라 다음처럼 요청해보세요.

```text
아래 두 공식 요금 페이지를 비교해줘.
[서비스 A 공식 URL]
[서비스 B 공식 URL]

월간 결제액, 연간 결제 조건, 무료 한도, 초과 비용을 정리해줘.
각 항목에 출처 링크와 확인한 문장을 붙여줘.
가격이 공개되지 않았거나 문서끼리 다르면 추측하지 말고 표시해줘.
회원가입·결제·파일 다운로드는 하지 말고 결과를 이 대화에만 보여줘.
```

검수할 때는 숫자만 보지 말고, 월 환산액을 월간 결제액으로 잘못 읽었는지와 별도 요금 조건을 빠뜨리지 않았는지 확인합니다. 인용한 링크를 직접 열어 원문과 맞춰보는 것이 완료 기준입니다.

여러 출처를 오래 비교하는 작업에는 [Ultrabrowse](https://docs.aside.com/help/ultrabrowse)가 별도로 안내되어 있습니다. 다만 유료 플랜 기능이므로, 처음에는 일반 작업으로 범위를 작게 잡아보는 편이 낫습니다.

### CI 실패 분석과 댓글 초안

개발자라면 [Aside의 개발자 활용 가이드](https://aside.com/blog/developers)가 제시하는 CI 근거 수집이 좋은 후보입니다. 코드 변경은 코딩 에이전트에 맡기고, Aside는 브라우저에 있는 로그와 화면을 확인하는 식으로 역할을 나눕니다.

```text
이 GitHub Actions 실행에서 처음 실패한 단계를 찾아줘: [실행 URL]
가능하면 같은 워크플로의 직전 성공 실행과 비교해줘.
실패한 명령, 관련 로그 링크, 확인된 사실과 추정을 구분해서
짧은 PR 댓글 초안을 이 대화에 작성해줘.
댓글 게시·워크플로 재실행·코드 변경·설정 변경은 하지 마.
```

공개 저장소 로그부터 시도할 수 있습니다. 비공개 저장소라면 조직의 외부 AI 이용 정책과 페이지 내용 전송 조건을 먼저 확인해야 합니다.

결과에서는 마지막에 나온 연쇄 오류보다 **처음 실패한 단계가 맞는지**를 봅니다. ‘의존성 문제인 것 같다’는 추정만 있고 로그 링크가 없다면 근거 수집이 끝난 것이 아닙니다. 실제 댓글 게시도 사람이 검토한 뒤 별도로 결정합니다.

### 청구서 PDF 수집

앞의 읽기 작업에 익숙해졌다면, 본인이 접근 권한을 가진 계정에서 파일 수집을 시험할 수 있습니다. [사이드 패널 문서](https://docs.aside.com/help/side-panel)도 청구서·영수증 수집을 예로 듭니다.

이 단계는 로그인과 로컬 파일 쓰기가 필요하므로, 앞의 두 작업보다 권한을 넓히는 실험입니다. 빈 테스트 폴더를 작업 폴더로 지정하고 대상 월과 문서 종류를 좁혀주세요.

```text
현재 청구 페이지에서 지난달 청구서 PDF만 찾아
내가 지정한 테스트 폴더에 저장해줘.
파일명은 청구일과 업체명으로 만들고, 같은 이름이 있으면 덮어쓰지 마.
원본 문서 링크와 저장한 파일 목록을 대화에 남겨줘.
결제·구독 변경·메일 발송·다른 폴더 접근은 하지 마.
추가 인증이 필요하면 멈추고 알려줘.
```

완료 후에는 PDF가 실제로 열리는지, 다른 달이나 다른 계정의 문서를 받지 않았는지, 목록과 저장 파일이 맞는지 확인합니다. 문서 내용에는 민감한 정보가 들어갈 수 있으므로 회사 청구서보다 테스트 가능한 자료부터 시작하는 편이 안전합니다.

## Routines와 개발 도구 연결

Aside는 [Routines](https://docs.aside.com/help/automation)로 반복 작업을 지원합니다. Cron routine은 정해진 시간에 새 작업을 시작하고, Heartbeat routine은 기존 대화를 깨워 이어가는 방식입니다.

예를 들어 공식 릴리스 노트를 확인해 변경점을 정리하는 브리핑을 만들 수 있습니다. 하지만 처음부터 매일 자동 실행하기보다는, 같은 요청을 수동으로 실행해 출처와 누락을 확인한 뒤 일정으로 바꾸는 편이 좋습니다.

문서에 따르면 겹치는 루틴 실행은 건너뛰고, 대상 대화가 없으면 루틴을 일시 중지합니다. 이 동작만으로 **컴퓨터를 꺼둔 상태에서도 실행된다고 볼 수는 없습니다.** 자동화에 쓰려면 실행 환경과 대기 조건, 플랜별 기능을 먼저 확인해야 합니다. 백그라운드 실행과 Cloud handoff의 실제 동작은 이 글의 검증 범위에 포함되지 않습니다.

개발자용으로는 [CLI·MCP·REPL](https://docs.aside.com/help/developers)도 제공합니다. CLI는 터미널에서 작업을 요청하는 경로, MCP는 다른 에이전트가 Aside를 도구로 쓰는 연결, REPL은 페이지 검사와 스크린샷 같은 단계를 직접 제어하는 실행 환경입니다.

[기존 Playwright CLI·MCP 비교 글](/blog/playwright-cli-vs-mcp)이 브라우저 제어 인터페이스 선택을 다뤘다면, Aside는 브라우저와 계정 상태·메모리·작업 UI를 함께 쓰는 제품 선택에 가깝습니다. 브라우저 조작이 필요한 모든 작업을 하나의 도구로 통일할 필요는 없습니다.

## 플랜 가격과 모델 이용 비용

2026년 9월 16일 재확인한 [공식 가격 페이지](https://aside.com/pricing)의 표시 가격입니다. 달러 기준이며, 연간 가격은 월 환산액이 아니라 일 년 결제 금액입니다. 세금과 지역별 최종 결제액은 결제 화면에서 별도로 확인해야 합니다.

| 플랜 | 표시 가격 | 처음 선택할 때 볼 조건 |
| --- | --- | --- |
| Free | $0 | 월 500크레딧, 활성 루틴 최대 3개, 비밀번호 관리자·메모리 |
| Pro | 월 $20 또는 연 $200 | Ultrabrowse, 무제한 활성 루틴, Free보다 많은 사용량 |
| Max | 월 $200 또는 연 $2,000 | 더 큰 사용량과 얼리 액세스 |
| Enterprise | 영업 문의 | 팀 계정·프로필·금고·관리 기능 |

한 가지 불일치는 남아 있습니다. 가격 페이지는 Max를 Free의 **40배**, [구독 도움말](https://docs.aside.com/help/subscription)은 **30배**로 설명합니다. 두 안내가 일치하지 않으므로 정확한 포함량은 결제 화면과 지원팀에서 확인하는 편이 좋습니다.

또 월 500크레딧이 곧 ‘500개 작업’은 아닙니다. [구독 도움말](https://docs.aside.com/help/subscription)은 작업·모델별 사용량 내역을 안내하지만, 모든 작업에 적용할 고정 차감량은 제시하지 않습니다. 실제 사용량은 `Settings > Plan & Usage`에서 확인할 수 있습니다.

모델을 쓰는 경로는 [공식 AI 설정 문서](https://docs.aside.com/help/ai) 기준으로 세 가지입니다.

- **Aside 플랜 모델:** Aside 계정과 플랜에 포함된 모델을 사용합니다.
- **기존 구독 연결:** ChatGPT Plus·Pro, Claude Pro·Max, GitHub Copilot 구독 연결을 안내합니다.
- **API 키 연결:** 본인의 모델 제공업체 계정으로 요청을 보냅니다. API 사용료는 해당 계정에 청구될 수 있습니다.

외부 구독 연결은 `Settings > Models > Providers`에서 `Connect` 후 `Subscription`을 선택하는 OAuth 흐름으로 안내되어 있습니다. 브라우저 채팅에 비밀번호나 API 키를 직접 붙여넣으라는 의미가 아닙니다.

**Aside 크레딧과 외부 구독·API 비용은 별개**입니다. ‘이미 ChatGPT를 결제했으니 Aside의 유료 기능도 모두 무료’라거나 ‘API를 연결하면 사용량 제한이 사라진다’고 해석해서는 안 됩니다. Aside의 연결 지원과 외부 제공업체의 이용약관·사용 한도도 따로 확인할 사항입니다.

## 메모리 저장과 데이터 전송

Aside 홈페이지에는 작업·메모리·데이터가 기기에 남으며 LLM 제공업체와 공유되지 않는다는 문구가 있습니다. 그런데 [개인정보처리방침 4절](https://aside.com/policy/privacy)은 **호스팅 AI 모델 제공업체가 작업 실행에 필요한 문맥을 받는다**고 구체적으로 설명합니다.

그 문맥에는 프롬프트·지시사항·도구 결과·선택된 브라우저 스냅샷·스크린샷·파일·모델 응답이 포함될 수 있습니다. 즉, **작업 기록과 메모리의 로컬 저장, 모델 추론을 위한 데이터 전송은 별개**입니다. 회사 문서나 청구서를 맡기기 전에는 저장 위치만 볼 것이 아니라 어떤 내용이 모델에 전달되는지까지 확인해야 합니다. 완전 로컬 추론이나 무전송을 보장하는 제품으로 이해해서는 안 됩니다.

[약관](https://aside.com/policy/terms)은 기본적으로 사용자 콘텐츠 등을 AI 학습에 사용하지 않는다고 설명합니다. 이것도 전송 자체가 없다는 의미는 아닙니다. 외부 모델을 연결하면 해당 제공업체의 정책도 적용되며, 모든 제공업체의 무보관을 동일하게 보장하지는 않습니다. [개인정보 설정](https://docs.aside.com/help/privacy) 문서는 분석 공유가 기본적으로 켜져 있다고 안내하므로, `Settings > Security & Privacy`에서 원하는 범위인지 확인하는 것이 좋습니다.

권한에서는 [공식 문서](https://docs.aside.com/help/security)의 `Allow`, `Ask`, `Deny`와 작업별 모드를 함께 봐야 합니다. 새 작업의 기본 모드는 `Guard`이며, 승인된 폴더에서 작업하고 다른 폴더 접근은 묻도록 설명합니다. `Full access`는 파일 접근 범위를 크게 넓힙니다.

읽기 중심 작업이라면 `Read only`를 우선 검토할 수 있습니다. 문서는 이 모드를 파일을 변경하지 않고 브라우저와 파일 문맥을 살펴보는 용도로 설명합니다. **이름만 보고 원격 사이트의 댓글 게시나 결제까지 모두 차단된다고 가정해서는 안 됩니다.** 발송·게시·결제를 맡기지 않을 때는 요청에 금지 범위를 적고 도구 권한도 함께 확인해야 합니다.

홈페이지는 민감 작업의 사람 승인을 강조하지만, 약관은 프롬프트 인젝션이나 의도치 않은 행동이 완전히 방지된다고 보장하지 않습니다. 그래서 첫 사용부터 실계정 결제나 대량 메시지 발송을 맡기는 것은 권하지 않습니다. 브라우저가 가진 세션과 쿠키는 편리한 작업 맥락인 동시에 실제 계정 권한이기도 합니다.

## Aside가 어울리는 작업

Aside는 공개 자료 조사, 브라우저에서만 볼 수 있는 로그 확인, 파일 수집처럼 **여러 탭의 정보를 모아 결과물로 만드는 사람**에게 흥미로운 선택입니다. 특히 코딩 에이전트가 저장소 안에서 작업하는 동안, 웹에 흩어진 근거를 따로 수집하는 역할이 잘 어울립니다.

반대로 단일 페이지 요약만 필요하다면 기존 도구로 충분할 수 있습니다. 회사의 외부 AI 전송 정책이 엄격하거나, 늘 같은 입력을 정확히 처리해야 하는 업무라면 승인된 API·기존 자동화를 먼저 검토하는 편이 낫습니다. 공식 사이트의 벤치마크 1위 주장도 자사 평가이므로, 자신의 업무에서 얻을 결과와는 구분해서 볼 필요가 있습니다.

기본 브라우저를 바로 바꾸기보다는 공개 사이트 두 곳을 비교하는 요청 하나로 시작해보면 좋겠습니다. 출처를 확인하고 빠진 조건을 보완하는 데 드는 수고까지 살펴보세요. **검수할 수 있는 결과를 남기면서 탭 사이를 오가는 일을 줄여주는지**가 Aside를 계속 쓸지 판단하는 기준이 될 것입니다.
