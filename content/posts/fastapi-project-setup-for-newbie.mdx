### 목차

## FastAPI 프로젝트를 시작하는 명령어

이번 포스팅을 FastAPI로 프로젝트를 시작하는 초보자를 위한 글입니다. FastAPI를 프로젝트를 시작하기 전에 `uv`를 설치하는 것을 강력하게 권장합니다. 

<Link url="https://chaechae.life/blog/python-uv" />

FastAPI는 `fastapi-new`로 프로젝트를 시작할 수 있습니다. **uv기반으로 프로젝트의 기본 세팅**을 해줍니다.

```bash
uvx fastapi-new <프로젝트명>
```

<Image alt="fastapi-new 실행" caption="fastapi-new 실행" src="/fastapi-project-setup-for-newbie/01.png" />

위 명령을 실행하면 다음과 같은 구조로 프로젝트가 생성됩니다. `main.py`가 루트에 생성되는데 `app`디렉토리를 만들어서 그 안에 넣어줍시다.

```bash
fastapi-start/
    ├── .venv/             # 파이썬 가상환경 디렉토리 (uv가 자동 생성 및 의존성 관리)
    ├── README.md          # 프로젝트 설명 및 기본 실행 방법이 적힌 마크다운 파일
    ├── main.py            # FastAPI 애플리케이션의 진입점 (Hello World 라우트 포함)
    ├── pyproject.toml     # 파이썬 프로젝트 메타데이터 및 의존성 목록을 정의하는 표준 파일
    └── uv.lock            # 패키지들의 정확한 버전을 고정하여 환경을 100% 재현 가능하게 해주는 잠금 파일
```

기존의 `pip install fastapi` **-> 가상환경 셋업 -> 파일 수동 생성** 이라는 번거로운 과정을 명령어 한 줄로 끝내줍니다.

`pyproject.tom`l과 `uv.lock`을 기본 제공하기 때문에, 현대 파이썬 개발의 표준이자 모범 사례를 그대로 따라갈 수 있게 해줍니다.

## FastAPI SKILL추가하기

FastAPI를 설치하면 내부에 Agent가 사용할 수 있는 SKILL이 저장되어 있습니다. **이제 코딩은 Agent가 하기 때문에 해당 스킬을 사용할 수 있도록 추가해주는 것이 좋겠습니다.** FastAPI 스킬을 추가하면 Agent가 최신 FastAPI 스타일에 맞게 코드를 작성합니다.

다음과 같은 명령으로 실행하면 쉽게 스킬을 추가할 수 있습니다.

```bash
uvx library-skills
```

<Image alt="library-skills 실행" caption="library-skills 실행" src="/fastapi-project-setup-for-newbie/02.png" />

실행 후 `.agents/skills/`  디렉토리 내부에 FastAPI 스킬과 스킬 관리 툴이 복사된 것을 확인할 수 있습니다. 단순히 `해서 나쁠 것 없는 설정`이라고 생각하실 수도 있지만, 최신 FastAPI 가이드를 따르기 떄문에 작업할 때 유용한 설정입니다.

## pre-commit 설정하기

AI Agent로 코딩하는 시대이지만 팀으로 작업을 한다면 지켜야할 규칙들이 반드시 존재할 것 입니다. **그런 것들을 미리 정해놓고 커밋 하기 전에 그것을 따르도록 할 수 있는 방법**이 있습니다. 바로 `pre-commit`을 사용하는 것입니다. 

<Link url="https://pre-commit.com/" />

다양한 작업들을 커밋 하기 전에 실행할 수 있습니다만, 대표적으로 린터 설정이 있습니다. 그리고 팀프로젝트를 진행할 때 초보자들의 경우 main 브랜치에 커밋하다가 커밋들이 막 꼬이는 경우들이 있는데 그런 것도 방지할 수있습니다.

다음과 같이 설치할 수 있습니다. pre-commit은 배포할 때는 필요 없기 때문에 `--dev`를 붙여줍니다.

```bash
uv add --dev pre-commit
```

설치가 완료된 후에 `.pre-commit-config.yaml`을 생성합니다. 아래는 하나의 예시 템플릿입니다.

```yaml
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v6.0.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-added-large-files
      - id: no-commit-to-branch # main 브랜치에 커밋 방지
        args: [--branch, main, --branch, master]

  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.16.1
    hooks:
	    # Run the linter.
	    - id: ruff-check
	      args: [ --fix ]
	    # Run the formatter.
	    - id: ruff-format
```

설정 파일을 만들었다면 팀원들 모두 각자의 로컬 환경에서 아래 명령어를 한 번씩 실행해야 합니다.

```bash
uv run pre-commit install
```

이제부터는 누군가 커밋을 시도할 때마다 코드가 팀의 규칙에 맞게 자동 포맷팅 되며, 만약 현재 위치가 main 브랜치라면 에러를 뿜으며 커밋을 아예 막아버립니다.

## Dockerfile 미리 만들기

보통 개발을 모두 마친 후에 배포 직전 Dockerfile을 작성하는 경우가 많습니다. 하지만 프로젝트 첫 세팅 단계에서 도커 환경을 미리 구성해 두는 것을 강력히 추천합니다. 처음부터 도커 빌드가 성공하는 뼈대를 만들어 두면, 개발 중간에 라이브러리를 추가하다가 OS 의존성 문제가 생겨도 즉각적으로 파악하고 고칠 수 있기 때문입니다. 소위 말하는 "내 컴퓨터에선 되는데 서버에선 안 되는데요?"라는 변명을 원천 차단할 수 있습니다.

`uv` 패키지 매니저의 캐시 시스템을 활용하는 빠르고 가벼운 Dockerfile을 작성해 보겠습니다.

먼저 `.dockerignore`를 만들어서 불필요한 파일이 도커 이미지에 포함되지 않게 합니다. 다음과 같이 예시를 만들어봤습니다.

```
.git
.venv
.ruff_cache
.github
.agents
__pycache__
*.pyc
.env
.pre-commit-config.yaml

```

이제 `Dockerfile`도 작성해줍니다.

```docker
FROM python:3.13-slim

# 공식 uv 이미지에서 uv 실행 파일만 복사
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

# 작업 디렉토리 설정
WORKDIR /app

# (선택 사항) 시스템 런타임 라이브러리가 필요한 경우 여기에 추가합니다.
# 예: Health check용 도구(curl), 타임존(tzdata) 등 파이썬 패키지 외의 OS 종속 라이브러리가 필요할 때
# RUN apt-get update && apt-get install -y --no-install-recommends \
#     curl tzdata \
#     && rm -rf /var/lib/apt/lists/*

# 시작 시간을 단축하기 위해 파이썬 바이트코드(.pyc) 컴파일 활성화
ENV UV_COMPILE_BYTECODE=1

# 의존성 파일 복사
COPY pyproject.toml uv.lock ./

# 의존성 설치
RUN uv sync --frozen --no-install-project --no-dev

# 나머지 애플리케이션 소스 코드 복사
COPY . .

# 애플리케이션 포트 개방
EXPOSE 8000

# FastAPI 서버 실행
CMD ["uv", "run", "fastapi", "run", "app/main.py", "--port", "8000", "--host", "0.0.0.0"]

```

이제 이미지를 빌드해보고 컨테이너까지 한 번 실행해서 잘 동작하는지 확인해봅니다. 잘 된다면 이제 프로젝트를 시작할 준비가 된 것 입니다.

## 마무리

지금까지 `uv`를 활용한 FastAPI 프로젝트 생성부터, AI 에이전트를 위한 스킬 주입, 팀 프로젝트의 평화를 지켜줄 `pre-commit` 설정, 그리고 배포의 두려움을 없애주는 `Dockerfile` 초기 세팅까지 모두 마쳤습니다. 초보일 때 프로젝트 시작하려고 하면 어떻게 시작해야하나 하는 생각에 스트레스 받곤 하는데 이 글이 도움이 되길 바랍니다.
