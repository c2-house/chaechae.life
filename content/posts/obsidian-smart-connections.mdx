옵시디언에 “휴대폰 로그인 화면을 고치자”라고 적었는데, 예전에 남긴 관련 메모의 제목이 기억나지 않을 때가 있습니다. 검색창에 `로그인`을 넣어도 당시에는 “스마트폰 회원 가입”이라고 써뒀다면 원하는 기록을 놓칠 수 있겠죠.

**Smart Connections는 지금 열어 둔 노트의 내용을 기준으로, 함께 읽을 만한 노트를 추천하는 커뮤니티 플러그인**입니다. 검색어를 정확히 떠올리지 않아도 시작할 수 있고, 기본 로컬 모델을 사용하면 API 키나 유료 AI 구독 없이 관련 노트를 찾을 수 있습니다. 다만 답변을 써주는 채팅이 아니라 **다시 열어볼 원문 후보를 찾는 도구**입니다.

2026년 10월 1일 기준 Windows 11의 별도 연습용 보관함에서 Obsidian 1.13.7과 Smart Connections Core 4.7.2를 실행했습니다. 한국어 노트로 모델 설정, 색인 상태, 관련 노트 추천과 원문 열기를 확인했습니다. 아래 화면은 이 연습 환경에서 직접 캡처한 것입니다.

## 기본 검색과 관련 노트 추천의 차이

옵시디언의 기본 검색은 기억나는 단어, 파일명, 태그를 찾을 때 편합니다. 반면 Smart Connections는 열려 있는 노트를 비교 기준으로 삼습니다. 노트를 읽거나 쓰는 동안 “이것과 연결해 볼 기록이 있었나?”를 확인하는 용도에 가깝습니다.

여기서 쓰는 **임베딩**은 글의 의미를 비교할 수 있도록 숫자로 바꾸는 과정입니다. 이 숫자를 미리 만들어 두는 작업을 색인 준비라고 생각하면 됩니다. 노트에 내부 링크나 태그가 없더라도 내용이 가까우면 후보가 될 수 있지만, 후보라는 이유로 두 기록이 같은 사실을 말하는 것은 아닙니다.

이름이 비슷한 기능은 다음처럼 구분해 두면 덜 헷갈립니다.

| 출발점 | 사용할 기능 | 받는 결과 |
| --- | --- | --- |
| 정확한 단어나 파일명을 알고 있음 | 옵시디언 기본 검색 | 해당 조건에 맞는 기록 |
| 지금 읽는 노트와 관련된 기록이 필요함 | Smart Connections | 현재 노트를 기준으로 정렬된 관련 노트 |
| 떠오르는 생각을 검색창에 직접 입력하고 싶음 | Smart Lookup | 입력한 의미와 가까운 원문 후보 |
| 여러 노트를 바탕으로 설명이나 요약이 필요함 | 별도의 Smart Chat 등 채팅 기능 | 선택한 자료를 이용한 생성 답변 |

**이번 글은 두 번째인 Connections에 집중합니다.** 이전의 [Claude Code로 노트에 질문하기](/blog/obsidian-claude-code-notes)나 [Agent Client로 Codex 연결하기](/blog/obsidian-codex-agent-client)처럼 대화를 보내거나 파일 수정을 맡기지 않습니다. [주제별 목차 만들기](/blog/obsidian-ai-topic-clusters)와도 달리, 먼저 분류 체계를 정리할 필요가 없습니다.

오래된 안내에서 Smart Connections 안의 `Lookup view`를 보셨을 수도 있습니다. **이번에 설치한 4.7.2의 Connections 설정에는 Lookup이 별도 플러그인으로 이동한다는 안내와 Install 버튼이 있었습니다.** 명령어 팔레트에서도 Lookup 명령은 없었습니다. 검색창이 안 보인다고 설치 실패로 판단하지 마세요. 직접 문장을 입력하는 검색은 [현재 Smart Lookup 문서](https://smartconnections.app/docs/lookup/)를 따르는 별도 흐름이며, 아래 관련 노트 추천에는 추가 설치가 필요하지 않습니다.

## 연습용 보관함과 플러그인 설치

### 지원 환경과 무료 범위

[공식 릴리스](https://github.com/brianpetro/obsidian-smart-connections/releases/tag/4.7.2)의 Core 4.7.2는 Obsidian 1.8.7 이상을 요구합니다. Obsidian은 Windows·macOS·Linux와 iOS·Android에서 제공되며, Smart Connections는 데스크톱 전용 플러그인이 아닙니다. 다만 아래 조작과 화면은 Windows 데스크톱 기준입니다. 모바일은 사이드바와 상태 표시 위치가 다를 수 있습니다.

[개발자 FAQ](https://smartconnections.app/smart-connections/faq/)에 따르면 **Core의 관련 노트 검색은 무료이고 기본 로컬 임베딩에는 API 키가 필요하지 않습니다.** Pro는 문단 옆의 Inline connections, 고급 필터와 순위 조정 등 추가 기능을 제공하는 별도 유료 선택지입니다. 이 글을 따라 하려고 Pro 체험이나 결제를 시작할 필요는 없습니다.

### 비교할 노트 준비

처음에는 개인 보관함 대신 `Smart-Connections-Demo`라는 빈 폴더를 만듭니다. 옵시디언의 보관함 관리 화면에서 **폴더를 보관함으로 열기 / Open folder as vault**로 그 폴더를 선택하세요. 보관함은 노트가 들어 있는 폴더를 뜻합니다.

다음 이름으로 새 노트 다섯 개를 만들고 내용을 넣습니다. 실제 업무 기록이 아닌 연습 자료입니다. 코드블록의 첫 줄은 노트 안의 제목이며, 파일도 같은 이름으로 저장합니다.

`모바일 로그인 개선.md`:

```markdown
# 모바일 로그인 개선

휴대폰에서 로그인할 때 입력창이 키보드 뒤로 가려집니다. 작은 화면에서 오류 메시지를 놓치지 않도록 입력창 바로 아래에 안내를 표시하려고 합니다. 가입 화면의 사용성 조사도 함께 찾아봅니다.
```

`가입 화면 관찰.md`:

```markdown
# 가입 화면 관찰

스마트폰으로 회원 가입을 할 때 사용자가 비밀번호 조건을 찾지 못했습니다. 가상 키보드가 뜨면 안내 문구가 가려졌습니다. 입력 필드 가까이에 짧은 오류 설명을 두고 작은 화면에서 다시 시험하기로 했습니다.
```

`접근성 점검.md`:

```markdown
# 접근성 점검

입력 오류를 색상만으로 알리지 말고 텍스트 설명도 제공합니다. 폼의 각 입력란에 이름을 붙이고 키보드로 이동할 수 있는지 확인합니다.
```

`커피 추출 기록.md`:

```markdown
# 커피 추출 기록

원두를 곱게 분쇄하고 물 온도를 조절했습니다. 추출 시간이 길어지면 쓴맛이 강해졌습니다. 다음에는 분쇄도를 굵게 바꿔 비교합니다.
```

`주말 산책.md`:

```markdown
# 주말 산책

공원에서 나무와 새를 관찰했습니다. 비가 오면 산책 대신 도서관에 가서 소설을 읽기로 했습니다.
```

첫 두 노트는 표현이 다르지만 작은 화면의 입력 안내라는 주제가 겹칩니다. 커피와 산책은 관계없는 후보를 구별하기 위한 자료입니다. 마지막 산책 노트는 짧은 기록이 색인에서 빠지는 경우도 확인하는 데 사용했습니다.

### Smart Connections 활성화

[공식 설치 안내](https://smartconnections.app/smart-connections/getting-started/)의 기본 경로는 다음과 같습니다.

1. 왼쪽 아래 톱니바퀴에서 **설정 → 커뮤니티 플러그인**을 엽니다.
2. 제한 모드 안내를 읽고, 신뢰할 수 있는 연습용 보관함에서 커뮤니티 플러그인 사용을 허용합니다.
3. **탐색 / Browse**에서 `Smart Connections`를 검색합니다.
4. 개발자가 Brian Petro이며 저장소가 `brianpetro/obsidian-smart-connections`인지 확인합니다.
5. **설치 / Install → 활성화 / Enable**를 누릅니다.
6. 설치된 플러그인 목록에서 Smart Connections 스위치가 켜져 있는지 확인합니다.

<Image src="/obsidian-smart-connections/01-install.webp" alt="옵시디언 커뮤니티 플러그인 목록에서 Smart Connections 4.7.2가 활성화된 화면" caption="Core 4.7.2 활성화 상태입니다. 이번 연습 환경은 공식 릴리스 파일을 넣는 수동 설치로 준비했습니다." />

수동 설치가 필요한 경우에는 위 릴리스의 `main.js`, `manifest.json`, `styles.css`를 보관함의 `.obsidian/plugins/smart-connections/`에 넣고 활성화할 수 있습니다. 처음이라면 탐색 메뉴를 이용하는 편이 간단합니다. 플러그인은 Obsidian이 직접 만드는 기능이 아니므로, 개인 자료를 연결하기 전에 출처와 처리 범위를 확인하세요.

## 로컬 모델과 색인 완료 확인

### Smart Environment 설정

활성화하면 관련 기능이 함께 쓰는 **Smart Environment**가 노트를 읽어 색인을 준비합니다. 이번 버전에서는 설정 왼쪽에 `Smart Environment`와 `Connections`가 각각 생겼습니다. 상태가 `Smart Environment not loaded`라면 **Load Smart Environment**를 눌러 시작합니다.

**설정 → Smart Environment → Default embedding model**에서 현재 모델을 확인하세요. 이번 새 보관함의 기본값은 `transformers - TaylorAI/bge-micro-v2`였습니다. `transformers`는 이 화면에서 로컬 모델을 실행하는 제공 방식이며, OpenAI API 키를 넣는 설정이 아닙니다.

기본값으로 먼저 결과를 확인해도 됩니다. 이번 한국어 예제에서는 비교를 위해 **Embedding models → Edit → Model → Multilingual E5 Small**로 바꿨습니다. 내부 모델 이름은 `Xenova/multilingual-e5-small`입니다. 한국어를 포함한 다국어 자료를 시험할 때 선택해 볼 수 있는 로컬 모델이지, 모든 한국어 노트에서 더 좋은 순위를 보장하는 설정은 아닙니다.

<Image src="/obsidian-smart-connections/02-model-settings.webp" alt="Smart Environment의 Edit model 창에서 로컬 Multilingual E5 Small 모델을 선택한 화면" caption="Provider는 transformers로 유지하고 Model만 Multilingual E5 Small로 선택했습니다. API 키나 채팅 모델은 설정하지 않았습니다." />

모델을 처음 사용할 때는 모델 파일을 내려받는 인터넷 연결이 필요할 수 있습니다. 로컬 처리라고 해서 설치부터 모든 과정이 무조건 오프라인인 것은 아닙니다. 다운로드와 색인 준비 중에는 앱을 켜 두고 완료 상태를 확인하세요.

모델 변경 뒤에는 선택값과 현재 모델을 다시 확인합니다. 이번 환경에서는 변경 후 새 임베딩이 준비됐습니다. 계속 이전 상태로 남는다면 [Smart Environment 안내](https://smartconnections.app/smart-environment/settings/)에 따라 진행 상태를 보고, 필요한 경우 **Re-index embeddings**를 사용합니다. 이 버튼은 선택된 모델의 임베딩을 다시 만드는 작업이며, **일상적인 모델 변경에 Reset data부터 누를 필요는 없습니다.** 재생성 안내에 원격 API 비용이 표시된다면 먼저 모델의 제공 방식을 확인하세요.

### Ready와 실제 처리 대상

Windows에서는 `Ctrl+P`, macOS에서는 `Command+P`로 명령어 팔레트를 열 수 있습니다. **Smart Connections: Open Environment Status View**를 실행하고 `Ready` 상태를 확인합니다. 이어서 **Environment stats**를 열면 처리 대상과 완료 수를 볼 수 있습니다.

<Image src="/obsidian-smart-connections/03-index.webp" alt="Smart Environment 통계에서 대상 네 개의 임베딩이 모두 준비되고 Needs embedding이 0인 화면" caption="연습 노트는 다섯 개지만 임베딩 대상은 네 개였습니다. 100%는 보관함 전체가 아니라 처리 가능한 대상에 대한 비율입니다." />

여기서는 **Eligible 4, Current embeddings 4, Needs embedding 0**이었습니다. 다섯 노트 중 `주말 산책.md`는 Skipped에 있었고, Inspect로 열어보니 `Below minimum size`가 이유였습니다. 짧은 노트가 빠졌는데도 완료율은 100%로 나올 수 있다는 뜻입니다.

또한 화면 위의 `Indexed items 15`는 노트와 블록을 합친 수이지, 노트 열다섯 개를 읽었다는 의미가 아닙니다. 이 예제에서는 **Smart Sources의 Total 5**로 노트 수를 확인해야 합니다. Sources는 노트 단위, Blocks는 노트 안의 작은 구간 단위입니다. 처음에는 노트 단위 결과로 시작하면 충분합니다.

## 현재 노트에서 관련 기록 찾기

### Connections 창 열기

1. 파일 목록에서 **모바일 로그인 개선** 노트를 엽니다. 빈 노트가 아니라 본문이 있는 노트를 사용하세요.
2. 명령어 팔레트에서 **Smart Connections: Open: Connections view**를 실행합니다.
3. 옆에 관련 노트 목록이 나타나는지 확인합니다.
4. 제목 옆의 작은 펼침 화살표를 눌러 후보의 본문을 읽습니다.
5. 전체 맥락이 필요하면 결과 제목을 눌러 원문 노트를 엽니다.

그래프보다 목록이 편하다면 **설정 → Connections → Display → Connections List Component → List only**로 바꿀 수 있습니다. 이번 결과 화면도 이 설정을 사용했습니다. 그래프를 끈다고 관련 노트 검색을 끄는 것은 아닙니다.

<Image src="/obsidian-smart-connections/04-results.webp" alt="모바일 로그인 개선 노트 옆에 가입 화면 관찰이 추천되고 해당 원문을 펼쳐 본 화면" caption="Multilingual E5 Small로 찾은 실제 결과입니다. 가입 화면 관찰을 펼쳐 읽고, 관련 이유를 확인한 뒤 원본 노트에 링크를 남겼습니다." />

이번에는 `가입 화면 관찰`이 가장 위에 나왔고, 제목을 눌렀을 때 실제 `가입 화면 관찰.md`가 열렸습니다. 그 노트에는 **가상 키보드 때문에 안내 문구가 가려졌다는 원문**이 있었습니다. 제목에 “로그인”이라는 단어가 없어도 함께 읽을 만한 기록을 찾은 것입니다.

하지만 목록 아래에는 `커피 추출 기록`도 나왔습니다. 이 노트는 지금 해결하려는 화면 문제와 관계가 없으므로 연결하지 않았습니다. **결과가 나타났다는 것과 쓸 만한 결과라는 것은 다릅니다.** 노트가 적은 연습 보관함에서는 특히 낮은 순위까지 모두 유용할 것이라고 기대하지 않는 편이 좋습니다.

### 점수와 자동 갱신

점수는 현재 기준 노트와 후보 사이의 유사도를 정렬하는 신호입니다. 화면의 `0.91`을 “91% 확률로 정답”이라고 읽으면 안 됩니다. 모델이나 노트 내용, 비교 대상이 달라지면 값도 달라지므로 다른 모델의 숫자만 비교해 성능을 판단하지 마세요.

기본 흐름에서는 다른 노트를 열면 추천 기준도 바뀝니다. 원래 노트의 후보 목록을 유지한 채 여러 결과를 읽고 싶다면 목록의 **Pause auto-refresh**를 사용합니다. 다시 현재 노트를 따라가려면 자동 갱신을 재개하세요. 목록 메뉴의 **Refresh connections**는 결과를 다시 확인할 때 사용합니다.

노트를 바꿨는데 결과가 맞지 않는다면 먼저 자동 갱신 상태와 현재 기준 노트를 확인하세요. 이때의 목록 새로고침은 임베딩 모델 전체를 다시 만드는 작업과 다릅니다.

## 확인한 원문을 링크로 남기기

추천을 받았다고 모든 결과를 연결할 필요는 없습니다. 이 예제에서는 `가입 화면 관찰`을 열어 다음을 대조하면 됩니다.

- 같은 문제를 다루는가: 작은 화면에서 입력 안내가 가려지는 상황입니다.
- 연결할 근거가 실제로 있는가: 가상 키보드가 뜨면 안내 문구가 가려졌다고 적혀 있습니다.
- 다른 사건을 같은 사건처럼 합치고 있지는 않은가: 로그인 개선과 가입 화면 관찰은 관련된 사례이지 동일한 작업 기록은 아닙니다.

확인한 뒤 `모바일 로그인 개선` 노트로 돌아와 아래처럼 직접 적습니다.

```markdown
관련 기록: [[가입 화면 관찰]] — 작은 화면에서 안내가 가려지는 사례
```

결과를 편집기로 끌어다 놓아 링크를 만들 수도 있습니다. 다만 처음에는 직접 입력해 보면 무엇이 추가되는지 분명합니다. 이번 연습에서도 이 링크 문구를 저장했으며, 후보 제목을 통한 원문 열기와 대상 파일의 존재를 확인했습니다.

독자의 앱에서는 읽기 보기로 전환한 뒤 링크를 눌러 **내용이 있는 기존 노트가 열리는지** 확인하세요. 새 빈 노트가 생긴다면 링크의 이름이나 경로를 잘못 적었을 수 있습니다. 같은 이름의 노트가 여러 폴더에 있다면 `[[폴더/가입 화면 관찰]]`처럼 경로를 포함합니다.

여기까지가 첫 작업의 완료 기준입니다. **의미 있는 후보 하나를 찾고, 원문에서 관련 이유를 확인하고, 다시 찾아갈 링크를 남기는 것**입니다. AI가 대신 요약하거나 원본을 합쳐야 완료되는 작업은 아닙니다.

## 빈 결과와 개인정보 점검

### 결과가 없거나 엉뚱한 경우

설정부터 이것저것 바꾸기보다 아래 순서로 확인해 보세요.

1. **노트 본문:** 제목만 있는 빈 노트 대신 구체적인 상황이 적힌 노트를 엽니다.
2. **준비 상태:** Environment Status View에서 Load, Resume embedding, 진행 중인 작업 여부를 확인합니다. Ready만 보지 말고 통계의 Needs embedding도 확인합니다.
3. **빠진 파일:** Environment stats의 Skipped → Inspect와 설정의 View all exclusions에서 제외 이유를 봅니다. 짧거나 제외된 노트는 색인이 끝나도 후보가 되지 않을 수 있습니다.
4. **검색 기준:** 다른 노트를 기준으로 멈춰 있는 것은 아닌지 자동 갱신과 기준 노트를 확인합니다.
5. **모델과 결과 유형:** 한국어 기록이라면 다국어 모델을 시험할 수 있습니다. 우선 Sources로 시작하고, 원문을 직접 읽어 바뀐 후보가 더 유용한지 판단합니다.

모델 변경이나 재색인은 시간이 걸릴 수 있습니다. “비슷한 결과가 안 나온다”는 이유만으로 API 키를 추가하거나 유료 모델로 바꾸는 것보다, 찾으려는 노트가 실제 처리 대상인지 확인하는 일이 먼저입니다.

### 로컬 처리와 외부 전송의 경계

[공식 FAQ](https://smartconnections.app/smart-connections/faq/)와 [개인정보 정책](https://smartconnections.app/legal/privacy-policy/)에서 구분하는 기본 경계는 다음과 같습니다.

- **기본 로컬 임베딩:** 노트의 의미를 기기에서 계산하고, 색인 데이터는 보관함의 `.smart-env/` 등에 저장합니다. 색인 준비 후 로컬 검색을 계속 사용할 수 있습니다.
- **원격 임베딩 제공자:** 사용자가 따로 구성하면 임베딩 대상 원문이 해당 제공자에게 전달됩니다. 결과를 누르는 순간뿐 아니라 색인을 만들거나 갱신하는 과정에서도 전송될 수 있습니다.
- **클라우드 채팅:** 별도로 선택한 채팅 기능에 보내는 질문과 문맥이 전송됩니다. Connections 결과를 찾는 작업 자체가 채팅 요청인 것은 아닙니다.

**Core가 무료라는 것과 외부 API 사용료가 무료라는 것은 별개입니다.** 원격 모델을 추가한다면 제공자의 요금과 데이터 처리 조건을 따로 확인해야 합니다. 이 글의 실행에서는 원격 API나 유료 기능을 사용하지 않았습니다.

또한 로컬 노트 처리를 서비스 전체의 “네트워크 통신 0”으로 해석하지는 마세요. 설치·업데이트·모델 다운로드에는 연결이 필요할 수 있고, 웹사이트·구독·지원·진단 정보에는 별도 정책이 적용됩니다.

민감한 폴더를 제외하려면 **Smart Environment → Manage excluded folders**를 사용하고 **View all exclusions**에서 반영 여부를 확인합니다. Connections의 결과 필터는 이미 만든 검색 대상에서 표시만 줄이는 기능이므로, **결과에서 숨기기와 색인 대상에서 제외하기는 다릅니다.** 처음부터 민감한 원본이 없는 연습 보관함으로 시작하는 이유입니다.

Smart Connections가 잘 맞는 순간은 “이 노트와 같이 읽을 기록이 있었는데”라는 생각이 들 때입니다. 정확한 단어를 찾을 때는 기본 검색이 더 빠르고 분명할 수 있습니다. 관련 노트 추천은 그 검색을 대체하기보다, 기억하지 못한 표현으로 남겨 둔 원문에 다시 도달하는 통로로 쓰는 편이 좋겠습니다.
