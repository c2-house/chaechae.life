### 목차

## 들어가며

대화를 지웠는데 새 답변에서 예전 직장이나 취향을 다시 언급한다면 **저장된 메모리와 답변의 Sources를 확인하세요.** 같은 정보가 다른 대화나 파일, 맞춤 지침에 남아 있을 수 있습니다.

2026년 10월 19일 OpenAI 공식 도움말을 기준으로 정리했습니다. 메모리 메뉴와 제공 기능은 플랜·지역·기기·워크스페이스 설정에 따라 다를 수 있습니다.

## 대화 기록과 메모리의 저장 범위

OpenAI의 [Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-in-chatgpt)는 저장된 메모리가 대화 기록과 별도로 보관된다고 설명합니다. 원래 대화를 삭제해도 그 대화에서 만들어진 별도 메모리가 자동으로 삭제되지는 않습니다. 반대로 메모리를 삭제해도 과거 대화에 이미 쓰인 문장까지 지워지지는 않습니다.

<Image src="/chatgpt-delete-memory/00.png" alt="ChatGPT의 대화 기록, 메모리, 다른 원본은 각각 확인해야 하는 별도 대상임을 보여주는 개념도" />

예를 들어 “저는 새봄회사에서 일합니다”라는 가상의 정보를 대화에서 말했고, 그 내용이 메모리에도 저장됐다고 해보겠습니다. 그 대화만 삭제하면 메모리 쪽에 정보가 남을 수 있습니다. 맞춤 지침이나 업로드한 자기소개서에도 같은 회사명이 있다면 그곳도 별도로 확인해야 합니다.

| 조작 | 바뀌는 것 | 별도로 남는 정보 |
| --- | --- | --- |
| 대화 삭제 | 해당 대화가 계정 화면에서 제거되고 서버 삭제 절차 진행 | 별도로 저장된 메모리, Library에 남은 파일 |
| 대화 보관 | 일반 사이드바에서 대화를 숨김 | 대화 내용 자체 |
| 저장된 메모리 삭제 | 해당 메모리를 향후 개인화에 사용하지 않도록 제거 | 과거 대화에 남은 같은 정보 |
| 메모리 끄기 | 개인화에 메모리를 사용하는 설정 변경 | 기존 대화 기록 |
| 모델 개선 끄기 | 새 대화의 모델 학습 사용 설정 변경 | 대화 기록과 메모리 |

보관한 대화는 사이드바에서 숨겨지며 검색으로 다시 찾을 수 있습니다.

## 답변의 출처와 메모리 설정

처음부터 ‘모든 대화 삭제’를 누르기보다, 문제가 된 정보 하나를 기준으로 확인하는 편이 안전합니다. 삭제한 대화는 ChatGPT 화면이나 고객 지원을 통해 복구할 수 없습니다.

### 답변 아래의 Sources

개인화에 사용된 정보가 있으면 답변 아래에 **Sources**가 표시될 수 있습니다. 여기서 과거 대화, 저장된 메모리, 맞춤 지침, 파일이나 연결된 이메일 등 어떤 자료가 사용됐는지 확인합니다.

- 저장된 메모리가 보이면 메모리 설정에서 해당 항목을 확인합니다.
- 다른 대화가 보이면 이미 지운 대화와 별개의 대화인지 확인합니다.
- 파일이나 연결 앱이 보이면 대화 기록만 지울 것이 아니라 그 자료의 접근·보관 상태를 확인합니다.

Sources에는 답변에 영향을 준 자료가 일부만 표시될 수 있습니다. 목록에 해당 정보가 없다면 메모리 설정과 원본도 확인하세요.

### 계정에 표시되는 메모리 메뉴

설정(Settings)을 열고 개인화(Personalization)의 메모리(Memory)로 이동합니다. 여기서 어떤 방식의 관리 화면이 표시되는지 봅니다. 아래 영문 항목은 공식 도움말의 표기이며 앱 언어에 따라 번역된 이름으로 보일 수 있습니다.

**Memory summary가 보이는 경우**에는 기억한 내용의 요약을 검토하고, 수정할 내용을 입력하거나 해당 문구를 선택해 교정할 수 있습니다. 요약에 보이지 않는 정보는 관련 대화나 파일에서도 찾아보세요.

**Saved memories 또는 Manage가 보이는 경우**에는 개별 저장 항목에서 해당 정보를 찾아 삭제합니다. 계정에 따라 기존 저장 메모리 방식과 개선된 메모리 방식 사이를 전환하는 메뉴도 제공됩니다.

여기서 조작의 의미도 구분해야 합니다.

- **Don't mention this again**은 해당 정보의 언급을 줄이는 옵션입니다. 원본 삭제는 자료가 저장된 곳에서 따로 합니다.
- **Delete and turn off memory**는 요약에 표시된 기억을 삭제하고 메모리를 끄는 동작입니다. 과거 대화를 함께 삭제하지는 않습니다.
- **Reference chat history**가 있는 계정에서 이 항목을 끄면, 과거 대화에서 기억한 정보가 OpenAI 시스템에서 30일 이내 삭제되도록 처리됩니다. 원래 대화와 별도 저장 메모리는 그대로 남습니다.

Reference saved memories가 별도 토글로 보이는 경우에는 이를 끄면 Reference chat history도 함께 꺼집니다. 반대로 저장 메모리 참조가 켜져 있을 때는 대화 기록 참조를 따로 관리할 수 있습니다. 필요한 것이 정보 하나의 수정인지, 개인화 전체의 중단인지부터 정한 뒤 변경하세요.

## 같은 정보가 남은 원본 확인

메모리를 다시 켜면 남아 있는 대화에서 같은 정보를 새로 기억할 수 있습니다. 없애려는 정보가 남은 원본을 찾아 정리하세요.

### 일반 대화와 보관된 대화

ChatGPT 검색에서 없애려는 정보와 관련된 대화를 찾습니다. 대화를 삭제하려면 해당 대화의 더보기 메뉴에서 **Delete**를 선택하고 확인합니다.

보관된 대화는 **Settings → Data controls → Archived chats 또는 View archived chats**에서 확인합니다. 화면에 Manage가 있으면 그 버튼을 선택합니다. 여기서 Unarchive는 일반 기록으로 되돌리는 동작이고, Delete는 삭제입니다.

한꺼번에 지우는 기능은 현재 계정이나 워크스페이스의 대화에 영향을 줄 수 있고 프로젝트 안의 대화도 포함될 수 있습니다. 특정 정보 하나가 문제라면 먼저 해당 대화를 골라 확인하고, 일괄 삭제 전에는 확인창의 범위를 읽어보세요.

### 맞춤 지침, Library와 연결 앱

대화 검색에서 찾지 못했다면 다른 입력 경로도 확인합니다.

**맞춤 지침**에 이전 회사나 거주 지역을 직접 적어뒀다면 그 지침을 수정해야 합니다.

**Library가 제공되는 계정**에서는 업로드하거나 생성한 파일이 대화와 별도로 저장될 수 있습니다. OpenAI의 [대화·파일 보관 정책](https://help.openai.com/en/articles/8983778-chat-and-file-retention-in-chatgpt)에 따르면 대화를 지워도 Library에 남은 파일은 삭제되지 않습니다. 파일까지 제거하려는 경우에는 Library의 해당 파일을 별도로 삭제해야 합니다.

**연결 앱**에 정보가 있다면 앞으로의 접근을 계속 허용할지 판단합니다. 앱 연결 해제는 향후 접근을 막지만, 이미 그 자료를 사용한 과거 대화를 지우지는 않습니다. 반대로 ChatGPT 대화를 지워도 원래 Gmail이나 Drive에 있던 자료까지 삭제되는 것은 아닙니다.

프로젝트에 올린 파일이나 커스텀 GPT의 지식 파일도 일반 대화와 보관 범위가 다릅니다. 회사·학교 계정은 조직의 보관 정책이 적용될 수 있으므로, 메뉴가 없거나 직접 관리할 수 없는 자료는 관리자에게 확인하는 편이 좋습니다.

앞의 가상 회사명 예시라면 다음처럼 범위를 좁힐 수 있습니다.

1. 메모리에서 ‘새봄회사’를 찾아 수정하거나 삭제합니다.
2. 같은 회사명이 있는 일반·보관 대화를 확인하고, 삭제가 필요한 대화만 선택합니다.
3. 맞춤 지침과 Library의 자기소개서에도 남아 있는지 확인합니다.
4. 연결 앱에 그 자료가 있다면 접근을 유지할지 결정합니다.

## 삭제 뒤의 확인과 반영 시간

설정을 바꾼 뒤에는 메모리 관리 화면을 다시 열어 삭제·수정한 항목을 확인하고, 대상 대화나 Library 파일도 해당 목록에서 확인합니다. 이어서 새 대화에서 이전 정보가 다시 등장하는지 살펴볼 수 있습니다.

이때 확인 질문에 지우려는 내용을 다시 자세히 적으면 그 내용 자체를 입력으로 제공하게 됩니다. “내 예전 회사는 새봄회사였는데 기억해?”보다, 새 대화에서 필요한 작업을 요청했을 때 불필요한 예전 회사 정보가 끼어드는지 살펴보는 편이 낫습니다.

새 대화에서 같은 정보가 다시 나오면 Sources와 맞춤 지침, 다른 원본을 확인하세요. 서버 보관 기간은 아래 정책을 기준으로 봅니다.

공식 문서는 삭제와 메모리 변경이 반영되기까지 시간이 걸릴 수 있다고 설명합니다. 대화는 계정 화면에서 즉시 제거되지만, OpenAI 시스템에서는 원칙적으로 30일 이내 영구 삭제되도록 예정됩니다. 이미 계정에서 분리·비식별화된 데이터이거나 보안·법률상 보관 의무가 있는 경우는 예외입니다. 삭제된 저장 메모리의 로그도 안전과 디버깅 목적으로 최대 30일 보관될 수 있습니다.

점검한 뒤에도 의도하지 않은 정보가 반복된다면 사용한 계정·워크스페이스, 조작한 메뉴, 변경 시각, 재현한 상황을 정리해 OpenAI 지원에 문의할 수 있습니다. 캡처에서는 이메일·회사 자료·다른 대화 내용처럼 문의에 필요하지 않은 정보는 가려주세요. 조직의 데이터 삭제 요청이라면 관리자와 조직의 보관 정책부터 함께 확인해야 합니다.

## 임시 채팅과 모델 개선 설정

**Settings → Data controls → Improve the model for everyone**을 끄면 새 대화의 모델 학습 사용을 중단할 수 있습니다. 대화 기록과 메모리 삭제는 각 저장 위치에서 진행합니다. 또한 응답에 좋아요·싫어요 등 피드백을 제출하면 그 피드백에 연결된 전체 대화가 모델 학습에 사용될 수 있다는 별도 조건도 있습니다.

대화 기록에 남기지 않을 질문이라면 임시 채팅을 고려할 수 있습니다. 다만 현재 공식 안내에서는 임시 채팅도 시작 전에 개인화 여부를 선택합니다.

1. 새 대화에서 **Temporary**를 선택합니다.
2. 첫 메시지를 보내기 전에 **Unpersonalized**를 선택합니다. 이 옵션은 메모리·맞춤 지침·플러그인을 사용하지 않습니다.
3. 대화 시작 후에는 개인화 선택을 바꿀 수 없으므로 처음 표시되는 상태를 확인합니다.

**Personalized**를 선택한 임시 채팅은 기존 메모리 등을 사용할 수 있습니다. 두 방식 모두 임시 상태인 동안에는 메모리를 만들거나 업데이트하지 않습니다.

임시 채팅을 일반 대화로 저장하면 그 시점부터 계정의 개인화·모델 개선 설정을 따릅니다. 임시 상태에서도 안전 목적으로 사본이 최대 30일 보관될 수 있고, 메모리·개인화 중단이 드물고 위험도가 높은 상황의 제한적 안전 맥락 사용까지 끄는 것은 아닙니다. GPT의 액션으로 제3자에게 데이터를 보냈다면 그 수신자의 개인정보 처리 정책도 별도로 적용됩니다.
