CSV를 엑셀로 열었더니 상품 코드 `00123`이 `123`으로 바뀌거나, 긴 주문 번호의 끝자리가 달라지는 경우가 있습니다. 숫자처럼 보이지만 계산할 값이 아닌데, Excel이 숫자로 해석하면서 생기는 문제입니다.

이럴 때는 파일을 연 다음 셀 모양부터 바꾸기보다 **CSV를 가져오는 단계에서 식별번호 열을 텍스트로 지정**하는 편이 안전합니다. 이미 사라진 앞자리 0이나 바뀐 끝자리는 서식을 바꾼다고 원래대로 돌아오지 않습니다. 원본 CSV가 그대로 있다면 그 파일에서 다시 가져와야 합니다.

아래 절차는 Windows 데스크톱 Microsoft Excel의 **데이터 → 텍스트/CSV에서** 기능을 기준으로 설명합니다. 2026년 10월 17일 공식 문서를 확인했고, Windows 11의 Excel 16.0, 빌드 20430에서 가상 CSV를 Power Query로 가져와 값과 자료형을 확인했습니다. 가져오기와 수식 계산은 자동화로 실행했으며, 메뉴 안내는 공식 절차를 바탕으로 정리했습니다.

## 계산할 숫자와 보존할 번호

먼저 열의 용도를 나누면 됩니다. 수량이나 금액은 더하고 빼야 하지만, 상품 코드나 주문 번호는 다른 기록과 **정확히 같은 문자열인지** 비교해야 합니다.

| 열의 용도 | 가져올 형식 | 이유 |
| --- | --- | --- |
| 상품 코드·우편번호·주문 식별번호 | 텍스트 | 앞자리 0과 전체 자릿수를 유지 |
| 수량 | 정수 | 합계와 개수 계산 |
| 가격·금액 | 값과 계산 목적에 맞는 숫자 형식 | 숫자로 계산하되 소수점·단위 확인 |

Microsoft는 Excel 숫자의 정밀도를 **유효 숫자 15자리**로 설명합니다. 따라서 16자리 이상의 식별번호를 워크시트의 숫자로 다루면 원래의 모든 자릿수를 보존할 수 없습니다. `1.23E+17` 같은 표시는 지수 표기법인데, 표시만 짧아진 경우와 실제 값의 끝자리가 바뀐 경우를 구분해야 합니다.

또한 CSV는 쉼표 같은 구분자로 나눈 텍스트 파일입니다. Excel 통합 문서처럼 셀의 텍스트 서식을 함께 저장하는 파일이 아닙니다. 같은 CSV라도 **어떤 프로그램이 어떤 형식으로 읽느냐**에 따라 결과가 달라질 수 있습니다. 파일 확장자를 `.xlsx`로 바꾸는 것만으로 해결되지 않는 이유이기도 합니다.

## 원본 CSV와 연습 데이터

작업 전에는 원본 CSV를 별도로 보관하세요. 이미 잘못 열린 파일이라면 원본에 덮어쓰지 말고 닫습니다. 원본이 손상되지 않았는지 확인할 때는 Excel이 아닌 메모장 같은 텍스트 편집기로 열어 실제 문자를 봅니다.

아래는 개인정보가 없는 가상 예제입니다. 연습하려면 메모장에 붙여넣고 **다른 이름으로 저장**을 선택하세요. 파일 형식은 `모든 파일`, 파일 이름은 `identifier-sample.csv`, 인코딩은 UTF-8로 지정합니다. 저장한 이름에 `.txt`가 추가되지 않았는지도 확인합니다.

```csv
item_code,record_id,quantity
00123,123456789012345678,2
00007,987654321098765432,5
```

첫 번째 열은 상품 코드, 두 번째 열은 가상의 식별번호, 세 번째 열은 수량입니다. **앞의 두 열만 텍스트**, 수량은 정수로 가져오겠습니다. 모든 열을 텍스트로 지정하면 번호는 보존되더라도 나중에 합계 계산에서 다시 변환 작업이 필요할 수 있습니다.

실제 고객 자료로 연습할 필요는 없습니다. 외부에서 받은 파일이라면 출처를 먼저 확인하고, 확인을 위해 매크로나 외부 콘텐츠를 무작정 허용하지 마세요. 이 예제에는 그런 기능이 없습니다.

## 텍스트 형식으로 가져오기

### CSV 미리 보기

CSV를 더블클릭하는 대신 새 Excel 통합 문서에서 시작합니다.

1. **데이터 → 텍스트/CSV에서**를 선택합니다. 리본 구성이 다르면 `데이터 가져오기 → 파일에서 → 텍스트/CSV에서` 경로를 확인합니다. 영문 메뉴는 `Data → From Text/CSV`입니다.
2. 원본 CSV를 선택하고 **가져오기**를 누릅니다.
3. 미리 보기에서 구분자를 확인합니다. 위 예제는 쉼표이므로 `item_code`, `record_id`, `quantity`가 서로 다른 세 열로 나뉘어야 합니다.
4. 한글이 들어 있는 파일은 문자 인코딩도 확인합니다. UTF-8로 저장한 파일이라면 해당 인코딩을 선택하고, 원본이 다른 인코딩이라면 그 파일에 맞춰야 합니다.
5. 곧바로 **로드**하지 말고 **데이터 변환**을 선택해 Power Query 편집기를 엽니다. 버전에 따라 편집 버튼의 이름이 다를 수 있습니다.

한 줄 전체가 A열에 들어갔다면 숫자 문제가 아니라 구분자 문제부터 해결해야 합니다. 반대로 열은 잘 나뉘는데 글자가 깨졌다면 인코딩을 먼저 확인합니다. Windows 전체의 지역 설정을 바꾸기보다 이 파일의 가져오기 미리 보기에서 맞추는 편이 영향 범위가 작습니다.

### 자동 형식 변환과 텍스트 열

Power Query도 CSV 열의 자료형을 자동으로 추정할 수 있습니다. 그래서 편집기를 열었다고 번호가 자동으로 보호되는 것은 아닙니다.

1. 오른쪽 **쿼리 설정 → 적용된 단계**에서 `변경된 유형` 또는 `Changed Type` 같은 자동 형식 변환 단계를 확인합니다.
2. 새로 가져오는 이번 예제에 자동 변환 단계가 있다면, **그 단계를 제거해 숫자 변환 전 데이터로 돌아갑니다.** 열 머리글이 설정된 상태에서 `00123`과 긴 번호가 원문대로 보이는지 확인합니다. 기존 업무 쿼리를 편집하는 경우에는 뒤의 단계가 의존할 수 있으므로 같은 방식으로 무작정 삭제하지 마세요.
3. `item_code` 열 머리글 왼쪽의 자료형 아이콘을 선택해 **텍스트**로 지정합니다. `record_id`도 텍스트로 지정합니다. `Ctrl`을 누르고 두 열 머리글을 선택하면 함께 바꿀 수 있습니다.
4. `quantity`는 **정수**로 지정합니다. 식별번호 열에 정수나 소수 형식을 다시 적용하지 않았는지 확인합니다.
5. **홈 → 닫기 및 로드**를 선택해 워크시트로 가져옵니다.

형식을 바꿀 때 **현재 항목 바꾸기 / Replace Current**와 새 단계 추가 중 무엇을 할지 묻는다면, 원래의 잘못된 변환을 바꾸려는 것인지 확인하세요. **숫자로 바뀐 결과 뒤에 텍스트 변환만 덧붙이면 사라진 0을 되살릴 수 없습니다.** 위 순서는 새 CSV에서 자동 변환 전 상태로 돌아간 뒤 필요한 형식을 정하는 방법입니다.

편집기의 자료형 아이콘만 보고 끝내지 말고, 번호의 실제 문자도 원본과 비교하세요. 이미 원본 CSV에 `123`만 남아 있다면 이 단계에서도 `00123`으로 복구되지는 않습니다.

공식 경로는 [앞자리 0과 큰 숫자 유지](https://support.microsoft.com/en-us/office/keeping-leading-zeros-and-large-numbers-1bf7b935-36e1-4985-842f-5dfa51f85fe7)와 [Power Query의 자료형](https://learn.microsoft.com/en-us/power-query/data-types)에서 확인할 수 있습니다.

## 가져온 값과 자료형 확인

위 연습 파일을 Power Query에서 식별자 두 열은 텍스트, 수량은 정수로 지정해 실제 Excel 워크시트에 가져왔습니다. 다음 화면은 그 결과입니다. **A2의 `00123`과 B2의 전체 번호가 유지**됐고, 수량은 계산 가능한 숫자로 들어왔습니다.

같은 위치로 가져왔다면 데이터는 A1:C3에 들어갑니다. 비어 있는 셀에서 다음 수식을 각각 실행해 보세요. 다른 위치에 로드했다면 셀 주소를 그에 맞게 바꾸면 됩니다.

| 확인할 내용 | 수식 | 이 예제의 확인 값 |
| --- | --- | --- |
| 상품 코드가 텍스트인지 | `=ISTEXT(A2)` | `TRUE` |
| 식별번호의 길이 | `=LEN(B2)` | `18` |
| 수량이 숫자인지 | `=ISNUMBER(C2)` | `TRUE` |

이 세 결과는 실제 Excel에서도 확인했습니다. 다만 `LEN`이 같다고 번호 자체가 맞다는 뜻은 아닙니다. **B2를 선택한 뒤 수식 입력줄에서 원본의 `123456789012345678`과 끝자리까지 대조**해야 합니다. 두 번째 행의 `00007`과 `987654321098765432`도 함께 확인하세요.

실제 업무 파일에서는 첫 행 하나만 확인하지 말고 앞자리 0이 있는 값, 가장 긴 번호, 빈칸이나 특이한 문자가 있는 값도 확인합니다. 행 수와 열 이름이 맞고, 식별번호는 원본과 같으며, 계산할 수량이 숫자로 들어왔다면 가져오기를 마친 것으로 볼 수 있습니다.

## 이미 바뀐 번호의 복구 범위

### 텍스트 변환의 순서

같은 연습 파일로 변환 순서도 비교해봤습니다. 처음부터 `item_code`를 텍스트로 지정했을 때는 `00123`이 남았지만, Power Query에서 숫자로 바꾼 다음 다시 텍스트로 바꿨을 때는 `123`이 남았습니다. **최종 자료형이 텍스트여도 원래 문자가 보존됐다는 증거는 아닙니다.**

긴 번호는 Excel 워크시트에서 별도로 확인했습니다. 텍스트 `123456789012345678`을 `VALUE`로 숫자로 바꾸자 실제 결과가 `123456789012345000`이 됐습니다. 이후 셀 서식을 텍스트로 바꿔도 원래 끝자리로 돌아오지 않았습니다.

여기서 Excel 워크시트의 숫자와 Power Query의 모든 숫자 처리를 같은 것으로 보면 안 됩니다. 이번 Power Query 내부의 숫자 후 텍스트 변환에서는 긴 번호가 유지된 경우도 있었습니다. **이 글의 권장 방식은 특정 숫자 형식의 허용 범위를 기대하기보다, 계산하지 않을 식별자를 처음부터 텍스트로 다루는 것**입니다.

### 원본이 남아 있는 경우와 없는 경우

원본 CSV의 문자가 온전하다면 잘못 가져온 결과를 수정하는 대신, 원본에서 텍스트로 다시 가져오는 것이 낫습니다. 반대로 변경된 번호를 CSV 원본에 덮어쓴 상태라면 다운로드했던 서비스의 재내보내기, 별도 백업, 보관된 이전 파일을 찾아야 합니다.

`00000` 같은 사용자 지정 서식으로 `123`을 `00123`처럼 보이게 할 수는 있습니다. 하지만 그것은 **정해진 길이에 맞춰 표시하는 규칙**이지, 원래 앞에 0이 몇 개 있었는지 알아내는 복구가 아닙니다. 길이가 서로 다른 코드나 끝자리가 손실된 긴 번호에는 같은 해결책을 적용할 수 없습니다.

원본에서 번호를 확인할 수 없다면 임의로 0을 붙이거나 AI에게 원래 번호를 추측하게 하지 않는 편이 맞습니다. 보기 좋은 번호가 아니라 원래 기록과 일치하는 번호가 필요하기 때문입니다.

## 저장과 다음번 가져오기

검수가 끝난 작업본은 원본 CSV와 다른 이름의 **Excel 통합 문서**로 저장하세요. 파일 형식은 `.xlsx`입니다. CSV로 다시 저장하면 셀 서식이나 여러 시트 같은 통합 문서 기능을 유지할 수 없고, 나중에 다시 여는 프로그램에서 자료형을 또 해석하게 됩니다.

외부 시스템에 CSV를 제출해야 한다면 그 시스템이 요구하는 형식으로 별도 내보내기를 하고, 텍스트 편집기로 식별번호가 그대로인지 확인합니다. 작은따옴표나 `="00123"` 같은 수식 형태를 임의로 넣는 것은 원래의 식별값 자체를 바꿀 수 있으므로 범용 해결책으로 쓰지 않는 편이 좋습니다.

Microsoft 365용 Excel과 Excel 2024에는 **파일 → 옵션 → 데이터 → 자동 데이터 변환**에서 앞자리 0이나 긴 숫자의 자동 변환을 조절하는 기능도 있습니다. 다만 Microsoft는 **이 설정이 Power Query 가져오기에 직접 적용되지 않는다**고 안내합니다. 해당 옵션을 바꿨더라도 위의 쿼리 자료형 확인은 별도로 필요합니다.

자주 받는 같은 구조의 파일이라면 Power Query의 가져오기 규칙을 유지하고 새로 고침할 수 있습니다. 이 경우에도 원본의 열 이름이나 경로가 바뀌지 않았는지, 새로 들어온 긴 번호가 텍스트인지 다시 확인하세요. CSV 파일을 열 수 있다는 것보다 **원래 번호를 바꾸지 않고 다음 작업으로 넘기는 것**이 완료 기준입니다.
