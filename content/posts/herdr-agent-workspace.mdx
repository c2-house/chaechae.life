### 목차

## 여러 터미널을 오가는 작업

AI에게 코드를 맡기고, 다른 터미널에서는 개발 서버를 띄우고, 또 다른 창에서는 테스트 결과를 확인하다 보면 어느 창이 어떤 프로젝트인지 헷갈리기 쉽습니다. Herdr는 이런 **터미널과 AI 코딩 에이전트를 프로젝트별로 모아 보는 데스크톱 앱**입니다. 새로운 AI 모델이 아니라, 이미 쓰는 프로그램의 작업 공간에 가깝습니다.

화면을 나누는 것만으로 끝나지는 않습니다. 프로그램을 실행하는 부분인 **herdr-core**가 앱 창과 분리되어 있어서, 창을 닫았다가 다시 열어도 실행 중인 작업에 돌아올 수 있습니다. 다만 컴퓨터 재부팅 뒤까지 같은 프로세스가 살아 있다는 뜻은 아닙니다.

이번에는 Windows 11에서 실제로 공간과 분할 터미널을 만들고, 로컬 웹 서버를 실행한 뒤 창을 닫고 다시 열어 응답이 유지되는지 확인했습니다. 아래는 이 작업을 따라가는 입문 가이드입니다. Claude Code나 Codex의 실제 AI 추론은 실행하지 않았으므로, 모델의 답변 품질이나 여러 에이전트의 협업 성능을 평가한 글은 아닙니다.

## Herdr 앱과 core의 역할

현재 [공식 다운로드 페이지](https://herdr.dev/download/)에서 배포하는 제품은 네이티브 데스크톱 앱입니다. 사이트에 별도로 연결된 **Herdr TUI**는 터미널 안에서 쓰는 인터페이스이므로, 그쪽의 예전 설치 명령과 이 글의 앱 설치법을 섞지 않는 편이 좋습니다.

두 프로그램의 역할은 이렇게 나뉩니다.

| 구성 | 하는 일 | 직접 쓰는 명령 |
| --- | --- | --- |
| Herdr 앱 | 공간·탭·분할 화면을 표시하고 정리 | `herdr-app` |
| herdr-core | 터미널과 프로그램을 실행하고 유지 | `hc` |

앱에서는 **Space → Tab → Pane** 순서로 생각하면 편합니다. Space는 프로젝트를 모으는 공간, Tab은 그 안의 작업 묶음, Pane은 화면에 보이는 터미널 한 칸입니다. 예를 들어 웹사이트 공간 안에 ‘미리보기’ 탭을 만들고, 왼쪽 칸에는 서버를, 오른쪽 칸에는 확인 명령을 두는 방식입니다.

Herdr는 무료 오픈 소스이며 Apache 2.0 라이선스로 공개되어 있습니다. 그렇다고 안에서 실행하는 AI까지 무료가 되는 것은 아닙니다. **Claude Code·Codex 등의 설치, 로그인, 구독 또는 API 비용은 각 제품의 조건을 따릅니다.** Herdr 설치만으로 해당 에이전트나 모델 사용권을 받는 구조가 아닙니다.

## Windows 설치와 첫 화면

### 지원 환경과 설치 경로

2026년 10월 31일 공식 안내 기준으로 Windows x86_64, Linux x86_64·arm64, Apple silicon Mac용 앱을 제공합니다. Intel Mac용 core가 있다는 사실을 Intel Mac용 앱 배포와 혼동하면 안 됩니다. 앱의 Intel Mac 사용은 소스 빌드 안내를 따로 확인해야 합니다.

Windows에서는 시작 메뉴에서 PowerShell을 열고, [공식 다운로드 페이지](https://herdr.dev/download/)의 **Windows** 탭에서 설치 명령을 확인합니다. PowerShell 안에서는 다음과 같이 실행할 수 있습니다.

```powershell
irm https://releases.herdr.dev/app/install.ps1 | iex
```

이 명령은 인터넷에서 받은 설치 스크립트를 곧바로 실행합니다. 출처를 확인하지 않은 채 다른 사이트의 비슷한 명령을 복사하지 마세요. 회사 PC라면 먼저 소프트웨어 설치 정책을 확인하는 편이 안전합니다.

공식 설치 스크립트는 사용자별 앱 폴더에 Herdr를 설치하고 시작 메뉴와 사용자 PATH에 등록하며, 필요한 경우 herdr-core도 설치합니다. 설치가 끝나면 시작 메뉴에서 Herdr를 열고, **새 PowerShell 창**에서 다음 명령으로 확인합니다.

```powershell
herdr-app --version
hc --version
```

명령을 찾을 수 없다면 먼저 설치 전에 열어 둔 터미널을 닫고 새로 여세요. 그래도 안 되면 설치 출력과 공식 다운로드 안내를 확인해야 합니다. 에이전트가 보이지 않는 문제를 해결하려고 기존 인증 파일부터 옮길 필요는 없습니다.

이 글의 실행에서는 시스템 PATH를 바꾸는 설치 스크립트 대신 공식 배포 파일을 별도 시험 폴더에 풀어 사용했습니다. 첫 실행은 앱 0.1.9·core 0.1.14였으며, 창 종료와 재실행 과정에서 앱의 자동 업데이트가 적용되어 이후 화면은 **앱 0.1.10·core 0.1.15**입니다. 일반 설치 절차와 실제 시험 방식은 이 차이가 있습니다.

### 새 공간과 프로그램 메뉴

첫 안내 화면을 닫으면 왼쪽에 Spaces, 위쪽에 탭과 `+`가 보입니다. 탭 막대의 `+` 메뉴에는 일반 **Terminal**, 설치된 에이전트, **New space** 등이 있습니다. 처음에는 AI 로그인을 추가하지 않고 Terminal로 시작해도 됩니다.

<Image src="/herdr-agent-workspace/01-new-menu.png" alt="Herdr의 Terminal, 에이전트 목록, New space와 worktree 항목이 표시된 새 작업 메뉴" caption="일반 터미널부터 시작할 수 있습니다. 이 시험 환경에서는 Claude Code와 Codex가 not installed로 표시됐습니다." />

1. `+` 메뉴에서 **New space**를 선택해 실습용 공간을 만듭니다. Windows의 기본 셸이 PowerShell인지 확인합니다.
2. 새 터미널에서 아래 폴더 준비 명령을 실행합니다. 기존 프로젝트 대신 새 실습 폴더를 사용합니다.
3. 탭 이름은 **F2**로 `Local preview`처럼 알아보기 쉽게 바꿉니다.

```powershell
New-Item -ItemType Directory -Force "$HOME\herdr-practice"
Set-Location "$HOME\herdr-practice"
python --version
```

`python --version`에서 버전 번호가 나오면 다음 단계로 진행합니다. 명령이 없거나 Store 안내만 열린다면 Python 실행 환경을 먼저 준비해야 합니다. [Python 공식 Windows 다운로드](https://www.python.org/downloads/windows/)를 참고하고, 설치 후에는 Herdr도 다시 열어 새 실행 경로를 읽게 합니다. Herdr가 Python까지 설치해 주는 것은 아닙니다.

## 분할 화면에서 웹 미리보기

### 왼쪽 터미널의 서버

실습의 목표는 **한쪽에서 서버를 실행한 채 다른 쪽에서 결과를 확인하는 것**입니다. Python 문법을 배우기 위한 예제가 아니라, 실제 개발 서버나 테스트 작업을 배치하기 전에 Herdr의 동작을 익히는 작은 작업입니다.

실습 폴더에 있는 PowerShell에서 다음 명령을 실행합니다. 같은 이름의 파일이 있으면 덮어쓰므로, 앞서 만든 비어 있는 실습 폴더에서 진행하세요.

```powershell
'<!doctype html><html lang="en"><meta charset="utf-8"><title>Herdr practice</title><h1>My first Herdr workspace</h1><p>A local page for testing terminal persistence.</p></html>' | Set-Content -Encoding utf8 .\index.html
python -m http.server 8765 --bind 127.0.0.1
```

`Serving HTTP on 127.0.0.1 port 8765`가 보이면 서버가 실행 중입니다. 프롬프트가 돌아오지 않는 것이 정상이며, 이 터미널은 그대로 둡니다. `127.0.0.1`에만 연결하도록 했으므로 같은 PC에서 확인하는 실습입니다. 외부 공개 서버로 쓰는 방법은 아닙니다.

### 오른쪽 터미널의 응답 확인

서버가 있는 칸에서 **Ctrl+Shift+O**를 누르면 오른쪽으로 터미널을 나눌 수 있습니다. 단축키가 헷갈리면 **Ctrl+Shift+P**로 명령 팔레트를 열어 **Split right**를 찾습니다. 아래쪽으로 나누는 항목은 **Split down**입니다.

<Image src="/herdr-agent-workspace/02-palette.png" alt="Herdr 명령 팔레트의 New tab, Rename tab, Split right와 Split down 항목" caption="명령 팔레트에서 화면 분할과 탭 이름 변경을 찾을 수 있습니다. 단축키도 항목 오른쪽에 표시됩니다." />

새로 생긴 **오른쪽** PowerShell에서 실행합니다. 작업 폴더를 명시해 두면 다른 위치에서 열린 경우에도 혼동을 줄일 수 있습니다.

```powershell
Set-Location "$HOME\herdr-practice"
(Invoke-WebRequest http://127.0.0.1:8765/ -UseBasicParsing).StatusCode
Get-Content .\index.html
```

응답 코드 **200**과 작성한 HTML이 나오는지 확인합니다. 브라우저 주소창에 `http://127.0.0.1:8765/`를 입력하면 **My first Herdr workspace**라는 제목도 볼 수 있습니다. 왼쪽 서버 로그에는 페이지 요청이 남습니다.

<Image src="/herdr-agent-workspace/00.png" alt="Herdr의 두 분할 터미널에서 왼쪽 HTTP 서버와 오른쪽 200 응답 및 HTML 내용을 확인한 화면" caption="실제로 실행한 로컬 서버와 응답입니다. 창을 닫았다가 다시 연 뒤에도 같은 작업에 돌아왔습니다." />

여기까지가 첫 작업의 완료 기준입니다. 단순히 칸 두 개가 생겼는지가 아니라, **왼쪽 프로그램이 계속 실행되는 동안 오른쪽에서 정상 응답을 받는지** 확인해야 합니다.

연결 오류가 나면 왼쪽 서버가 여전히 실행 중인지, 양쪽 포트가 모두 `8765`인지 확인하세요. 주소가 이미 사용 중이라는 오류가 나오면 기존 프로세스를 무작정 종료하지 말고, 서버 명령과 요청 주소의 포트를 함께 다른 값으로 바꿉니다. 페이지 대신 파일 목록이 보이면 서버를 시작한 폴더에 `index.html`이 있는지 확인합니다.

## 창을 닫은 뒤의 작업 유지

서버를 켜 둔 상태에서 **앱 창 오른쪽 위의 X**로 창만 닫고, 브라우저에서 페이지를 새로고침해 보세요. 이어 Herdr를 다시 열면 기존 공간과 터미널로 돌아올 수 있습니다. 위쪽 탭의 X나 개별 Pane의 닫기 버튼과는 다른 동작입니다.

이번 실행에서는 창을 닫기 전, 닫은 뒤, 다시 연 뒤 모두 같은 HTML을 받았습니다. core에서 확인한 터미널 주소 `t1`과 셸 프로세스도 유지됐습니다. 재실행 과정의 자동 업데이트 후에도 HTTP 응답이 이어졌습니다.

다만 **창을 닫는 것과 작업을 끝내는 것은 다릅니다.**

| 동작 | 작업에 미치는 영향 |
| --- | --- |
| 앱 창 닫기 | core의 실행 중 터미널은 유지 |
| 터미널 Pane 또는 Tab 닫기 | 그 안의 터미널 종료 |
| PC 재부팅·로그아웃·core 장애 | 기존 프로그램이 계속 실행되는 것으로 볼 수 없음 |

공식 가이드에 따르면 장애나 재부팅으로 잃은 유지 대상 터미널은 마지막 폴더에서 새 셸로 복원될 수 있지만, **원래 실행하던 서버나 AI 명령을 자동으로 다시 실행하는 것은 아닙니다.** 탭이 다시 보인다고 작업까지 복구됐다고 판단하면 안 됩니다.

실습을 마칠 때는 왼쪽 서버 칸에서 **Ctrl+C**를 눌러 중지합니다. 프롬프트가 돌아오고 브라우저 새로고침이 더는 성공하지 않는지 확인하세요. 창만 닫아 두면 서버는 계속 남습니다.

## Claude Code와 Codex를 함께 쓰는 방식

Herdr에서 에이전트를 시작하려면 **그 에이전트가 먼저 해당 환경에 설치되어 있어야** 합니다. `+` 메뉴의 `not installed` 표시는 이 조건을 확인할 출발점입니다. 이미 설치했다면 일반 터미널에서 실행되는지와 Herdr를 재시작했는지부터 점검합니다. 설치와 로그인은 각각 [Claude Code 공식 안내](https://code.claude.com/docs/en/overview), [Codex CLI 공식 안내](https://developers.openai.com/codex/cli)를 따릅니다.

준비가 끝나면 작업할 프로젝트 폴더에서 에이전트를 열고, 다른 Pane에는 개발 서버나 테스트를 둡니다. 처음부터 여러 AI를 동시에 돌리기보다는 **에이전트 하나와 확인용 터미널 하나**로 시작하는 편이 역할을 구분하기 쉽습니다.

다음은 AI에게 맡길 요청 예시입니다. 이번 로컬 서버 시험에서 실제로 실행한 AI 요청은 아닙니다.

```text
현재 프로젝트의 README와 실행 스크립트를 읽고,
로컬 실행 방법과 테스트 명령을 먼저 정리해 줘.
아직 파일을 수정하거나 패키지를 설치하지 말고,
필요한 작업과 확인 기준을 알려 줘.
```

Herdr 자체의 화면을 바꾸고 싶다면 공식 가이드가 안내하는 앱 홈의 `AGENTS.md`를 에이전트에게 읽게 할 수 있습니다. 기본 경로는 Windows에서도 사용자 홈 아래의 `.config/herdr-app/AGENTS.md`입니다. 이 파일에는 설치된 앱 버전에 맞는 화면·명령 설명이 들어 있습니다.

예를 들어 탭에 타이머를 추가하거나 에이전트 상태를 모아 보는 화면을 요청하는 방식입니다. 다만 이런 확장은 단순한 테마 변경과 다를 수 있으므로, **무슨 파일을 바꾸고 어떤 프로그램이나 네트워크를 사용할지 먼저 설명받는 것**이 좋습니다.

두 에이전트가 같은 파일을 동시에 고치면 Herdr가 알아서 충돌을 해결해 주지는 않습니다. 병렬 수정이 필요하다면 별도 브랜치와 Git worktree로 작업 디렉터리를 나누는 방법을 검토하세요. `+` 메뉴에도 worktree 항목이 있지만, 이것을 파일 접근을 차단하는 보안 격리로 생각하면 안 됩니다.

## 도입 전에 볼 장점과 부담

### 작업 정리와 기존 터미널의 차이

직접 확인한 장점은 **서버와 확인 명령을 한 탭에서 함께 보고, 창을 다시 열어도 작업을 이어갈 수 있다는 점**입니다. 여러 프로젝트나 에이전트를 오갈 때는 공간별 구분과 작업 상태 표시가 일반 터미널 창 여러 개보다 유용할 수 있습니다.

반면 AI 하나만 쓰고 터미널도 한두 개면 기존 Windows Terminal이나 IDE 터미널로 충분할 수 있습니다. 화면 분할 자체만 필요하다면 새로운 앱과 core의 동작, 업데이트, 종료 방식을 익힐 부담까지 생깁니다. 이번처럼 재실행 사이에 버전이 바뀔 수도 있으므로, 메뉴가 설명과 다르면 먼저 현재 버전을 확인하는 편이 좋습니다.

또한 ‘창이 없어져도 살아 있는 작업’은 장점인 동시에 정리할 대상입니다. 서버뿐 아니라 실행 중인 AI도 별도로 종료해야 하며, 창을 닫았다는 이유로 모델 사용이나 비용이 끝났다고 생각하면 안 됩니다.

### 사용 정보와 확장 코드의 권한

[공식 보안 문서](https://github.com/herdrdev/herdr-app/blob/main/docs/security.md)에 따르면 배포판의 사용 정보 수집은 기본으로 켜져 있습니다. **Settings → Privacy → Share anonymous usage data**에서 상태를 확인하고 끌 수 있으며, **What we send → Show**에서 보고 내용을 확인할 수 있습니다.

<Image src="/herdr-agent-workspace/03-privacy.png" alt="Herdr Settings의 Privacy에서 Share anonymous usage data와 What we send 항목을 확인한 화면" caption="이번 시험 환경은 DO_NOT_TRACK 환경 변수로 수집이 꺼진 상태입니다. 일반 설치의 기본값이 꺼져 있다는 뜻은 아닙니다." />

공식 설명상 보고 대상은 버전·OS·알려진 에이전트 이름과 사용 횟수 등이며, 터미널 내용·프롬프트·파일 내용·폴더 경로는 포함하지 않습니다. 다만 이 설정을 꺼도 업데이트 확인이나 mod의 네트워크 요청, 에이전트 자체의 모델 서버 전송까지 차단되지는 않습니다.

**Mod는 신뢰할 수 있는 코드만 추가해야 합니다.** Herdr의 mod는 프로그램 실행, 파일 읽기, 네트워크 접근을 할 수 있고 매번 별도 권한 창이 뜨는 구조가 아닙니다. Layout도 mod를 불러올 수 있습니다. 앱 설정 폴더 역시 암호화 저장소가 아니므로 비밀값을 담아 두는 용도로 쓰지 않는 편이 좋습니다.

저라면 기존 터미널이 부족한 이유가 ‘프로젝트와 에이전트를 오가며 작업 상태를 놓치는 것’일 때 Herdr를 검토하겠습니다. 첫날에는 확장을 잔뜩 추가하기보다, 이 글처럼 **서버 하나와 확인용 터미널 하나를 배치하고 종료까지 확인하는 것**부터 시작하는 편이 낫겠습니다.
