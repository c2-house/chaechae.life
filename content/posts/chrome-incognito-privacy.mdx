### 목차

## 들어가며

크롬에서 시크릿 창을 닫았는데 다운로드한 파일이 그대로 있거나, 시크릿 탭을 새로 열었는데 방금 로그인한 계정이 다시 보이면 의아할 수 있습니다. 이름은 시크릿인데 무엇을 숨겨 주는 걸까요?

**시크릿 모드는 이 기기의 Chrome에 남는 탐색 정보를 줄이는 기능이지, 인터넷에서 내 활동을 없애는 기능은 아닙니다.** 같은 시크릿 세션 안에서는 쿠키와 사이트 데이터를 잠시 사용하고, 모든 시크릿 창을 닫아야 세션이 끝납니다. 직접 저장한 파일과 북마크는 그 뒤에도 남습니다.

2026년 10월 28일 Google 공식 도움말을 확인하고, Windows의 Google Chrome 155.0.8059.79에서 가상 데이터로 쿠키와 사이트 저장소의 종료 전후 상태를 비교해봤습니다. 먼저 기록이 남는 위치를 나누면, 시크릿 모드가 필요한 상황과 다른 조치가 필요한 상황을 구분하기 쉽습니다.

## 기록이 남는 위치

우리가 흔히 말하는 ‘인터넷 기록’은 한곳에 저장되는 자료가 아닙니다. **Chrome의 방문 기록, 웹사이트에 보낸 정보, 네트워크에서 관찰할 수 있는 활동은 서로 다릅니다.**

[Google의 시크릿 모드 안내](https://support.google.com/chrome/answer/95464?hl=ko)를 기준으로 정리하면 다음과 같습니다.

| 정보 | 시크릿 모드의 처리 범위 |
| --- | --- |
| 시크릿 세션에서 방문한 사이트 기록 | 세션이 끝난 뒤 Chrome이 보관하지 않음 |
| 쿠키·사이트 데이터 | 세션 중 일시적으로 사용하고 종료 시 삭제 |
| 다운로드한 파일 | 직접 삭제할 때까지 기기에 남음 |
| 추가한 북마크·읽기 목록 항목 | 일반 탐색에서도 사용 가능 |
| 사이트에 직접 보낸 검색·주문·게시물 등 | 시크릿 창을 닫는 것만으로 사이트 쪽 데이터가 삭제되지 않음 |
| 학교·회사·인터넷 제공업체가 관찰할 수 있는 활동 | 시크릿 모드로 관찰을 차단하는 것은 아님 |

아래 실제 시작 화면에도 왼쪽에는 Chrome이 저장하지 않는 항목, 오른쪽에는 활동을 확인할 수도 있는 주체가 따로 표시됩니다. 이 두 목록을 함께 읽는 것이 중요합니다.

예를 들어 시크릿 창에서 쇼핑몰에 로그인해 주문했다면, 창을 닫는다고 주문이 취소되거나 쇼핑몰의 구매 내역이 없어지는 것은 아닙니다. Chrome이 보관하는 쿠키와 쇼핑몰이 보관하는 주문 정보는 다른 데이터이기 때문입니다.

또한 시크릿 창을 새로 여는 것은 **일반 창에서 이미 쌓인 방문 기록을 지우는 작업도 아닙니다.** 이전 일반 창의 기록을 정리하려는 목적이라면 별도의 인터넷 사용 기록 관리가 필요합니다.

## 시크릿 탭과 세션의 차이

### 세션 중에 유지되는 정보

시크릿 모드라고 해서 쿠키를 전혀 만들지 않는 것은 아닙니다. 쿠키는 사이트가 로그인 상태 등을 이어 가는 데 사용하는 작은 데이터입니다. 시크릿 세션에서도 웹사이트가 동작할 수 있도록 이런 정보를 일시적으로 보관합니다.

따라서 시크릿 창에서 로그인한 뒤 새 시크릿 탭을 열었을 때 같은 계정이 보이는 것은, 그 자체로 시크릿 모드가 고장 났다는 뜻이 아닙니다. **탭을 하나 더 여는 것과 새 시크릿 세션을 시작하는 것은 다릅니다.** Google은 시크릿 창을 추가로 열어도 기존 시크릿 세션이 계속되며, 모든 시크릿 창을 닫아야 종료된다고 설명합니다.

처음 시크릿 세션을 시작할 때 일반 창의 Google 계정이나 다른 웹사이트에 자동으로 로그인되는 것은 아닙니다. 다만 시크릿 창 안에서 직접 로그인하면 그 사이트는 로그인한 계정을 알 수 있습니다. ‘일반 창의 로그인 상태를 그대로 가져오지 않는다’와 ‘로그인해도 사이트가 나를 모른다’는 전혀 다른 이야기입니다.

### 탭 유지와 세션 종료 비교

이 차이를 확인하려고 개인 계정 대신 컴퓨터 안에서만 접속하는 시험 웹페이지를 만들었습니다. 별도 Chrome 시험 프로필의 시크릿 세션에서 가상 쿠키와 `localStorage` 값을 넣고, 같은 세션의 두 번째 탭과 종료 후 상태를 자동화로 확인했습니다. `localStorage`는 웹사이트가 브라우저에 값을 보관하는 저장소입니다.

| 확인 시점 | 가상 쿠키 | localStorage 값 |
| --- | --- | --- |
| 시험 페이지에서 값을 저장한 직후 | 있음 | 있음 |
| 같은 세션의 두 번째 탭 | 있음 | 있음 |
| 첫 번째 탭만 닫고 두 번째 탭을 유지한 상태 | 있음 | 있음 |
| 시험 브라우저를 완전히 종료한 뒤 새 시크릿 세션으로 접속 | 없음 | 없음 |

반면 시험 서버가 따로 보관한 요청 경로 목록에는 이전 접속 경로가 남아 있었습니다. 브라우저의 임시 저장소가 비워지는 것과 서버가 받은 요청의 기록은 별개라는 것을 보여줍니다.

이 비교는 가상 데이터의 브라우저 저장소와 로컬 시험 서버만 확인한 결과입니다. 실제 회사의 감시 범위나 디스크에서 흔적을 복구할 수 있는지까지 시험한 것은 아닙니다. 다운로드 파일·북마크가 남는다는 설명은 앞서 연결한 Google 공식 도움말에 근거합니다.

## 사이트와 회사의 기록 범위

시크릿 창에서 웹사이트에 접속해도 그 사이트와 통신하는 과정은 필요합니다. Google은 로그인하지 않은 상태에서도 사이트가 사용자 정보를 수집할 수 있고, 시크릿 모드가 방문 사이트의 데이터 수집 방식을 바꾸지는 않는다고 안내합니다.

회사나 학교에 대해서도 “시크릿이니 아무것도 안 보인다”라고 생각하면 안 됩니다. 다만 반대로 **회사라면 모든 페이지 내용과 입력 문장을 무조건 볼 수 있다고 단정하는 것도 정확하지 않습니다.** 어떤 정보를 확인할 수 있는지는 사용 기기, 조직의 관리 방식과 네트워크 환경에 따라 달라집니다. 시크릿 모드의 안내는 활동을 파악할 수 있는 가능성을 말하는 것이지, 특정 회사가 실제로 수집하는 항목의 목록은 아닙니다.

[HTTPS](https://developer.mozilla.org/en-US/docs/Glossary/HTTPS)는 브라우저와 서버 사이의 통신을 TLS로 암호화하는 기술입니다. 이것과 시크릿 모드는 역할이 다릅니다. HTTPS를 쓴다고 기기의 방문 기록이 자동으로 없어지는 것도 아니고, 시크릿 모드를 켰다고 조직의 관리 정책이 해제되는 것도 아닙니다.

업무 기기나 업무 네트워크를 쓴다면 조직의 개인정보·기기 관리 안내에서 수집 범위를 확인하는 편이 맞습니다. 시크릿 모드를 근거로 업무 자료를 외부 사이트에 올리거나 조직의 보안 제한을 피하려고 해서는 안 됩니다.

## 목적에 맞는 모드 선택

시크릿 모드는 모든 상황에서 더 안전한 모드라기보다, **브라우저에 정보를 남기는 방식을 바꾸는 선택지**에 가깝습니다.

| 하고 싶은 일 | 먼저 고려할 방법 |
| --- | --- |
| 내 PC에서 선물 검색 기록이 일반 방문 기록에 쌓이지 않게 하기 | 시크릿 모드, 사용 후 모든 시크릿 창 닫기 |
| 내 사이트가 로그인하지 않은 방문자에게 어떻게 보이는지 확인하기 | 새 시크릿 세션에서 로그인 없이 확인 |
| 업무·개인 계정과 북마크를 계속 나누어 쓰기 | 별도 Chrome 프로필 |
| 신뢰할 수 있는 다른 사람의 PC를 잠깐 빌려 쓰기 | 게스트 모드 |
| 사이트에 이미 저장한 주문·게시물·계정 데이터를 없애기 | 해당 서비스의 삭제·개인정보 관리 기능 |

업무·개인 환경을 계속 나누려는 경우에는 [크롬 프로필 분리 방법](/blog/chrome-work-personal-profiles)이 더 적합합니다. 시크릿은 세션이 끝나면 사이트 데이터를 지우므로, 로그인과 작업 환경을 계속 유지하려는 목적과는 맞지 않을 수 있습니다.

[게스트 모드](https://support.google.com/chrome/answer/6130773?hl=ko)는 다른 Chrome 프로필의 정보를 보거나 변경할 수 없도록 하는 점에서 차이가 있습니다. 반면 내 프로필의 시크릿 모드에서는 기존 정보와 설정을 계속 확인할 수 있습니다. 다른 사람에게 잠깐 PC를 빌려줄 때는 단순히 시크릿 창 하나를 열어 주는 것보다 게스트의 용도를 먼저 살펴보세요.

어느 쪽도 신뢰할 수 없는 컴퓨터를 안전한 기기로 바꿔 주지는 않습니다. Google도 민감한 웹사이트에는 신뢰할 수 있는 기기에서만 로그인하라고 안내합니다.

## 사용 후 종료 확인

데스크톱에서는 Chrome 오른쪽 상단의 **더보기 → 새 시크릿 창**으로 시작합니다. Windows에서는 `Ctrl + Shift + N`, Mac에서는 `⌘ + Shift + N`을 사용할 수 있습니다. 창이 어둡다는 이유만으로 판단하지 말고 주소 표시줄 오른쪽의 시크릿 아이콘을 확인하세요. 일반 창도 테마에 따라 어둡게 보일 수 있습니다.

작업을 마칠 때는 다음 순서로 확인하면 됩니다.

1. 사용한 사이트에서 로그아웃이 필요한 작업을 마칩니다. 단순히 탭을 닫는 것을 사이트 데이터 삭제로 생각하지 않습니다.
2. **열려 있는 시크릿 창을 모두 닫습니다.** 마지막으로 보던 탭 하나만 닫고 다른 시크릿 창을 남겨 두지 않습니다.
3. 직접 내려받은 파일이 있으면 저장 위치를 확인합니다. 파일을 보관할지 삭제할지는 별도로 판단합니다.
4. 시크릿 세션에서 추가한 북마크나 읽기 목록 항목이 있다면, 일반 창에도 남는다는 점을 확인합니다.

다시 시크릿 창을 열었을 때 이전 로그인 상태가 보인다면 먼저 다른 시크릿 창이 남아 있었는지 확인하세요. 모두 종료한 것이 맞다면 해당 사이트의 로그인·재인증 방식도 따로 확인해야 합니다. 로그인 화면이 나왔다는 사실만으로 사이트 서버의 데이터까지 삭제됐다고 판단해서는 안 됩니다.

또 하나의 차이는 **시크릿 모드에서 서드 파티 쿠키가 기본적으로 차단된다는 점**입니다. 다른 사이트가 제공하는 로그인 기능 등이 예상대로 동작하지 않을 수 있습니다. Google 도움말은 필요한 사이트에 한해 서드 파티 쿠키를 일시적으로 허용하는 방법을 안내합니다. 일반 창과 시크릿 창의 동작이 다를 때는 이 조건도 확인하되, 모든 사이트의 보호 설정을 한꺼번에 낮추는 식으로 해결하지 않는 것이 좋습니다.

시크릿 모드를 고를 때는 흔적이 남는지만 묻기보다 **기록을 남기지 않으려는 위치**를 먼저 정하면 됩니다. 내 Chrome의 방문 기록을 줄이는 것, 웹사이트에 보낸 정보를 지우는 것, 회사의 관리 범위를 확인하는 것은 각각 다른 작업입니다.

Google 및 Google Chrome은 Google LLC의 상표입니다. 이 글은 Google과 제휴하거나 Google의 승인을 받아 작성한 글이 아닙니다.
