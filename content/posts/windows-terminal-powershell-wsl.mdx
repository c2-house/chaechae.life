### 목차

## 들어가며

개발도구 문서에는 “터미널에 붙여 넣으세요”라고 적혀 있는데, Windows에서 따라 하면 처음 보는 오류가 날 때가 있습니다. Terminal을 열었으니 맞는 것 같은데 `export`는 인식되지 않고, 다른 글에서는 PowerShell 대신 Ubuntu를 열라고 합니다. 모두 명령을 입력하는 창처럼 보여서 헷갈리기 쉽습니다.

먼저 **Windows Terminal은 명령을 입력하고 결과를 보는 앱, PowerShell은 명령을 해석하는 셸, WSL은 Windows에서 Linux 환경을 실행하는 기능**입니다. Windows Terminal에서 PowerShell 탭과 WSL의 Ubuntu 탭을 열어 두 환경을 함께 쓸 수 있습니다.

2026년 10월 15일 확인한 Microsoft 공식 문서를 바탕으로 각 도구의 역할을 살펴보고, Windows PowerShell과 Git Bash에서 환경변수를 설정해 문법을 비교했습니다.

## 창, 셸, 실행 환경의 역할

명령을 실행하는 과정을 바깥에서 안쪽으로 보면 이해하기 편합니다.

| 구분 | 하는 일 | 예 |
| --- | --- | --- |
| 터미널 | 키보드 입력을 전달하고 출력을 표시하는 창 제공 | Windows Terminal, VS Code 통합 터미널 |
| 셸 | 입력한 문장을 해석하고 명령이나 프로그램 실행 | PowerShell, 명령 프롬프트의 cmd, Bash, zsh |
| 실행 환경 | 프로그램이 사용할 운영체제와 파일·도구 제공 | Windows, WSL의 Ubuntu |
| 명령줄 도구 | 특정 작업 수행 | Git, Python, Node.js 기반 CLI |

[Microsoft의 셸 설명](https://learn.microsoft.com/en-us/powershell/scripting/what-is-a-command-shell)은 셸이 입력을 평가해 자체 명령을 실행하거나 운영체제에 실행을 요청한다고 설명합니다. 반면 터미널은 그 셸을 담는 창입니다. 글꼴과 탭을 바꾸는 것과 명령의 문법을 바꾸는 것은 다른 일인 셈입니다.

<Image src="/windows-terminal-powershell-wsl/00.png" alt="Windows Terminal 아래에서 Windows의 PowerShell 경로와 WSL Ubuntu의 Bash 경로를 구분한 개념도" caption="Windows Terminal에서 PowerShell과 WSL의 Bash가 실행되는 위치를 보여주는 개념도입니다." />

예를 들어 Windows Terminal의 PowerShell 탭에서는 PowerShell 문법을, Ubuntu 탭에서 Bash를 실행하면 Bash 문법을 씁니다.

VS Code의 통합 터미널에서도 현재 탭에서 선택한 셸에 맞춰 문법을 고르면 됩니다.

## PowerShell과 Bash의 명령 문법

설치 문서를 따라 하다가 차이를 바로 만나는 부분이 환경변수입니다. 환경변수는 실행할 프로그램에 전달하는 설정값입니다. 예제로 `DEMO_MODE`에 `local`을 넣어보겠습니다.

새 **PowerShell** 세션에서는 다음 두 줄을 실행합니다.

```powershell
$env:DEMO_MODE = 'local'
$env:DEMO_MODE
```

**Bash**에서는 같은 목적을 이렇게 표현합니다.

```bash
export DEMO_MODE=local
printf '%s\n' "$DEMO_MODE"
```

Windows 11에서 Windows PowerShell 5.1.26100.9711과 Git Bash의 Bash 5.3.9로 실행하니 둘 다 `local`을 출력했습니다.

두 예제 모두 현재 셸과 그 셸에서 시작한 자식 프로세스에만 값을 전달합니다. 다른 탭에서 같은 값이 필요하면 그 탭에서도 설정하세요.

Bash용 `export` 명령이 PowerShell에서 인식되지 않으면 Bash 탭을 열거나 `$env:` 문법으로 바꾸세요.

`git --version`처럼 외부 프로그램을 실행하는 명령은 해당 프로그램이 설치되어 있고 PATH에서 찾을 수 있다면 여러 셸에서 같은 형태로 쓸 수 있습니다. **변수·따옴표·줄바꿈·파이프가 들어가면 셸의 문법을 확인하세요.**

## Windows PowerShell과 PowerShell 7

Windows에서 PowerShell이라는 이름을 봤다고 모두 같은 버전은 아닙니다.

- **Windows PowerShell 5.1**의 실행 파일은 `powershell.exe`입니다.
- **PowerShell 7 계열**의 실행 파일은 Windows에서 `pwsh.exe`입니다.

Microsoft는 두 제품을 나란히 설치할 수 있도록 실행 파일 이름을 구분했습니다. 자세한 차이는 [Windows PowerShell과 PowerShell 비교 문서](https://learn.microsoft.com/en-us/powershell/scripting/whats-new/differences-from-windows-powershell)에서 확인할 수 있습니다.

PowerShell이라고 생각되는 세션에서는 다음 명령으로 현재 버전을 확인할 수 있습니다.

```powershell
$PSVersionTable.PSVersion
```

결과의 `Major` 값이 `5`인지 `7`인지 확인합니다. 문서가 PowerShell 7을 요구하면 PowerShell 7을 설치한 뒤 `pwsh.exe`로 실행한 탭에서 명령을 입력하세요.

## WSL과 Git Bash의 차이

[공식 WSL 소개](https://learn.microsoft.com/en-us/windows/wsl/about)에 따르면 WSL은 Windows에서 Ubuntu·Debian 같은 Linux 배포판을 실행하는 기능입니다. 그 안에서 Bash나 zsh 같은 셸과 Linux용 프로그램을 사용합니다. WSL 2는 가벼운 가상 머신 안에서 Linux 커널을 실행합니다.

Git Bash는 [Git for Windows](https://gitforwindows.org/)가 제공하는 Bash 환경으로, Windows에서 Git과 유닉스 계열 명령을 쓸 수 있게 해줍니다.

설치 문서가 Ubuntu에서 `apt`를 실행하라고 하면 WSL의 Ubuntu 탭을 여세요. Windows용 설치 방법이 있다면 그 경로로 시작할 수 있습니다.

설치된 WSL 배포판을 확인하려면 Windows의 PowerShell이나 명령 프롬프트에서 다음을 실행합니다.

```powershell
wsl --list --verbose
```

[WSL 기본 명령 문서](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)에 나온 조회 명령입니다. 실습 환경에서는 배포판 이름이 `Ubuntu`, 상태가 `Stopped`, `VERSION`이 `2`로 표시됐습니다. `VERSION`은 배포판의 WSL 실행 방식을 나타냅니다.

목록을 확인한 뒤 Ubuntu에서 명령을 실행하려면 Ubuntu 탭을 따로 열어야 합니다. 조회 명령이 인식되지 않거나 목록이 비어 있으면 WSL과 배포판 설치 상태를 확인하세요.

## 명령을 실행할 위치 선택하기

무엇이 더 좋은 터미널인지부터 고르기보다, 사용하려는 도구의 공식 설치 문서에서 지원 OS와 명령의 셸을 확인하는 편이 빠릅니다.

| 문서나 작업의 조건 | 선택할 실행 위치 |
| --- | --- |
| Windows용 설치 방법과 PowerShell 명령이 제공됨 | 요구 버전에 맞는 PowerShell |
| Ubuntu에서 `apt`로 설치하고 Linux용 도구를 실행하도록 안내 | WSL Ubuntu 등 실제 Ubuntu 환경 |
| Windows에서 Git 작업과 Bash 스크립트가 필요함 | Git Bash를 검토하되 스크립트의 도구 의존성 확인 |
| Bash 코드만 있고 지원 OS가 불분명함 | Bash라는 표시만으로 판단하지 말고 지원 환경부터 확인 |

마지막 경우가 특히 중요합니다. Bash는 Linux에서도, macOS에서도, Git Bash에서도 만날 수 있습니다. 코드블록에 `bash`라고 적혀 있다고 해서 모든 환경에서 같은 프로그램과 파일 경로가 준비되는 것은 아닙니다.

Windows와 WSL을 함께 쓴다면 **설치 위치와 프로젝트 위치도 한 쌍으로 확인**하세요. Windows에 설치한 Python과 WSL에 설치한 Python은 서로 다른 실행 파일과 패키지 환경일 수 있습니다. 같은 폴더를 보고 있어도 어떤 Python으로 실행하는지에 따라 결과가 달라질 수 있습니다.

WSL에서도 Windows의 `.exe`를 실행할 수 있고, Windows에서는 `wsl` 명령으로 Linux 프로그램을 호출할 수 있습니다. Microsoft의 [Windows·Linux 상호 운용 문서](https://learn.microsoft.com/en-us/windows/wsl/filesystems)에서 예를 볼 수 있습니다.

Windows의 `C:\work\demo`는 기본적인 WSL 드라이브 마운트 구성에서 `/mnt/c/work/demo`로 접근할 수 있습니다. Linux 도구로 계속 작업하는 프로젝트라면 Microsoft는 성능을 위해 WSL의 Linux 파일 시스템에 보관하는 방법을 권장합니다.

## AI에게 전달할 실행 환경

AI에게 명령을 요청할 때는 Windows 버전과 함께 현재 셸과 실행할 환경을 알려주세요.

```text
Windows 11에서 Windows Terminal을 사용하고 있습니다.
현재 셸은 Windows PowerShell 5.1입니다.
WSL이 아니라 Windows에 설치한 도구로 실행하려고 합니다.

이 환경을 공식 지원하는지 먼저 확인하고,
PowerShell 5.1에서 실행할 명령을 알려주세요.
다른 셸이나 PowerShell 7이 필요하면 이유부터 설명해주세요.
관리자 권한, 영구 PATH 변경, 보안 설정 변경은 자동으로 진행하지 마세요.
설치 후 어떤 명령으로 버전과 실행 위치를 확인할지도 알려주세요.
```

WSL을 쓰는 경우에는 배포판과 셸, 프로젝트 경로를 알려주면 됩니다. 문제를 질문할 때는 전체 환경변수 목록이나 비밀키를 보내지 말고, 해당 도구의 버전과 오류 문구만 필요한 범위에서 전달하세요. 경로에 개인 이름이나 회사 정보가 있다면 가리는 편이 좋습니다.
