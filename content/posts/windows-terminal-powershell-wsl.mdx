개발도구 문서에는 “터미널에 붙여 넣으세요”라고 적혀 있는데, Windows에서 따라 하면 처음 보는 오류가 날 때가 있습니다. Terminal을 열었으니 맞는 것 같은데 `export`는 인식되지 않고, 다른 글에서는 PowerShell 대신 Ubuntu를 열라고 합니다. 모두 명령을 입력하는 창처럼 보여서 헷갈리기 쉽습니다.

먼저 **Windows Terminal은 명령을 입력하고 결과를 보는 앱, PowerShell은 명령을 해석하는 셸, WSL은 Windows에서 Linux 환경을 실행하는 기능**입니다. 같은 종류의 도구 세 개 중 하나를 고르는 관계가 아닙니다. Windows Terminal 안에서 PowerShell을 쓸 수도 있고, WSL의 Ubuntu에 들어가 Bash를 쓸 수도 있습니다.

이 구분을 알고 나면 AI가 알려준 명령을 어디에 붙여 넣을지 판단하기 쉬워집니다. 2026년 10월 15일 확인한 Microsoft 공식 문서를 바탕으로 역할을 나누고, Windows PowerShell과 Git Bash에서 작은 예제를 실행해 문법 차이도 확인했습니다.

## 창, 셸, 실행 환경의 역할

명령을 실행하는 과정을 바깥에서 안쪽으로 보면 이해하기 편합니다.

| 구분 | 하는 일 | 예 |
| --- | --- | --- |
| 터미널 | 키보드 입력을 전달하고 출력을 표시하는 창 제공 | Windows Terminal, VS Code 통합 터미널 |
| 셸 | 입력한 문장을 해석하고 명령이나 프로그램 실행 | PowerShell, 명령 프롬프트의 cmd, Bash, zsh |
| 실행 환경 | 프로그램이 사용할 운영체제와 파일·도구 제공 | Windows, WSL의 Ubuntu |
| 명령줄 도구 | 특정 작업 수행 | Git, Python, Node.js 기반 CLI |

[Microsoft의 셸 설명](https://learn.microsoft.com/en-us/powershell/scripting/what-is-a-command-shell)은 셸이 입력을 평가해 자체 명령을 실행하거나 운영체제에 실행을 요청한다고 설명합니다. 반면 터미널은 그 셸을 담는 창입니다. 글꼴과 탭을 바꾸는 것과 명령의 문법을 바꾸는 것은 다른 일인 셈입니다.

<Image src="/windows-terminal-powershell-wsl/00.png" alt="Windows Terminal 아래에서 Windows의 PowerShell 경로와 WSL Ubuntu의 Bash 경로를 구분한 개념도" caption="역할을 구분하려고 직접 만든 개념도입니다. 제품 화면이나 보안 격리를 나타내는 그림은 아닙니다." />

예를 들어 Windows Terminal에서 PowerShell 탭을 열었다면, 입력한 문장은 PowerShell이 해석합니다. 같은 창에 Ubuntu 탭을 열어 Bash를 실행하면 그 탭에서는 Bash 문법을 씁니다. 창이 같다고 문법까지 같아지지는 않습니다.

VS Code 아래쪽의 통합 터미널도 같은 관점으로 보면 됩니다. VS Code라는 편집기 안에 터미널이 있고 그 안에서 선택한 셸이 실행됩니다. **“VS Code에서 실행했다”는 설명만으로 PowerShell인지 Bash인지 알 수는 없습니다.**

## PowerShell과 Bash의 명령 문법

설치 문서를 따라 하다가 차이를 바로 만나는 부분이 환경변수입니다. 환경변수는 실행할 프로그램에 전달할 설정값이라고 생각하면 됩니다. 여기서는 비밀키 대신 `DEMO_MODE`라는 연습용 변수에 `local`을 넣어보겠습니다.

새 **PowerShell** 세션에서는 다음 두 줄을 실행합니다.

```powershell
$env:DEMO_MODE = 'local'
$env:DEMO_MODE
```

**Bash**에서는 같은 목적을 이렇게 표현합니다.

```bash
export DEMO_MODE=local
printf '%s\n' "$DEMO_MODE"
```

Windows 11에서 Windows PowerShell 5.1.26100.9711과 Git Bash의 Bash 5.3.9로 각각 실행했고, 둘 다 `local`을 출력했습니다. Git Bash로 확인한 Bash 문법 비교이며, WSL Ubuntu에서 동일 작업을 실행한 결과는 아닙니다.

두 예제는 현재 셸과 그 셸에서 시작하는 자식 프로세스에 값을 전달하는 방식입니다. 시스템 전체에 영구 저장하는 설정이 아니고, 이미 열려 있는 다른 탭에 값을 넣어주는 것도 아닙니다. 연습은 새 세션에서 하고 끝나면 닫으면 됩니다.

따라서 Bash용 `export` 명령을 PowerShell에 붙여 넣고 실패했다면, 먼저 셸이 맞는지 확인해야 합니다. 오류를 없애려고 관리자 권한을 주거나 보안 설정을 끄는 문제는 아닙니다. 반대로 PowerShell의 `$env:` 문법을 Bash에 그대로 옮기는 것도 맞지 않습니다.

다만 모든 명령이 완전히 달라지는 것은 아닙니다. `git --version`처럼 외부 프로그램을 실행하는 단순한 명령은 여러 셸에서 같은 모양으로 쓸 수 있습니다. **변수·따옴표·줄바꿈·파이프가 들어가면 어떤 셸의 문법인지 더 중요해집니다.** 프로그램이 설치되어 있고 실행 경로에서 발견되는지는 별도로 확인해야 합니다.

## Windows PowerShell과 PowerShell 7

Windows에서 PowerShell이라는 이름을 봤다고 모두 같은 버전은 아닙니다.

- **Windows PowerShell 5.1**의 실행 파일은 `powershell.exe`입니다.
- **PowerShell 7 계열**의 실행 파일은 Windows에서 `pwsh.exe`입니다.

Microsoft는 두 제품을 나란히 설치할 수 있도록 실행 파일 이름을 구분했습니다. 자세한 차이는 [Windows PowerShell과 PowerShell 비교 문서](https://learn.microsoft.com/en-us/powershell/scripting/whats-new/differences-from-windows-powershell)에서 확인할 수 있습니다.

PowerShell이라고 생각되는 세션에서는 다음 명령으로 현재 버전을 확인할 수 있습니다.

```powershell
$PSVersionTable.PSVersion
```

결과의 `Major` 값이 `5`인지 `7`인지부터 봅니다. 탭 이름은 사용자가 바꿀 수 있으므로 이름만 믿기보다 실행 중인 셸에서 확인하는 편이 정확합니다. 문서가 PowerShell 7을 요구한다면 Windows Terminal을 최신으로 바꾸는 것만으로 해결되지 않습니다. **터미널 앱 업데이트와 셸 버전 변경은 별개**입니다.

## WSL과 Git Bash의 차이

WSL은 Bash의 다른 이름이 아닙니다. [공식 WSL 소개](https://learn.microsoft.com/en-us/windows/wsl/about)에 따르면 Windows에서 Ubuntu·Debian 같은 Linux 배포판을 실행할 수 있는 기능입니다. 그 배포판 안에서 Bash나 zsh 같은 셸과 Linux용 프로그램을 사용합니다. WSL 2는 가벼운 가상 머신 안에서 Linux 커널을 실행합니다.

**Git Bash는 WSL과 다른 도구입니다.** [Git for Windows](https://gitforwindows.org/)가 제공하는 Bash 환경으로, Windows에서 Git과 익숙한 유닉스 계열 명령을 쓰도록 돕습니다. Bash 문법을 사용할 수 있다는 사실이 곧 Ubuntu의 패키지·서비스·Linux 커널 환경까지 있다는 뜻은 아닙니다.

이 차이는 `apt`로 패키지를 설치하라는 안내를 만났을 때 중요합니다. Ubuntu 기준의 설치 절차라면 Ubuntu 환경이 필요합니다. PowerShell 대신 Git Bash를 열었다고 Ubuntu 설치 명령을 그대로 실행할 수 있는 것은 아닙니다. 반대로 Windows를 공식 지원하는 도구를 쓰기 위해 항상 WSL부터 설치해야 하는 것도 아닙니다.

설치된 WSL 배포판을 확인하려면 Windows의 PowerShell이나 명령 프롬프트에서 다음을 실행합니다.

```powershell
wsl --list --verbose
```

[WSL 기본 명령 문서](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)에 안내된 조회 명령입니다. 배포판 이름, 실행 중인지 중지 상태인지, WSL 1·2 중 어느 방식인지 보여줍니다. 이번 환경에서도 목록 조회를 실행했고 설치된 Ubuntu가 WSL 2의 중지 상태로 표시되는 것을 확인했습니다. Ubuntu를 시작하거나 기본 배포판을 바꾸지는 않았습니다.

여기서 `VERSION`의 `2`는 **Ubuntu 버전이 아니라 WSL 방식**입니다. 그리고 목록에 Ubuntu가 있다는 것은 설치 여부를 보여줄 뿐, 현재 입력 중인 PowerShell이 Ubuntu로 바뀌었다는 뜻이 아닙니다. 명령 자체가 인식되지 않거나 배포판이 없다면 먼저 WSL 설치 상태를 확인해야 합니다.

## 명령을 실행할 위치 선택하기

무엇이 더 좋은 터미널인지부터 고르기보다, 사용하려는 도구의 공식 설치 문서에서 지원 OS와 명령의 셸을 확인하는 편이 빠릅니다.

| 문서나 작업의 조건 | 선택할 실행 위치 |
| --- | --- |
| Windows용 설치 방법과 PowerShell 명령이 제공됨 | 요구 버전에 맞는 PowerShell |
| Ubuntu에서 `apt`로 설치하고 Linux용 도구를 실행하도록 안내 | WSL Ubuntu 등 실제 Ubuntu 환경 |
| Windows에서 Git 작업과 Bash 스크립트가 필요함 | Git Bash를 검토하되 스크립트의 도구 의존성 확인 |
| Bash 코드만 있고 지원 OS가 불분명함 | Bash라는 표시만으로 판단하지 말고 지원 환경부터 확인 |

마지막 경우가 특히 중요합니다. Bash는 Linux에서도, macOS에서도, Git Bash에서도 만날 수 있습니다. 코드블록에 `bash`라고 적혀 있다고 해서 모든 환경에서 같은 프로그램과 파일 경로가 준비되는 것은 아닙니다.

Windows와 WSL을 함께 쓴다면 **설치 위치와 프로젝트 위치도 한 쌍으로 확인**하세요. Windows에 설치한 Python과 WSL에 설치한 Python은 서로 다른 실행 파일과 패키지 환경일 수 있습니다. 같은 폴더를 보고 있어도 어떤 Python으로 실행하는지에 따라 결과가 달라질 수 있습니다.

둘이 완전히 단절된 것은 아닙니다. Microsoft의 [Windows·Linux 상호 운용 문서](https://learn.microsoft.com/en-us/windows/wsl/filesystems)는 WSL에서 Windows의 `.exe`를 실행하거나 Windows에서 `wsl`을 통해 Linux 프로그램을 호출하는 방법을 안내합니다. 그래서 “WSL 탭이니까 무조건 Linux용 실행 파일만 실행된다”는 가정도 피해야 합니다.

파일 경로도 다르게 보일 수 있습니다. 예를 들어 Windows의 `C:\work\demo`는 기본적인 WSL 드라이브 마운트 구성에서 `/mnt/c/work/demo`로 접근할 수 있습니다. Linux 도구로 계속 작업하는 프로젝트라면 Microsoft는 성능을 위해 WSL의 Linux 파일 시스템에 보관하는 방법을 권장합니다. 이는 기존 폴더를 당장 옮기라는 뜻은 아닙니다. 프로젝트의 설치·실행 환경을 정한 뒤 경로를 맞추면 됩니다.

## AI에게 전달할 실행 환경

AI에게 명령을 요청할 때도 “Windows예요”에서 한 단계 더 알려주면 좋습니다. 다음은 실제 작업 결과가 아니라 자신의 환경에 맞게 바꿔 쓰는 요청 예시입니다.

```text
Windows 11에서 Windows Terminal을 사용하고 있습니다.
현재 셸은 Windows PowerShell 5.1입니다.
WSL이 아니라 Windows에 설치한 도구로 실행하려고 합니다.

이 환경을 공식 지원하는지 먼저 확인하고,
PowerShell 5.1에서 실행할 명령을 알려주세요.
다른 셸이나 PowerShell 7이 필요하면 이유부터 설명해주세요.
관리자 권한, 영구 PATH 변경, 보안 설정 변경은 자동으로 진행하지 마세요.
설치 후 어떤 명령으로 버전과 실행 위치를 확인할지도 알려주세요.
```

WSL을 쓰는 경우에는 배포판과 셸, 프로젝트 경로를 알려주면 됩니다. 문제를 질문할 때는 전체 환경변수 목록이나 비밀키를 보내지 말고, 해당 도구의 버전과 오류 문구만 필요한 범위에서 전달하세요. 경로에 개인 이름이나 회사 정보가 있다면 가리는 편이 좋습니다.

판단 기준은 간단합니다. **창의 이름보다 그 안에서 실행 중인 셸과 프로그램의 환경을 확인하는 것**입니다. PowerShell 문법이 필요한지, Ubuntu의 Linux 환경이 필요한지 구분하면 불필요하게 터미널을 다시 설치하거나 여러 환경에 같은 도구를 중복 설치하는 일을 줄일 수 있습니다.
