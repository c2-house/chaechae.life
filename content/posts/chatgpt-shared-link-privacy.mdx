### 목차

## 들어가며

ChatGPT가 정리해준 답변을 동료에게 보내려고 공유 버튼을 눌렀는데, 앞에서 했던 개인적인 질문까지 같이 보일까 걱정될 수 있습니다. 링크 하나를 보내면 내 계정의 다른 대화도 열리는지, 나중에 이어 쓴 내용까지 보이는지도 헷갈립니다.

**개인 계정의 공유 링크는 주소를 가진 누구나 열 수 있습니다.** 상대가 전달하면 새 수신자도 같은 공유 페이지를 볼 수 있습니다. 열람 범위는 그 페이지에 포함된 내용으로 제한됩니다.

아래 절차는 [OpenAI의 공유 도움말](https://help.openai.com/en/articles/7925741-sharing-conversations-and-scheduled-tasks-in-chatgpt)에 나온 개인 계정 기준입니다. 관리형 워크스페이스와 예약 작업의 공유 권한·갱신 방식은 도움말에서 각각 확인할 수 있습니다.

## 상대에게 보이는 내용

대화 화면의 Share로 공유하면 앞서 주고받은 메시지를 포함할 수 있습니다. 개별 답변에 공유 옵션이 제공되는 경우에는 그 답변만 공유하는 방식도 있습니다. 어느 버튼에서 시작했는지와 공유 미리보기에 무엇이 나타나는지를 함께 봐야 합니다.

| 확인할 대상 | 공유 전에 볼 부분 |
| --- | --- |
| 앞에서 주고받은 질문과 답변 | 마지막 답변뿐 아니라 미리보기의 처음부터 끝까지 확인 |
| 개별 답변 | 답변 하나로 범위가 제한됐는지 확인 |
| 이미지와 업로드 파일 | 공유 화면·계정 기능·수신 권한에 따라 포함될 수 있으므로 직접 확인 |
| 이름과 개인정보 | 프로필 표시뿐 아니라 대화 본문에 직접 입력한 정보도 확인 |

공식 도움말에 따르면 공유 링크는 기본적으로 익명이지만, 일부 기존 공유 방식에서는 작성자 이름이 표시될 수 있습니다. **작성자 이름이 가려져도 질문이나 답변에 적은 회사명·이메일·고객 이름은 본문에 남습니다.**

## 공유 이후에 추가한 메시지

개인 계정의 대화 링크는 **링크를 만들거나 업데이트한 시점의 내용**을 보여줍니다. 그 뒤에 원래 대화에서 새 메시지를 주고받았다고 기존 공유 링크에 자동으로 추가되지는 않습니다.

행사 안내문을 공유한 뒤 장소를 변경했다면 다음 순서로 갱신합니다.

1. ChatGPT와 행사 안내문 초안을 작성하고 공유 링크를 만듭니다.
2. 같은 대화에서 행사 장소를 바꿔달라고 요청합니다.
3. 공유 링크를 업데이트하지 않았다면 상대에게는 변경 전 내용이 보입니다.
4. 변경한 내용까지 보내려면 원래 대화에서 **Share → Update link**로 공유 내용을 갱신합니다.

업데이트할 때도 새 미리보기를 확인해야 합니다. 처음에는 공개해도 괜찮았던 대화에 나중에 연락처나 내부 검토 의견을 추가했다면, 갱신하면서 그 내용까지 공유 대상에 들어갈 수 있기 때문입니다.

생성 중인 답변은 공유에 포함되지 않을 수 있으니, 답변이 끝나면 미리보기를 확인하세요. 상대가 공유 대화를 자기 계정에서 이어가면 원본과 별도로 비공개 사본이 생깁니다.

## 링크를 보내기 전 확인 순서

아래는 공식 공유 경로에 내용 검토와 수신 화면 확인을 더한 순서입니다. 앱 언어와 기기에 따라 버튼 이름이나 공유 창 모양이 다를 수 있으므로 영문 항목을 함께 적었습니다.

1. **공유할 대화를 엽니다.** 개인 계정에서 만든 대화인지 먼저 확인합니다. 회사 워크스페이스의 자료를 개인 계정으로 옮겨 공유 제한을 피하면 안 됩니다.
2. **Share를 선택합니다.** 답변 하나만 전달하려면 개별 답변의 공유 옵션이 제공되는지 확인합니다. 해당 옵션이 없다면 필요한 부분을 별도 문서로 정리하는 방법도 있습니다.
3. **미리보기를 처음부터 끝까지 읽습니다.** 질문, 답변에 다시 인용된 정보, 이미지와 파일을 확인합니다. 민감한 정보가 보이면 이 상태로 링크를 전달하지 않습니다.
4. **Create link 또는 Copy link를 선택합니다.** 화면에 표시되는 항목을 따릅니다. 모바일에서는 기기의 공유 시트가 열릴 수도 있습니다.
5. **복사한 주소의 수신 화면을 확인합니다.** 개인 계정 링크라면 별도의 로그아웃 창에서 열어 실제로 보이는 범위를 점검할 수 있습니다. 기대한 내용과 다르면 전달을 멈추고 공유 범위를 다시 확인합니다.
6. **확인한 링크만 전달합니다.** 새 창에서 로딩 화면이 계속 보이면 잠시 뒤 다시 열어봅니다.

미리보기에 민감한 정보가 보이면 **필요한 결과만 복사해 개인정보를 지우고 별도로 전달**하세요. ChatGPT에 앞선 정보를 무시해 달라고 요청해도 기존 메시지는 공유 범위에 남을 수 있습니다.

개인 계정의 공유 링크에는 사람별 접근 권한과 사용자 지정 만료일이 없습니다. 검색엔진 색인을 위한 페이지는 아니지만, 주소를 가진 사람은 열 수 있으므로 공개 게시판 등에 붙이기 전에 공유 범위를 확인하세요.

## 공유 중단과 남아 있는 사본

이미 보낸 링크를 더 이상 열리지 않게 하려면 대화를 통째로 지우기 전에 **공유 링크 자체를 삭제**하는 경로부터 확인하세요. 원래 대화는 보관하면서 링크 접근만 중단할 수 있습니다.

1. **Settings → Data controls**로 이동합니다.
2. **Shared links → Manage**를 엽니다.
3. 목록에서 중단하려는 링크를 확인하고 **Delete shared link**를 선택합니다.
4. 관리 목록에서 해당 링크가 제거됐는지 확인합니다.
5. 앞서 보낸 주소를 별도 창에서 새로 열어, 더 이상 공유 내용을 볼 수 없는지 확인합니다.

전체 링크를 없애려는 경우에는 **More actions → Delete all shared links**가 있지만, 일부 링크만 중단할 목적이라면 개별 삭제가 낫습니다. 관리 목록에는 대화와 예약 작업 링크가 함께 표시될 수 있으므로 대상도 구분해야 합니다.

**상대 계정으로 가져간 대화, 복사한 텍스트, 캡처는 링크를 삭제한 뒤에도 남습니다.**

| 조작 | 개인 계정의 대화 공유 링크에 미치는 영향 |
| --- | --- |
| 공유 링크 삭제 | 해당 주소를 통한 이후 접근 중단, 원래 대화는 유지 |
| 원래 대화 삭제 | 그 대화의 공유 링크도 삭제 |
| 대화 잠금 | 기존 링크의 이미 공유된 내용은 그대로 접근 가능 |
| 모델 개선 설정 끄기 | 기존 공유 링크 삭제나 접근 대상 변경이 아님 |

예약 작업이 연결된 대화는 원래 대화를 삭제한 뒤에도 작업 공유 링크가 남을 수 있습니다. **작업 링크는 관리 목록에서 따로 확인해 삭제하세요.**

민감한 자료를 잘못 공유했다면 링크를 끊고 수신자에게 저장하거나 전달한 사본의 삭제를 요청하세요. 비밀번호나 API 키가 노출됐다면 해당 서비스에서 폐기하고 교체하세요. 회사 자료는 조직의 보안 대응 절차에 따라 처리합니다.

## 공유 링크 대신 결과물만 전달할 때

공유 링크는 질문과 답변의 맥락을 함께 보여주고 싶을 때 편합니다. 같은 문제를 어떻게 풀었는지 설명하거나, 공개해도 되는 예시 대화를 전달하는 경우에 잘 맞습니다.

특정 동료에게만 보내거나 전달 후 접근 권한을 관리해야 한다면 **필요한 부분만 옮겨 문서 도구에서 수신자별 권한을 설정**하세요.

대화 자체를 삭제했는데 ChatGPT가 예전 정보를 다시 언급하는 문제는 공유 링크와 다른 범위입니다. 이 경우에는 [ChatGPT 대화 삭제와 메모리의 차이](/blog/chatgpt-delete-memory)를 확인하면 됩니다.
