자료를 읽다가 잠시 다른 탭으로 갔는데, 돌아오는 순간 페이지가 다시 로딩될 때가 있습니다. 열어 둔 탭이 사라진 것은 아닌데 화면을 다시 불러오니 작업 흐름이 끊깁니다. 이때 먼저 살펴볼 설정이 크롬의 **메모리 절약**입니다.

그렇다고 바로 메모리 절약을 전부 끌 필요는 없습니다. **자주 돌아오는 작업 사이트만 예외 목록에 추가하고, 나머지 탭에는 메모리 절약을 유지할 수 있습니다.** 다만 이 설정은 Chrome의 탭 비활성화를 조절하는 기능이지, 사이트 자체의 새로고침이나 로그인 만료까지 막는 기능은 아닙니다.

아래는 데스크톱 Chrome 기준입니다. 2026년 10월 18일 Windows 11의 Google Chrome 155.0.8059.79에서 별도 시험 프로필을 만들고, 자동화로 예외 등록과 브라우저 재실행 후 설정 유지를 확인했습니다. 실제 화면을 함께 보되, 자연 비활성화까지 걸리는 시간이나 메모리 절감량을 측정한 실험은 아닙니다. 모바일 Chrome에는 이 성능 설정이 제공되지 않습니다.

## 탭 복귀 시 새로고침과 메모리 절약

[Chrome 공식 도움말](https://support.google.com/chrome/answer/12929150?hl=ko)에 따르면 메모리 절약은 현재 사용하지 않는 탭을 비활성화해 메모리를 확보합니다. 그 탭으로 돌아가면 페이지가 자동으로 새로고침됩니다.

탭 제목은 계속 남아 있어서 페이지도 그대로 실행 중이라고 생각하기 쉽습니다. 하지만 [Chrome 개발자 문서](https://developer.chrome.com/blog/memory-and-energy-saver-mode?hl=en)는 비활성화된 탭의 제목과 아이콘이 남더라도 페이지 자체는 메모리에서 내려갈 수 있다고 설명합니다. 다시 돌아왔을 때 이전 위치나 입력 상태를 복원하는지는 해당 사이트의 구현에도 달려 있습니다.

먼저 증상을 나눠 보세요.

- **한동안 보지 않던 탭으로 돌아올 때 다시 로딩됨**: 메모리 절약 설정을 먼저 확인할 만합니다.
- **지금 보고 있는 탭이 몇 초마다 다시 로딩됨**: 백그라운드 탭 비활성화만으로 설명하기 어렵습니다. 사이트나 확장 프로그램도 확인해야 합니다.
- **페이지 대신 로그인 화면이 나옴**: 사이트의 세션 만료 여부를 따로 확인해야 합니다. 예외 등록이 로그인 유지 시간을 늘려 주지는 않습니다.

메모리 절약을 끄면 모든 새로고침이 사라진다고 단정하지 않는 이유입니다. Google은 이 기능 도입 전에도 메모리가 부족하면 탭을 메모리에서 내려놓는 동작이 있었다고 설명합니다.

## 메모리 절약 설정과 단계 선택

1. 컴퓨터의 Chrome에서 오른쪽 상단 **더보기 → 설정 → 성능**을 엽니다.
2. `메모리` 구간의 **메모리 절약**이 켜져 있는지 확인합니다.
3. 켜져 있다면 현재 선택된 단계를 확인합니다. 꺼져 있는데도 같은 문제가 난다면, 이 기능만 원인으로 보고 설정을 반복하지 마세요.

주소 표시줄에 아래 주소를 직접 입력해도 같은 설정 화면으로 이동합니다. 웹페이지 안의 검색창이 아니라 **브라우저 주소 표시줄**에 입력합니다.

```text
chrome://settings/performance
```

<Image src="/chrome-memory-saver-tabs/01-memory-settings.png" alt="Chrome 성능 설정에서 다음 사이트를 항상 활성 상태로 유지 항목과 메모리 절약 단계가 보이는 화면" caption="메모리 절약을 켠 시험 프로필입니다. 위쪽 일반 구간에 사이트 예외 목록, 아래쪽 메모리 구간에 절약 단계가 있습니다." />

현재 도움말과 확인한 화면의 단계는 다음과 같습니다.

| 단계 | 탭 비활성화 기준 | 선택할 상황 |
| --- | --- | --- |
| 보통 | 좀 더 긴 시간이 지난 뒤 비활성화 | 여러 탭을 자주 오가며 유지 시간을 더 두고 싶을 때 |
| 균형(권장) | Chrome이 정한 적절한 시점에 비활성화 | 우선 기본 수준으로 사용해 볼 때 |
| 최대 | 좀 더 짧은 시간이 지난 뒤 비활성화 | 사용하지 않는 탭의 메모리를 더 적극적으로 확보하고 싶을 때 |

공식 안내는 각 단계를 고정된 분 단위 시간으로 약속하지 않습니다. `최대`가 모든 작업에서 가장 빠른 설정이라는 뜻도 아닙니다. 돌아올 때 다시 로딩되는 탭이 늘면 오히려 불편할 수 있습니다.

특정 업무 사이트에서만 불편하다면, 저는 전체 단계를 바꾸기 전에 그 사이트부터 예외에 넣겠습니다. 반대로 수많은 탭을 모두 예외로 등록하면 메모리 절약의 이점이 줄어듭니다.

## 필요한 사이트만 예외에 추가하기

같은 `성능` 화면에서 **일반 → 다음 사이트를 항상 활성 상태로 유지**를 찾습니다. 메모리 절약 스위치 바로 아래가 아니라 위쪽에 별도 항목으로 있습니다.

1. `다음 사이트를 항상 활성 상태로 유지` 오른쪽의 **추가**를 누릅니다.
2. 이미 열려 있는 사이트라면 **현재 사이트 추가**에서 해당 사이트를 선택합니다.
3. 직접 주소를 넣으려면 **수동으로 사이트 추가**를 선택합니다.
4. 유지할 사이트 주소를 입력하고 **추가**를 누릅니다.

<Image src="/chrome-memory-saver-tabs/02-add-site.png" alt="Chrome 사이트 추가 대화상자의 수동으로 사이트 추가 탭에 example.com을 입력한 화면" caption="example.com은 등록 절차를 확인하기 위한 예시 주소입니다. 실제로 사용할 때는 유지하려는 사이트 주소로 바꿉니다." />

주소 범위가 헷갈리면 현재 열린 사이트에서 고르는 방법부터 쓰는 편이 간단합니다. 수동 입력에서는 **어느 범위까지 예외로 둘지**도 확인해야 합니다. 공식 도움말의 예시는 다음처럼 구분됩니다.

| 입력 예시 | 예외로 지정하는 범위 |
| --- | --- |
| `google.com` | 해당 도메인과 `drive.google.com`, `calendar.google.com` 같은 하위 도메인 |
| `.google.com` | 앞에 점을 붙인 정확한 호스트. `www.google.com` 등 하위 도메인은 제외 |
| `www.google.com/finance` | 해당 경로에 해당하는 페이지. `www.google.com` 전체를 지정하는 것과 다름 |

표의 주소 범위는 Google의 공식 규칙입니다. 필요한 페이지가 `www`나 다른 하위 도메인으로 열리는지도 주소 표시줄에서 함께 확인하세요.

업무 페이지 하나를 유지하려고 `https://*`처럼 아주 넓은 예외를 넣을 필요는 없습니다. Google도 호스트 이름의 일부에 붙이는 와일드카드와 `google.com/*` 같은 패턴은 지원하지 않는다고 안내합니다. 잘 모르겠다면 별표를 덧붙이기보다 현재 사이트 선택이나 필요한 호스트부터 사용하세요.

## 등록 확인과 예외 해제

등록 후에는 **추가 창이 닫혔는지보다 목록에 의도한 주소가 남았는지**를 확인합니다.

1. `다음 사이트를 항상 활성 상태로 유지` 목록에 입력한 주소가 표시되는지 봅니다.
2. 설정 탭을 닫았다가 같은 `성능` 화면을 다시 엽니다.
3. 주소가 계속 남아 있는지 확인합니다. 메모리 절약을 함께 사용하려면 스위치도 켜져 있어야 합니다.
4. 이후 평소처럼 작업하면서, 다른 탭을 보다가 돌아왔을 때의 재로딩이 달라지는지 관찰합니다. 중요한 입력은 먼저 저장해 두세요.

<Image src="/chrome-memory-saver-tabs/03-site-added.png" alt="Chrome 성능 설정의 활성 상태 유지 목록에 example.com이 등록되고 메모리 절약이 켜져 있는 화면" caption="예외 주소가 목록에 나타난 상태입니다. 별도 시험 프로필에서는 설정 페이지 새로고침과 Chrome 종료·재실행 뒤에도 등록이 유지됐습니다." />

**설정 완료와 문제 해결 확인은 별개**입니다. 주소가 목록에 남으면 예외 등록은 완료된 것이지만, 사이트의 모든 재로딩이 없어졌다는 뜻은 아닙니다. 로그인 유지나 작성 내용 저장도 따로 확인해야 합니다.

예외가 더는 필요 없다면 해당 주소 오른쪽의 **점 세 개 메뉴 → 삭제**를 선택합니다. 확인한 Chrome 화면에서는 이 메뉴에 `수정`과 `삭제`가 있습니다. 여기서 삭제하는 것은 예외 항목이지, 사이트 계정이나 방문 기록이 아닙니다.

업무용과 개인용 Chrome 프로필을 나눠 쓰고 있다면, 문제가 생기는 창에서 설정을 확인하세요. 다른 프로필의 화면을 열어 놓고 설정이 없다고 판단하지 않도록 상단 프로필도 함께 확인하면 좋습니다. 프로필 분리 자체가 목적이라면 [크롬 업무용·개인용 계정 분리 안내](/blog/chrome-work-personal-profiles)를 참고할 수 있습니다.

## 예외 설정 후에도 반복될 때

예외를 추가했는데도 불편하다면 목록을 계속 늘리기보다, 어떤 상황에서 다시 로딩되는지부터 좁히는 편이 낫습니다.

**현재 보고 있는 탭도 반복해서 새로고침된다면** 사이트 자체의 갱신 기능과 확장 프로그램을 살펴보세요. 자동 새로고침용 확장 프로그램 등을 사용 중인지 확인하고, 필요 없는 확장 프로그램은 하나씩 사용 중지한 뒤 차이를 비교할 수 있습니다. 회사가 관리하는 보안 확장 프로그램이나 정책을 임의로 해제하지는 마세요.

**여러 탭과 앱을 동시에 쓸 때 전체가 느려진다면** 사용하지 않는 탭을 줄여 봅니다. [Google의 속도 개선 안내](https://support.google.com/chrome/answer/1385029?hl=ko)는 `더보기 → 도구 더보기 → 작업 관리자`에서 메모리 사용량순으로 작업을 확인하는 방법도 설명합니다. 처음에는 어떤 탭이 자원을 많이 쓰는지만 보세요. **프로세스 종료는 저장하지 않은 작업을 잃게 할 수 있습니다.**

**로그인 화면으로 돌아가거나 작성 중인 내용이 사라진다면** 해당 서비스의 로그인 정책과 자동 저장 상태를 확인해야 합니다. 예외 목록은 백업이나 저장 기능이 아닙니다. 사이트가 작업을 저장했는지 확인하지 않은 채 탭을 오래 열어 두는 방식으로 중요한 내용을 보관하지 않는 것이 좋습니다.

또한 통화·동영상 재생·화면 공유·다운로드·일부 입력된 양식·고정 탭 같은 활동은 원래 탭 비활성화를 막을 수 있다고 공식 도움말에 나와 있습니다. 그래서 어떤 탭이 한동안 유지됐다는 사실만으로 예외 설정의 효과를 단정하기도 어렵습니다.

권하는 출발점은 단순합니다. **메모리 절약은 유지하되, 다시 로딩되면 작업이 끊기는 사이트만 좁게 예외로 지정하세요.** 등록이 남는지 확인한 다음 실제 증상이 달라졌는지 살펴보면, 처음부터 전체 설정을 끄거나 브라우저 데이터를 삭제하는 것보다 변경 범위를 작게 유지할 수 있습니다.
