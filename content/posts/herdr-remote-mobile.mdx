### 목차

## 집 PC의 작업으로 돌아가기

집에서 Claude Code나 Codex에 작업을 맡겨 두고 나왔는데, 에이전트가 답변을 기다리는지 궁금할 때가 있습니다. Herdr의 공식 모바일 앱은 집 PC의 `herdr-core`에 SSH로 연결해 **기존 터미널을 열고 상태를 확인하거나 답변할 수 있습니다**. 다른 PC에서도 Herdr 데스크톱 앱이나 일반 SSH로 같은 작업에 접근할 수 있습니다.

이 글은 Windows 집 PC에 Herdr와 사용할 에이전트가 이미 있고, SSH 연결을 사용 중이거나 공식 안내로 준비하려는 분을 위한 안내입니다. Windows 설치와 공간·분할 화면은 [기존 Herdr 입문 글](/blog/herdr-agent-workspace)에서 먼저 확인할 수 있습니다.

## 집 PC에서 먼저 준비할 세 가지

### 전원과 네트워크

집 PC가 켜져 있고 절전으로 연결이 끊기지 않아야 합니다. 예를 들어 집 PC와 휴대폰, 다른 PC를 같은 Tailscale 네트워크에 연결하고 접근 권한을 허용하면, 공유기에서 SSH 포트 22를 공인 인터넷에 포워딩하지 않고도 접근할 수 있습니다. 외출 전에 각 기기가 집 PC의 Tailscale 주소 또는 이름에 도달하는지 확인해 두세요.

Herdr 데스크톱 창을 닫아도 core에서 실행 중인 터미널은 유지될 수 있습니다. 다만 PC 재부팅이나 core 장애 뒤에는 기존 프로그램이 그대로 계속 실행되는 것이 아니라 새 셸로 복원될 수 있으므로 다시 확인해야 합니다.

### Windows OpenSSH와 사용자

Windows 집 PC에는 접근 가능한 **OpenSSH Server**가 필요합니다. Tailscale이 기기 사이의 연결을 만들고, Windows OpenSSH가 로그인할 때 사용자를 확인합니다. 서버를 처음 설치한다면 글 끝의 `Windows OpenSSH 설치와 첫 연결`을 참고해 서비스와 방화벽 범위, 로그인 계정을 준비하세요.

Herdr의 공식 모바일 안내에 나오는 **Tailscale SSH** 서버는 Linux와 오픈소스 macOS CLI에서 지원합니다. 이 글의 Windows 집 PC에서는 Tailscale 네트워크에 연결한 뒤 **Windows OpenSSH**로 로그인합니다.

처음 연결할 때 표시되는 호스트 키 지문은 연결하려는 집 PC에서 미리 확인한 값과 대조하세요. 기본 설정에서 Ed25519 호스트 키를 사용하는 예라면 집 PC의 PowerShell에서 공개 키 지문을 확인할 수 있습니다.

```powershell
ssh-keygen -lf "$env:ProgramData\ssh\ssh_host_ed25519_key.pub"
```

연결 화면에 나온 키 종류와 같은 지문을 비교하세요. 위 파일이 없거나 다른 종류의 키가 표시되면 Windows OpenSSH의 `HostKey` 설정에서 사용할 공개 키를 확인합니다. 두 지문이 일치할 때만 연결을 승인하세요.

### 같은 계정의 core

집 PC에서 Herdr를 실행한 **동일 Windows 사용자**의 PowerShell을 열어 확인합니다.

```powershell
whoami
hc ls
```

`whoami`의 계정이 원격 SSH 로그인 계정과 같은지 확인하고, `hc ls`에서 찾으려는 터미널의 ID나 이름을 기록해 둡니다. `hc` 명령을 찾지 못하면 새 터미널에서 설치 경로를 확인합니다. 목록이 비어 있다면 원하는 작업이 이 계정의 core에서 시작됐는지 살펴보세요.

Herdr 데스크톱 앱은 창과 공간을 보여주고, `herdr-core`는 터미널을 실행하며 `hc`로 관리합니다. 이름이 비슷한 **Herdr TUI는 별도 런타임**을 사용하므로 거기서 시작한 에이전트는 공식 모바일 앱에 나타나지 않습니다. 앱 창만 닫는 것과 터미널 탭이나 pane을 닫는 것도 다릅니다. 후자는 해당 터미널을 종료합니다.

## 집 PC에서 확인할 작업 만들기

외출 전에 확인용 작업을 하나 띄워 두면 다른 기기에서 올바른 터미널을 찾기 쉽습니다.

1. 집 PC의 Herdr 앱에서 일반 터미널을 열고, 기존 프로젝트가 아닌 확인용 폴더로 이동합니다. 에이전트는 해당 PC에 설치·로그인되어 있어야 합니다.
2. 그 터미널에서 `codex` 또는 `claude` 중 하나를 실행합니다. 탭 이름도 `원격 확인`처럼 구분하기 쉽게 바꿔 둡니다.
3. 에이전트에게 다음 요청을 한 번 입력하고 응답을 기다립니다. 파일 변경이나 명령 실행을 승인하는 요청이 나타나면 내용과 권한을 검토하고, 확인만 하려면 승인하지 않습니다.

```text
지금까지 변경한 파일과 다음에 할 일을 3줄로 알려줘.
파일은 수정하지 말고 명령도 실행하지 마.
```

4. 집 PC 화면에 보이는 **터미널 이름과 마지막 응답 한 줄**을 기억합니다. 별도 PowerShell의 `hc ls`에서도 이 터미널의 ID를 확인합니다. 예를 들어 `t3`가 표시됐다면 아래의 `t3` 대신 실제 ID를 사용합니다. 이름과 ID는 다를 수 있습니다.

## 휴대폰에서 데모와 실제 연결

### 공식 앱과 데모

공식 앱은 개발자가 **Herdr, Inc.**인 Herdr입니다. [iPhone·iPad App Store](https://apps.apple.com/kr/app/herdr/id6828898364) 또는 [Android Google Play](https://play.google.com/store/apps/details?hl=ko&id=dev.herdr.app)에서 내려받을 수 있습니다.

11월 26일 한국 App Store에 표시된 버전은 `1.0.7`입니다. iPhone은 **iOS 26.0 이상**, iPad는 **iPadOS 26.0 이상**이 필요합니다.

공식 앱 첫 화면의 **Try the demo**를 누르면 실제 집 PC를 연결하기 전에 가상의 기기와 에이전트를 둘러볼 수 있습니다. Inbox에서 `Needs you`, `Done`, `Working`, `Idle`의 분류를 살펴보고 항목을 열어 터미널을 확인해 보세요.

### 집 PC 등록과 인증

데모를 마친 뒤 앱에서 기기 연결을 선택합니다. 집 PC의 Tailscale 이름 또는 주소, SSH 포트, 앞에서 확인한 Windows 사용자와 인증 방식을 입력하세요. 휴대폰 앱에서 만든 SSH 키를 쓴다면 집 PC에 **공개키만** 등록합니다. Windows는 일반 사용자와 관리자 계정의 등록 위치와 권한이 다릅니다. 본인 계정에 해당하는 절차는 글 끝의 `Windows OpenSSH 키 인증`에서 확인할 수 있습니다.

처음 제시되는 호스트 지문을 집 PC에서 확인한 지문과 비교한 다음 인증합니다. 연결이 되면 Inbox에서 작업 중인 에이전트를 열어 실제 터미널의 이름과 마지막 응답을 집 PC와 대조합니다. 상태를 보고하지 않는 프로그램은 Inbox의 상태 카드 대신 터미널 검색이나 공간에서 찾습니다. 공간 표시는 집 PC에서 Herdr 앱이 실행되는 조건을 확인하세요.

## 다른 PC에서 같은 터미널 열기

### Herdr 데스크톱 앱

다른 PC에도 Herdr 데스크톱 앱이 있다면 공식 안내의 **Settings → Machines** 또는 사이드바의 **Add machine**에서 집 PC를 등록합니다. SSH 설정에 저장된 호스트를 선택하거나 집 PC에 도달하는 SSH 대상을 입력합니다. 예를 들어 `homeuser@home-pc`는 설명용 계정과 호스트이므로 실제 값으로 바꾸세요. 필요한 호스트 키 확인이나 인증 안내가 뜨면 집 PC에서 확인한 정보와 대조합니다.

연결된 집 PC의 공간과 에이전트를 열어 앞서 기록한 터미널 이름과 마지막 응답을 확인합니다.

### 일반 SSH 대안

다른 PC에 Herdr 앱을 설치하지 않아도 SSH 클라이언트가 있고 집 PC에 접속할 수 있다면, 그 PC의 터미널에서 다음처럼 연결할 수 있습니다.

```bash
ssh homeuser@home-pc
```

계정과 주소는 예시입니다. 최초 지문을 대조하고 본인의 방식으로 인증한 뒤, **집 PC에 접속된 원격 셸**에서 실행합니다.

```text
hc ls
hc attach t3
```

`t3`를 앞에서 확인한 실제 터미널 ID나 이름으로 바꾸세요. 같은 터미널이 열리면 마지막 응답을 집 PC와 휴대폰에서 본 내용과 비교합니다. `Ctrl+\`를 누르면 에이전트를 실행 상태로 두고 화면에서 빠져나올 수 있습니다.

## 화면이 비어 있을 때

1. **SSH부터 확인:** 다른 PC에서 위 `ssh` 연결이 되는지 살펴봅니다. 실패하면 주소·포트·Tailscale 연결과 접근 권한, Windows OpenSSH 서비스와 인증을 먼저 확인합니다. 호스트 지문이 다르면 무시하고 진행하지 않습니다.
2. **같은 사용자의 core 확인:** SSH 로그인 뒤 `whoami`와 `hc ls`로 집 PC에서 작업을 띄운 계정과 터미널 목록을 비교합니다. 로그인 셸에서 `hc`를 찾지 못하면 원격 계정의 PATH와 core 설치를 확인합니다.
3. **실행한 제품 확인:** 작업이 Herdr 데스크톱 앱의 core가 아니라 별도 Herdr TUI에서 시작됐다면 공식 모바일 앱에 표시되지 않습니다. 터미널 목록에는 있지만 Inbox에 없다면 해당 프로그램이 상태를 보고하지 않을 수 있으니 터미널 검색에서 찾습니다.

## 비용과 전달되는 정보

공식 모바일 안내 기준 Herdr 앱은 무료입니다. Claude Code나 Codex의 구독·모델 사용량·API 비용은 별도 조건을 따릅니다. 원격 화면을 닫아도 에이전트 작업이 계속되면 그 사용량이 발생할 수 있습니다.

Herdr 개인정보 안내에 따르면 모바일 터미널 트래픽은 휴대폰과 추가한 컴퓨터 사이를 SSH로 오갑니다. 앱에서 피드백을 보내면 메시지와 직접 입력한 이메일, 첨부 스크린샷, 앱·기기·core 버전 정보가 Herdr에 전달됩니다. 데스크톱 앱의 익명 사용 통계는 설정에서 끌 수 있습니다. 에이전트에 보낸 요청과 파일 정보는 각 모델 제공자의 정책을 따릅니다.

원격 터미널은 집 PC 사용자 계정으로 작업할 수 있는 통로입니다. 승인 요청은 작은 화면에서도 명령과 대상 파일을 읽은 뒤 판단하고, 공용 기기에 인증 수단을 남기지 않는 편이 안전합니다.
