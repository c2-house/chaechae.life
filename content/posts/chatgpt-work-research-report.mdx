ChatGPT에 자료조사를 부탁하면 읽기 좋은 답변은 받았는데, 회의에 가져갈 보고서는 따로 만들어야 할 때가 있습니다. 출처를 다시 열어보고, 비교 기준을 맞추고, 표를 문서로 옮기는 일이 남기 때문입니다. **ChatGPT Work는 이런 여러 단계의 일을 검토 가능한 결과물까지 맡기는 모드**입니다.

기존 ChatGPT와의 차이를 ‘검색이 가능한가’로 나누면 정확하지 않습니다. Chat도 검색이나 파일을 활용한 도움을 줄 수 있습니다. Work를 선택할 이유는 한 번의 답변보다 **자료 수집·분석·파일 작성이 이어지는 작업**을 맡기고 싶을 때입니다.

이 글은 2026년 9월 18일 확인한 공식 사용 안내를 바탕으로 작성했습니다. 아래 프롬프트는 독자가 따라 해볼 수 있도록 구성한 요청 예시이며, Work에서 실제 보고서를 생성해 품질이나 소요 시간을 측정한 후기는 아닙니다.

## Chat과 Work의 역할 차이

[OpenAI 도움말](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)은 Chat을 빠른 대화형 도움, Work를 길고 여러 단계인 업무와 완성된 결과물을 위한 에이전트로 구분합니다. 소프트웨어 개발과 저장소 작업을 담당하는 Codex도 별도 경험으로 유지됩니다.

| 맡기려는 일 | 먼저 고려할 모드 | 요청의 중심 |
| --- | --- | --- |
| 개념 설명, 아이디어 정리, 짧은 문장 수정 | Chat | 지금 필요한 답변 |
| 여러 자료를 모아 비교표·보고서·발표자료 작성 | Work | 검토하고 사용할 결과물 |
| 저장소 수정, 테스트 실행, 코드 변경 검토 | Codex | 코드와 실행 결과 |

이는 기능을 서로 완전히 나눈 표가 아니라 **어디에서 시작하면 좋은지에 대한 기준**입니다. 짧은 비교 질문까지 모두 Work로 보낼 필요는 없습니다. 반대로 여러 출처를 찾아 문서와 스프레드시트를 함께 만들어야 한다면 Work의 작업 방식이 더 잘 맞습니다.

예를 들어 Chat에는 ‘코드 호스팅 서비스를 고를 때 어떤 기준을 봐야 하나요?’라고 물을 수 있습니다. Work에는 ‘공식 자료로 세 서비스를 비교하고, 출처가 붙은 비교표와 팀장에게 보낼 검토용 보고서를 만들어 주세요’라고 맡기는 식입니다.

또 하나 구별할 이름은 **ChatGPT Business**입니다. Business는 조직용 구독 요금제이고, Work는 작업을 수행하는 모드입니다. Work를 사용한다는 이유만으로 Business의 조직 관리나 데이터 정책이 자동으로 적용되는 것은 아닙니다.

## Work 시작과 자료 준비

[공식 시작 안내](https://learn.chatgpt.com/docs/get-started-with-work)에 따른 기본 흐름은 다음과 같습니다.

1. **웹·모바일에서는 ChatGPT에서 Work를 선택**합니다. 데스크톱에서는 왼쪽 위 메뉴에서 ChatGPT를 선택한 뒤 상단의 Chat/Work 전환에서 Work를 고릅니다.
2. 새 대화를 시작하거나 기존 프로젝트에서 Work 대화를 엽니다. 프로젝트는 관련 대화·파일·지침을 함께 두고 이어서 작업할 때 유용합니다.
3. 필요한 파일을 첨부하고 결과물의 목적, 독자, 형식과 제약을 입력합니다.
4. 작업 진행 중 질문에 답하거나 방향을 수정하고, 결과물을 검토한 뒤 같은 대화에서 수정을 요청합니다.

Work가 보이지 않는다면 구독부터 다시 결제할 문제가 아닐 수 있습니다. 공식 도움말은 계정별 순차 제공을 안내하며, 조직에서는 역할별 권한도 영향을 줍니다. 데스크톱 앱 업데이트와 워크스페이스의 Work 접근 권한을 먼저 확인하는 편이 좋겠습니다.

### 로컬과 클라우드 선택

웹·모바일 Work는 클라우드에서 실행됩니다. 데스크톱에서는 입력창의 `Work locally` 제어에서 **Cloud가 선택지로 제공될 때** 클라우드 작업을 선택할 수 있습니다. 클라우드 작업은 앱을 닫거나 컴퓨터를 꺼도 이어갈 수 있고, 지원되는 다른 기기에서 대화를 계속할 수 있습니다.

컴퓨터 안의 파일이나 설치된 앱이 필요한 작업은 로컬 실행을 고려합니다. 다만 클라우드로 전환한다고 내 컴퓨터의 폴더, 브라우저 로그인 상태, 사내 VPN 접근권이 그대로 따라가는 것은 아닙니다. 클라우드에서 쓸 자료는 첨부 파일이나 승인된 연결 경로로 제공해야 합니다.

### 첫 작업에 필요한 자료 범위

처음에는 **공개 웹 자료만 사용하는 작은 비교 업무**를 권합니다. 메일·Slack·Drive를 한꺼번에 연결하지 않아도 요청 설계와 결과 검수 방법을 익힐 수 있기 때문입니다.

업무 자료가 필요해지면 사이드바의 `Plugins`에서 관련 플러그인을 확인하고, 입력창에 `@`와 이름을 입력해 사용할 도구를 지정할 수 있습니다. 실제 이용 여부는 플랜, 조직 설정, 연결 계정의 권한에 달려 있습니다. 플러그인 설치와 자료 접근 허가는 별개의 단계입니다.

## 자료조사 요청과 중간 검토

예시는 **개발팀이 코드 호스팅 서비스를 검토하는 상황**으로 잡겠습니다. GitHub, GitLab, Bitbucket의 공개 자료를 비교하고, 도입 판단에 필요한 근거를 정리하는 작업입니다. 서비스별 우열을 미리 정하는 대신 비교 기준부터 고정합니다.

한 번에 보고서까지 요청할 수도 있지만, 처음에는 자료조사 뒤 멈추게 하는 편을 권합니다. 조사 대상이나 요금 기준이 틀리면 보기 좋은 보고서까지 같은 오류가 이어지기 때문입니다.

### 1단계: 조사 범위와 근거 목록

다음 예시에서 인원과 필수 조건은 실제 팀 상황에 맞게 바꾸면 됩니다. 공개 자료 조사만으로는 알 수 없는 사내 요구사항을 AI가 추측하지 않도록 적어주는 것이 중요합니다.

```text
개발자 10명인 팀의 코드 호스팅 서비스 검토를 도와주세요.
대상은 GitHub, GitLab, Bitbucket입니다.
독자는 개발팀장이고, 목표는 바로 계약하는 것이 아니라
검증할 후보와 추가 확인 질문을 정하는 것입니다.

현재 공개된 공식 가격표, 제품 문서, 보안 문서만 사용하세요.
비교 기준은 비공개 저장소, CI/CD 포함량과 초과 비용,
접근 제어·SSO, 감사 로그, 기존 저장소 이전의 제약입니다.

먼저 조사 계획을 짧게 설명하고 자료를 수집하세요.
서비스별로 요구사항에 해당하는 플랜 이름을 명시하고,
주장마다 출처 URL, 확인일, 적용 조건을 붙여주세요.
월간 결제와 연간 약정의 월 환산액을 섞지 마세요.
세금, 통화, 최소 인원 조건과 CI 과금 단위를 구분하세요.

공개 자료가 없거나 접근에 실패하면 미확인으로 남기세요.
서로 충돌하는 자료는 양쪽 근거를 함께 보여주세요.
가입, 결제, 무료 체험 신청, 외부 전송은 하지 마세요.

이번 단계에서는 근거 목록과 비교표 초안까지만 작성하고,
제가 검토할 때까지 최종 보고서 작성은 멈춰주세요.
```

이 요청에는 조사 대상뿐 아니라 **무엇으로 작업 완료를 판단할지**가 들어 있습니다. 출처가 없는 문장과 확인하지 못한 항목을 구분할 수 있어야 다음 단계로 넘어갈 수 있습니다.

### 조사 결과의 확인 기준

비교표가 나오면 모든 문장을 같은 비중으로 읽기보다, 결정을 바꾸는 항목부터 원문을 열어보는 것이 좋습니다.

- **플랜과 조건:** SSO나 감사 로그가 비교한 플랜에 실제 포함되는지 확인합니다. 상위 플랜의 기능을 하위 플랜 가격 옆에 붙이면 잘못된 비교입니다.
- **가격과 단위:** 사용자당 가격인지, 조직당 가격인지, 월간 결제인지 연간 약정인지 확인합니다. CI 사용량도 실행 시간·운영체제·러너 조건에 따라 같은 숫자가 아닐 수 있습니다.
- **출처의 직접성:** 링크가 공식 홈페이지 첫 화면에만 연결되는지, 해당 주장을 뒷받침하는 문서나 요금 항목으로 연결되는지 확인합니다.
- **미확인 항목:** 빈칸을 기능 없음으로 해석하지 않습니다. 공개 문서에서 못 찾은 것과 제공하지 않는 것은 다릅니다.

출처가 많이 붙었다고 보고서가 정확해지는 것은 아닙니다. **그 출처가 실제로 해당 문장을 지지하는지**를 확인해야 합니다. 잘못된 기준을 발견하면 최종 문서부터 고치기보다 비교표의 근거를 먼저 수정하는 편이 낫습니다.

## 비교표에서 보고서 파일로 확장

근거와 비교 기준을 검토한 뒤에는 같은 대화에서 결과물 제작을 요청합니다. [공식 프롬프트 안내](https://learn.chatgpt.com/docs/prompting#prompting-for-work)도 원하는 결과, 사용할 자료, 독자, 검토 기준을 명시하고 파일 생성과 최종 확인을 요청하도록 설명합니다.

### 2단계: 검토용 보고서와 비교표

```text
검토한 근거 목록과 비교표를 바탕으로 결과물을 작성하세요.

1. 개발팀장 검토용 한국어 보고서 DOCX
   - 본문은 약 2쪽, 상세 출처는 별도 부록
   - 첫 부분에 우선 검증할 후보와 판단 이유
   - 필수 요구사항 충족 여부, 비용 조건, 이전 위험
   - 계약 전에 담당자가 확인할 질문과 다음 행동

2. 항목별 비교표 XLSX
   - 서비스, 플랜, 비교 항목, 값, 단위, 조건, 출처 URL, 확인일
   - 공식 사실, 계산 결과, 판단을 구분
   - 비용 계산이 필요하면 입력값과 계산식을 별도로 표시
   - 미확인 항목을 임의로 0이나 '지원 안 함'으로 채우지 않기

필수 조건을 충족하지 못하면 가장 싼 후보라도 우선 추천하지 마세요.
정보가 부족하면 최종 선정 대신 추가 검증 대상을 제안하세요.

마지막으로 보고서와 비교표의 플랜 이름·수치·결론이 일치하는지,
파일이 정상적으로 열리는지 확인하고 남은 문제를 알려주세요.
지정 형식을 만들 수 없으면 그 한계를 설명하고 대안을 제시하세요.
이메일 발송, 공유 링크 생성, 외부 서비스 게시 없이
제가 검토할 파일까지만 만들어주세요.
```

파일 형식을 정하면 활용 목적이 분명해집니다. 보고서는 의사결정에 필요한 설명을, 스프레드시트는 근거와 계산을 다시 확인하는 역할을 맡습니다. 다만 형식을 요청했다고 모든 환경에서 동일한 결과가 보장되는 것은 아니므로, 파일 생성에 실패했을 때의 처리도 요청에 포함했습니다.

### 최종 파일의 검수

Work가 ‘완료했다’고 답해도 **파일을 직접 열어보는 단계**는 남습니다. DOCX의 표가 잘리거나 XLSX의 값이 텍스트로 들어가면 내용이 맞더라도 바로 사용하기 어렵습니다.

먼저 보고서의 추천 이유를 비교표와 대조합니다. 가격과 계산은 몇 개를 골라 다시 계산하고, 중요한 출처 링크도 열어봅니다. 특히 ‘비용이 가장 낮다’ 같은 결론에는 포함량과 추가 요금의 가정이 빠지지 않았는지 확인해야 합니다.

수정 요청은 ‘더 잘 만들어 주세요’보다 구체적으로 쓰는 편이 좋습니다. 예를 들어 ‘연간 약정 금액을 월간 결제액과 분리하고, 미확인인 SSO 조건을 확정된 장점에서 빼 주세요. 변경한 근거를 보고서와 비교표에 함께 반영해 주세요’라고 요청할 수 있습니다.

반복 보고서로 확장하고 싶다면 이 단발 작업이 쓸 만한 결과를 내는지 먼저 확인하는 것이 순서입니다. 처음부터 예약 실행을 걸기보다, 필요한 출처와 검수 기준을 다듬은 뒤 반복 작업을 검토하는 편이 낫겠습니다.

## 요금과 Codex 공유 사용량

Work를 별도 무제한 보고서 생성 상품으로 생각하면 곤란합니다. [공식 가격 문서](https://learn.chatgpt.com/docs/pricing)는 **Work와 Codex가 가격 체계·크레딧·사용 한도를 공유한다**고 설명합니다. Codex로 개발 작업을 많이 했다면 Work에 사용할 잔여량에도 영향을 줄 수 있습니다.

확인 시점의 공개 가격표에서 Plus는 월 20달러, Pro는 월 100달러부터입니다. Business 기본 가격 카드는 연간 청구 시 사용자당 월 20달러이며 최소 2명 조건이 있고, 월간 청구는 사용자당 월 25달러로 안내합니다. 이는 가격표의 USD 기준으로, 실제 결제액은 결제 화면의 통화·세금·약정 조건을 확인해야 합니다. 조직의 좌석 유형과 별도 계약 조건도 구별해야 합니다.

무료 접근은 문서 표현이 일치하지 않습니다. 가격 문서 상단은 Free와 Go를 포함한 플랜 목록에 Work와 Codex를 함께 기재하지만, Work 도움말은 **웹·모바일 Work를 지원 대상 유료 플랜에 제공**한다고 설명합니다. 따라서 ‘무료 계정에서도 웹 Work를 바로 쓸 수 있다’거나 ‘모든 Work가 유료 전용이다’라고 단정하기보다, 계정의 실제 Work 노출과 허용 범위를 확인해야 합니다.

사용량도 보고서 몇 편으로 환산하기 어렵습니다. 모델, 입력 자료, 도구 사용, 추론 설정과 작업 규모에 따라 소모량이 달라집니다. 가격표의 메시지 수 추정치를 보고서 생성 보장 횟수로 읽으면 안 됩니다. Plus와 Pro는 포함량 소진 후 추가 크레딧을 구매할 수 있지만, 이것이 초과 시 무조건 자동 결제된다는 뜻은 아닙니다.

첫 작업에서는 다음처럼 범위를 줄일 수 있습니다.

- 비교 대상과 자료 기간을 제한합니다.
- 필수 결과물과 추가 디자인 작업을 나눕니다.
- 출처 검토 뒤 보고서 작성으로 넘어가 불필요한 재작성을 줄입니다.
- 큰 작업 전에 사용량 화면과 추가 크레딧 설정을 확인합니다.

## 업무 자료와 외부 변경의 경계

보고서 예시를 공개 자료로 시작한 이유는 오류뿐 아니라 데이터 접근 범위를 쉽게 확인할 수 있기 때문입니다. 로컬 문서와 업무 앱을 연결하면 편해지는 만큼 고려할 조건도 늘어납니다.

**로컬 실행은 자료가 기기 밖으로 전혀 나가지 않는다는 뜻이 아닙니다.** [로컬 보안 문서](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-local-security)는 로컬 실행과 오프라인·기기 내 모델 추론을 구분합니다. 작업에 필요한 프롬프트, 파일 일부, 화면이나 도구 결과 등이 OpenAI 서비스로 전송될 수 있으며, 도움말도 로컬 작업의 메시지와 문맥이 클라우드에 저장될 수 있다고 안내합니다.

업무 앱의 읽기와 쓰기 권한도 구분해야 합니다. [클라우드 보안 문서](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-cloud-security)에 따르면 연결 계정과 관리 정책에 따라 허용된 쓰기 작업이 매번 확인창을 띄우지 않고 수행될 수도 있습니다. ‘보고서만 만들어 달라’는 프롬프트와 함께, 가능한 경우 실제 연결 설정도 읽기 전용이나 제한된 작업 범위로 맞추는 편이 좋습니다.

또한 Business·Enterprise·Edu는 업무 데이터를 기본적으로 학습에 사용하지 않는 정책이 적용되지만, 개인 플랜에 같은 기본값을 가정하면 안 됩니다. 개인 계정에서는 [데이터 제어 설정](https://help.openai.com/en/articles/8983130-what-if-i-want-to-keep-my-history-on-but-disable-model-training)을 확인하고, 회사 자료는 조직의 반출·AI 이용 정책에 따라 취급해야 합니다.

처음부터 메일 전체나 넓은 공유 폴더를 연결하기보다, 필요한 파일 사본과 특정 폴더부터 허용하는 것이 낫겠습니다. 작성한 파일을 검토하는 일과 다른 사람에게 보내는 일도 별도의 단계로 남겨두는 편이 안전합니다.

## 처음 맡기기 좋은 업무의 크기

첫 작업은 **자료의 정확성과 결과물의 쓸모를 직접 판단할 수 있는 일**로 고르는 편이 좋습니다. 익숙한 분야의 비교 보고서, 회의 자료를 바탕으로 한 의사결정 메모, 공개 문서의 변경 내용 정리가 좋은 출발점이 될 수 있습니다.

답변 한 문단이면 충분한 질문은 Chat에 남겨두어도 됩니다. 여러 출처를 확인하고 실제 파일까지 만들어야 할 때 Work를 선택하되, 처음에는 조사 대상과 결과물 하나를 작게 정하는 편을 권합니다. 출처를 확인하고 수정 요청을 해본 뒤에야 더 많은 자료나 반복 업무를 맡길지 판단할 수 있습니다.

결국 Work의 사용법에서 중요한 것은 긴 프롬프트 자체가 아닙니다. **어디까지 맡기고, 어떤 근거와 파일을 받아야 하며, 어느 지점에서 사람이 확인할지**를 정하는 것입니다.
