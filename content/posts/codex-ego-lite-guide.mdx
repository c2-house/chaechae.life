Codex에 웹 자료를 조사해달라고 했는데 검색 결과의 링크만으로 부족할 때가 있습니다. **ego(lite)는 Codex 같은 로컬 에이전트가 웹페이지를 열고 검색창과 링크를 조작하도록 연결하는 Chromium 브라우저**입니다. Codex가 지시를 해석하고, `ego-browser`가 브라우저 작업을 실행합니다.

이번에는 Windows에서 Codex CLI로 Python 공식 문서를 검색하고, `pathlib` 메서드 세 개의 용도·주의점·원문 링크를 모았습니다. 처음에는 샌드박스 안에서 브라우저 연결이 실패했지만, 공개 문서에 접근하는 **ego-browser 명령만 한 번씩 승인**한 뒤 실제 검색과 본문 수집까지 끝냈습니다. Codex 전체를 Full Access로 바꾸지는 않았습니다.

확인 환경은 2026년 10월 21일의 Codex CLI `0.163.0-alpha.10.2`, ego(lite) `0.6.0.16`, ego-browser 사용 가이드 `2.1.0`입니다. 아래는 이 Windows CLI 환경에서 확인한 절차입니다. Codex 앱의 메뉴와 CLI의 명령별 승인은 구분해서 보시면 됩니다.

## 설치와 스킬 확인

먼저 같은 Windows 컴퓨터에 [ego(lite)를 설치하고 초기 설정을 완료](https://lite.ego.app/document/en/docs/windows/quick-start)합니다. 공개 문서 검색에는 기존 브라우저의 비밀번호·쿠키 가져오기나 기본 브라우저 변경이 필요하지 않습니다. 이번에도 그런 작업은 하지 않았습니다.

<Image src="/ego-lite-public-research/01-ready.png" alt="ego(lite) 초기 설정을 완료한 Windows 앱의 에이전트 연결 안내" caption="ego(lite) 0.6.0.16 Windows 앱의 실제 초기 설정 완료 화면입니다. 이 화면 자체가 Codex의 작업 성공을 뜻하지는 않습니다." />

Codex CLI 설치와 로그인이 완료되어 있어야 합니다. 아직 준비하지 않았다면 [공식 CLI 시작 안내](https://developers.openai.com/codex/cli/)를 먼저 확인하세요. 브라우저 사용과 별개로 Codex 계정의 이용 조건과 한도가 적용됩니다.

초기 설정 뒤 Codex를 새로 열어 `ego-browser` 스킬이 있는지 확인합니다. 스킬은 Codex가 해당 도구의 사용법을 읽도록 제공하는 안내 파일입니다. 이번 CLI 세션에서는 자동으로 발견된 목록에서 이 스킬을 읽고, `ego-browser skill`로 설치 버전에 맞는 가이드를 불러왔습니다.

Codex 입력창에 다음처럼 요청할 수 있습니다.

```text
$ego-browser를 사용해줘.
먼저 스킬과 설치 버전의 사용 가이드를 읽고,
브라우저 작업에 필요한 준비가 됐는지 확인해줘.
설정이나 권한을 임의로 변경하지 마.
```

[공식 Codex 앱 안내](https://lite.ego.app/document/en/docs/windows/codex)에서는 `/ego`를 입력해 Ego Browser를 선택합니다. 앱에서 스킬이 보이지 않으면 ego(lite)의 초기 설정을 끝낸 뒤 Codex를 종료하고 다시 열어 확인하라는 안내입니다. CLI에서 명령을 찾지 못하는 문제와 스킬이 없는 문제는 다릅니다. 이번 CLI 환경에서도 PATH로는 명령을 찾지 못했지만 설치된 실행 파일의 전체 경로로 가이드를 읽을 수 있었습니다.

## 명령별 승인과 첫 호출

공식 ego(lite) Windows 문서는 Codex 앱의 Full access 설정을 안내합니다. 다만 공개 페이지 하나를 시험하려고 모든 작업의 권한을 넓힐 필요가 있는지는 따로 검토할 만합니다. [Codex의 승인 문서](https://learn.chatgpt.com/docs/agent-approvals-security)는 샌드박스 범위와 승인 시점을 별도로 설명합니다.

이번에는 터미널에서 다음 옵션으로 Codex CLI를 시작했습니다. `codex`가 설치되어 있고 명령으로 인식되는 환경에서 실행하는 예입니다.

```powershell
codex --sandbox workspace-write --ask-for-approval on-request
```

`workspace-write`는 작업 폴더 안의 작업을 허용하는 샌드박스 모드이고, `on-request`는 필요한 작업에서 승인을 요청하게 하는 옵션입니다. **이 옵션만 넣으면 ego가 자동으로 연결되는 것은 아닙니다.** Codex가 실제로 실행하려는 명령과 그 안의 스크립트를 확인한 뒤 승인해야 합니다.

이번에는 Codex가 공개 Python 문서만 여는 스크립트를 준비하도록 했습니다. 확인한 내용은 지정한 작업 공간 생성, 공개 URL 열기, 제목과 페이지 내용 반환뿐이었습니다. Codex가 그 파일을 실행하는 `ego-browser ... nodejs -e ...` 명령의 샌드박스 밖 실행을 요청했을 때 **Yes, proceed**를 골랐습니다. 이후에도 검색과 원문 수집 명령을 각각 확인해 한 번씩 승인했습니다. 다시 묻지 않는 영구 승인 항목은 선택하지 않았습니다.

<Image src="/codex-ego-lite-guide/01-codex-result.png" alt="Codex CLI가 종료 코드 0과 고유 원문 세 개 검증, TaskSpace 2 유지 상태를 보고한 실제 실행 결과" caption="명령별 승인 뒤의 실제 Codex CLI 완료 결과입니다. 승인 대화상자가 아니라 결과 영역만 발췌했습니다." />

연결 성공 여부는 종료 코드뿐 아니라 결과로 확인합니다. 이번에는 `codex-ego-public-guide`라는 TaskSpace와 ID `2`, 실제 Python 문서 URL과 제목이 반환됐습니다. TaskSpace는 이번 작업의 탭을 모으는 공간이며 이후에도 같은 `p1` 탭을 사용했습니다. 작업 탭의 분리를 계정 접근의 보안 격리로 해석하면 안 됩니다.

## 공개 문서 조사 요청

처음 맡길 작업은 사이트와 결과 항목을 좁히는 편이 좋습니다. 아래는 이번에 수행한 범위를 독자가 요청하기 쉽게 정리한 예시이며, 실제 대화 전체를 복사한 것은 아닙니다.

```text
$ego-browser로 Python 공식 문서에서 pathlib를 검색해줘.
Quick search에 pathlib를 입력하고 검색 결과의 pathlib 문서를 열어줘.
Path.iterdir, Path.glob, Path.read_text의 용도와 주의점,
각 메서드의 원문 링크를 표로 정리해줘.
공개 문서만 읽고 로그인·업로드·계정 설정 변경은 하지 마.
샌드박스 밖 실행이 필요하면 ego-browser 명령 한 건씩 승인을 요청해줘.
확인하지 못한 내용은 추측하지 마.
```

Codex는 실제 페이지의 **Quick search** 입력란에 `pathlib`를 넣고 **Go**를 눌렀습니다. 검색 결과에 나타난 `pathlib — Object-oriented filesystem paths` 링크를 연 다음, 요청한 메서드의 설명을 읽었습니다. 주소를 추측해서 표만 만든 작업과 구분되는 부분입니다.

<Image src="/codex-ego-lite-guide/02-search.png" alt="Codex가 ego-browser로 실행한 Python 공식 문서의 pathlib 검색 결과" caption="Codex의 명령별 승인을 거쳐 실제로 검색창에 입력하고 버튼을 누른 결과입니다. 출처: Python 공식 문서. 실제 검색 결과의 입력란과 링크 영역을 발췌했습니다." />

명령이 반환하는 Snapshot은 이미지가 아니라 입력란·버튼·링크 등을 표현한 페이지 정보입니다. Codex는 여기서 조작할 대상을 찾았고, 실제 화면 이미지는 별도로 저장했습니다. 검색 페이지로 이동했다고 결과 목록까지 준비된 것은 아니므로, 결과 링크가 나타나는 조건을 기다린 뒤 다음 단계로 넘어갔습니다.

이 방식은 공개 릴리스 노트에서 변경 항목과 링크를 모으거나, 공식 지원 문서에서 특정 설정의 조건을 찾는 일에도 응용할 수 있습니다. 다만 이번에 실제 실행한 예시는 Python 문서 조사입니다. 로그인된 업무 사이트나 사내 자료까지 검증한 것은 아닙니다.

## 결과 확인과 문제 해결

Codex가 반환한 내용을 줄여 정리하면 다음과 같습니다. 수집한 JSON에 메서드가 정확히 세 개 있고, 중복이나 빈 설명이 없는지도 확인했습니다.

| 항목 | 용도 | 함께 확인한 주의점 |
|---|---|---|
| [Path.iterdir()](https://docs.python.org/3/library/pathlib.html#pathlib.Path.iterdir) | 디렉터리 바로 아래의 항목 순회 | 반환 순서는 임의이며, 접근할 수 없으면 OSError 발생 |
| [Path.glob()](https://docs.python.org/3/library/pathlib.html#pathlib.Path.glob) | 패턴과 일치하는 경로 수집 | 순서가 필요하면 정렬, 파일시스템 검색의 OSError는 억제됨 |
| [Path.read_text()](https://docs.python.org/3/library/pathlib.html#pathlib.Path.read_text) | 파일 내용을 문자열로 읽기 | 파일을 열고 닫으며, newline 인수는 Python 3.13부터 제공 |

<Image src="/codex-ego-lite-guide/03-glob.png" alt="Codex가 ego-browser로 읽고 캡처한 Path.glob 원문의 정렬 및 오류 처리 설명" caption="Python 3.15.0 문서의 실제 Path.glob 절입니다. 순서와 오류 처리 조건을 요약 결과와 대조했습니다. 문서 속 Python 예제를 실행한 결과는 아닙니다." />

[Python 문서 화면의 라이선스와 저작권 고지](/images/blog/ego-lite-public-research/LICENSE-PYTHON.txt)를 함께 확인할 수 있습니다. 완료 기준은 표가 보기 좋게 나왔는지가 아니라 **요청 항목이 모두 있는지, 링크가 해당 절로 가는지, 요약이 원문과 맞는지**입니다.

연결이 안 될 때는 증상에 따라 확인할 위치를 나누세요.

- `Please complete the onboarding process first`: ego(lite)의 초기 설정부터 완료합니다. 이전 시도에서는 이 안내와 함께 종료 코드 0이 나왔지만 페이지 결과는 없었습니다.
- `ego-browser` 명령을 찾을 수 없음: 설치와 초기 설정, 새 터미널의 명령 인식 여부를 확인합니다. 이번에는 이미 설치된 실행 파일의 전체 경로를 사용했습니다. 불필요한 재설치나 PATH 수정을 먼저 하지 않았습니다.
- `Failed to connect to ego_cli bootstrap`: 이번 Codex의 기본 샌드박스 실행에서 실제로 나온 오류입니다. 같은 공개 페이지 작업을 명령별로 승인해 샌드박스 밖에서 실행하자 연결됐습니다. 다만 같은 오류가 모든 환경에서 샌드박스 하나만 원인이라는 뜻은 아닙니다. 실행 중인 ego(lite)와 초기 설정을 함께 확인하고, 관리형 환경에서 승인이 막혀 있으면 정책을 우회하지 마세요.
- URL은 바뀌었는데 내용이 비어 있음: 필요한 결과가 아직 로드 중인지 확인합니다. 실제 결과 링크나 원하는 본문이 나타난 뒤 읽도록 요청할 수 있습니다.

[개인정보 처리방침](https://lite.ego.app/privacy)에 따르면 브라우저가 로컬에서 돌아가도 읽은 내용은 연결된 AI 도구에 전달될 수 있습니다. 공개 페이지로 먼저 확인하고, 민감한 정보나 로그인된 계정을 맡기기 전에는 브라우저와 모델 제공자의 데이터 정책 및 권한 범위를 별도로 검토하는 편이 좋습니다. 작은 작업 하나에서 **검색부터 출처 대조까지 끝나는지** 확인한 다음 업무 범위를 넓혀보세요.
