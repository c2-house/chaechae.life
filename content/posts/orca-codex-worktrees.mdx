### 목차

## 여러 작업을 나누는 이유

AI에게 기능을 만들게 한 뒤 테스트 계획과 사용성 검토도 부탁하고 싶을 때가 있습니다. 하나의 작업 폴더에서 동시에 수정하면 어떤 변경이 어느 요청에서 왔는지 살피기 어려워질 수 있죠. Orca는 같은 Git 저장소에서 별도의 워크트리를 만들고 각 작업에 Codex 같은 에이전트를 붙여 관리하는 데스크톱 도구입니다.

Windows에서 작은 게시판을 만든 다음, 같은 기준 커밋에서 두 워크트리를 열어 테스트 계획과 모바일·키보드 사용성 코드 검토를 병렬로 맡겨봤습니다. 두 결과는 각각 별도 문서였고, 확인한 뒤 실습 저장소에 모았습니다. **워크트리가 파일 작업을 나눠줄 뿐 결과의 정확성이나 통합까지 보장하는 것은 아닙니다.**

## Orca와 Codex 준비

[Orca 공식 설치 안내](https://www.onorca.dev/docs/install)에서 Windows 설치 프로그램을 받아 실행합니다. 이 글은 Windows에서 확인한 흐름이며 다른 운영체제는 설치 파일과 화면이 다를 수 있습니다. 처음 실행할 때 저장소 접근과 기존 에이전트 설정 가져오기 안내가 나타날 수 있으니 표시되는 권한과 대상을 확인하세요.

Codex는 Orca에 포함된 별도 모델이 아니라 이미 사용하는 에이전트 CLI입니다. [Orca의 Codex 안내](https://www.onorca.dev/docs/agents/codex)에 따르면 먼저 [Codex를 설치](https://developers.openai.com/codex/cli/)하고 터미널에서 로그인한 뒤 Orca의 에이전트 선택 메뉴에서 Codex를 선택합니다. 공식 안내의 기본 계정은 기존 `~/.codex` 로그인을 사용합니다. 로그인 정보나 토큰을 글이나 캡처에 넣지 마세요. ChatGPT 계정 로그인과 API 키 사용은 서로 다른 인증·과금 경로이므로 본인의 플랜과 사용 한도를 확인하고, 저장소 접근과 명령 실행 권한은 요청 내용을 살펴 필요한 범위만 승인하세요.

이번 환경의 Codex CLI는 `0.166.0`이었습니다. Orca의 메뉴 이름이나 설치·계정 연결 흐름은 업데이트에 따라 달라질 수 있습니다.

## 게시판 저장소와 워크트리

실습에는 Git으로 관리하는 폴더가 필요합니다. 게시판은 HTML, CSS, JavaScript로 만든 로컬 예제로, `index.html`을 브라우저에서 열어 글을 작성하고 삭제할 수 있습니다. 서버나 계정에 저장하는 서비스는 아닙니다.

직접 따라 한다면 빈 폴더에서 Codex에 아래와 같이 게시판 제작을 요청해도 됩니다. 이 문장은 재현을 위한 예시이므로 생성되는 코드와 화면은 이 글의 결과와 다를 수 있습니다.

```text
HTML, CSS, JavaScript로 작은 게시판을 만들어줘. 제목과 내용이 있는 글을 등록하고 삭제할 수 있게 하고, 새로고침 후에도 이 브라우저에 글이 남도록 localStorage를 사용해줘. 빈 입력을 막고 index.html을 직접 열어 실행할 수 있게 해줘.
```

생성된 파일을 검토하고 해당 폴더의 터미널에서 `git init`, `git add index.html styles.css app.js`, `git commit -m "Create board"` 순서로 기준 커밋을 만듭니다. 파일명이 다르면 실제 생성된 파일을 지정하세요. 이미 Git 저장소인 프로젝트라면 기존 작업의 변경 사항을 확인하고 보관한 뒤 원하는 커밋을 기준으로 사용하면 됩니다.

Orca 왼쪽 **프로젝트 추가**에서 이 저장소를 추가하고, 프로젝트의 **새 작업 트리 만들기**로 작업별 워크트리를 만듭니다. 작업 이름과 시작 기준을 확인한 뒤 각 워크트리에서 Codex를 선택합니다. 워크트리는 같은 저장소의 Git 이력을 공유하지만 체크아웃된 파일과 브랜치는 별도입니다. 시작 기준이 다르면 결과를 비교할 때 그 차이도 고려해야 합니다.

이번에는 게시판의 기준 커밋 `04e712b`에서 `게시판 테스트 작성`과 `게시판 사용성 검토`를 만들었습니다. 실제로 `git worktree list`에서 두 경로와 브랜치가 분리되어 있고 같은 커밋을 가리키는 것을 확인했습니다.

## Codex에 나눠 맡긴 작업

각 워크트리의 에이전트 입력란에 작업 범위와 결과 파일을 구체적으로 적었습니다. 요청은 한국어로 작성했고, 다른 파일을 건드리거나 임의로 커밋하지 않도록 범위를 제한했습니다. 예를 들어 테스트 쪽에는 다음처럼 요청할 수 있습니다.

```text
이 게시판의 글 등록과 삭제, 새로고침 후 저장 유지, 빈 입력 차단을 확인할 수 있는 수동 테스트 계획을 작성해줘. tests 폴더에 문서만 만들고 다른 파일은 수정하거나 커밋하지 마.
```

사용성 쪽에는 모바일 화면과 키보드 접근성을 검토해 `docs` 폴더에 문서를 만들도록 요청했습니다. 처음에는 브라우저 도구를 이용한 확인이 시도됐지만 해당 명령은 승인되지 않았습니다. 이후 다음 요청으로 **브라우저 도구를 쓰지 않는 코드 정적 검토**로 범위를 바꿨습니다.

```text
브라우저 도구는 사용하지 말고 현재 코드만 검토해줘. 실제 화면 검증을 했다고 쓰지 말고 확인이 필요한 항목을 구분해서 docs 폴더에 검토 문서만 작성
```

<Image src="/orca-codex-worktrees/review.png" alt="Orca에서 브라우저를 사용하지 않는 코드 검토 요청과 문서 작성 완료가 표시된 화면" caption="사용성 작업은 정적 검토로 범위를 바꿨습니다." />

테스트 작업은 등록 3개, 삭제 3개, 새로고침 유지 3개, 빈 입력과 복구 7개 등 16개 사례가 담긴 `tests/test-plan.md`를 만들었습니다. 이는 **실행 결과가 아니라 테스트 계획**입니다. 사용성 작업의 `docs/mobile-keyboard-review.md`는 삭제 복구 수단과 저장 결과 안내 위치 같은 개선 후보를 코드 근거와 추가 확인 항목으로 구분했습니다. 모바일 기기와 스크린 리더에서 통과했다는 뜻은 아닙니다.

## 게시판 동작과 결과 모으기

별도로 게시판을 브라우저에서 열어 테스트 글을 등록했습니다. 새로고침 뒤 제목과 내용이 남아 있었고, 삭제한 다음 다시 새로고침했을 때 저장 배열이 빈 상태인 것도 확인했습니다. 이 확인은 한 브라우저에서 한 글로 수행한 기본 흐름이며, 위 16개 사례나 여러 브라우저 전체를 실행한 결과는 아닙니다.

<Image src="/orca-codex-worktrees/board.png" alt="새로고침 후에도 테스트 글 한 개가 남아 있는 작은 게시판 화면" caption="등록한 테스트 글이 새로고침 뒤에도 남아 있는 상태입니다." />

이 게시판은 `localStorage`를 사용합니다. 따라서 글은 해당 브라우저에 남고 다른 기기나 브라우저에 공유되지 않습니다. `file://`로 직접 열 때 저장 방식은 브라우저에 따라 달라질 수 있으니 같은 브라우저와 파일 경로로 확인하고, 중요한 데이터를 실습에 사용하지 않는 편이 안전합니다.

두 작업의 결과는 각각 추적되지 않은 새 문서로 남아 있었습니다. 실제 파일과 내용을 검토한 뒤 실습용 원본 저장소에 두 문서를 복사하고 원본과 내용이 같은지 확인했습니다. 서로 다른 파일이라 충돌은 없었지만, **복사는 Git 병합이나 자동 통합과 다릅니다.** 같은 파일을 수정했다면 변경 내용을 비교하고 충돌을 해결한 다음 테스트해야 합니다.

## 병렬 작업에서 남는 비용

두 작업을 나란히 실행하면 진행 상황과 결과를 각 워크트리에서 나누어 볼 수 있습니다. 반면 각 에이전트의 권한 요청을 확인하고, 결과가 실제 실행인지 계획인지 구분하고, 중복이나 충돌을 검토하는 일은 남습니다. 이번에는 같은 일을 순차 실행한 대조군이나 시간을 측정하지 않았으므로 얼마나 빨라졌다고 평가할 수는 없습니다.

독립적인 조사·테스트 계획·구현 후보처럼 서로 덜 겹치는 일을 나누고, 마지막에 사람이 결과와 권한을 검토하는 흐름부터 시작해보면 좋겠습니다. 워크트리를 삭제하면 작업 디렉터리와 브랜치에도 영향이 있을 수 있으니 보관할 변경을 먼저 확인하세요. 자세한 동작은 [Orca 워크트리 문서](https://www.onorca.dev/docs/model/worktrees)와 [첫 세션 안내](https://www.onorca.dev/docs/first-session)를 참고할 수 있습니다.
