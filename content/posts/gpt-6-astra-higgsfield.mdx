[기존 『AI 게임 개발 with 코덱스』 서평](/blog/ai-game-development-with-codex-review)에서는 코드 외에도 Unity 사용법과 애셋·애니메이션 작업이 진입 장벽이었다고 기록했습니다. AI가 코드를 작성해줘도 캐릭터와 배경을 준비하고, 버튼을 눌렀을 때 게임이 제대로 끝나는지 확인하는 일은 남습니다. 반대로 영상 생성 도구에서 멋진 장면을 얻어도, 그 장면이 움직이는 게임이 되는 것은 아닙니다.

**GPT-6 Astra와 Higgsfield의 조합은 이 사이의 작업을 연결하려는 접근**입니다. Astra가 코드와 제작 순서를 맡고, Higgsfield가 시각 자산과 제작 도구를 제공합니다. 중요한 변화는 모델 하나가 모든 것을 직접 생성한다는 이야기가 아니라, 서로 다른 도구를 오가던 과정을 에이전트가 이어간다는 점입니다.

이 글은 **2026년 9월 13일 공식 자료와 공개 웹 화면을 확인한 분석**입니다. Hermes가 Supercomputer의 Games 진입 화면과 선택 항목을 확인했지만, 계정 연결·유료 생성·게임 배포는 실행하지 않았습니다. 아래 제작 프롬프트는 시작 방법을 설명하는 예시이지, 직접 완성한 결과물의 기록은 아닙니다.

## Higgsfield는 영상 모델 하나가 아닙니다

Higgsfield는 이미지와 영상 등 창작물을 만들고 편집하는 AI 제작 플랫폼입니다. 초보자라면 **여러 생성 모델과 편집 도구를 한곳에 모아놓은 온라인 작업실**이라고 생각하면 됩니다. 사용자가 장면을 설명하고 모델과 옵션을 고르면, 플랫폼이 결과물을 만들고 보관합니다.

자체 Soul 계열뿐 아니라 Kling, Veo, Seedream 등 여러 모델을 사용할 수 있습니다. 여기서 Higgsfield라는 서비스와 서비스 안에서 선택하는 생성 모델은 구분해야 합니다. 같은 플랫폼에서도 모델에 따라 영상 길이, 해상도, 입력 조건과 비용이 달라집니다. 지원 목록은 [공식 요금표](https://higgsfield.ai/pricing)에서 확인할 수 있습니다.

일반 생성 화면에서는 사람이 모델·프롬프트·옵션을 고르고 다음 작업으로 결과를 넘깁니다. **Supercomputer는 이 플랫폼 안에서 여러 단계를 실행하는 대화형 에이전트 작업 공간**입니다. 별도 슈퍼컴퓨터를 구매하거나 로컬 GPU를 구성하라는 뜻이 아닙니다.

[공식 Supercomputer 가이드](https://higgsfield.ai/blog/higgsfield-supercomputer-guide)는 요구사항을 단계로 나누고, 모델을 선택하고, 비용을 보여준 뒤 승인에 따라 실행한다고 설명합니다. 예를 들어 캐릭터 이미지를 만든 뒤 그 결과를 다음 영상 생성의 레퍼런스로 넘기는 식입니다. 다운로드와 재업로드를 사람이 반복하던 구간을 줄이는 것이 핵심입니다.

## Astra는 감독과 개발자, Higgsfield는 제작 도구

[Higgsfield의 Games 2.0 발표](https://higgsfield.ai/blog/higgsfield-mcp-gpt6-astra-games-2)는 역할을 명확히 나눕니다. Astra는 코딩·로직·추론·여러 단계의 조율을, Higgsfield는 창작 자산과 게임 생성·배포 흐름을 담당합니다.

<Image src="/gpt-6-astra-higgsfield/00.png" alt="Astra의 코드와 도구 호출, Higgsfield의 시각 자산 생성, 사람의 품질과 공개 검수를 구분한 개념도" caption="공식 문서 기반 편집 개념도입니다. 실제 제품 UI나 생성 결과가 아닙니다." />

이 조합이 잘 맞는 이유는 게임이나 영상 제작에 **서로 다른 종류의 문제**가 섞여 있기 때문입니다. 게임의 승리 조건과 충돌 처리는 코드 문제이고, 등장인물의 생김새와 배경의 분위기는 시각 자산 문제입니다. 어떤 것을 먼저 만들고 수정된 결과를 어디에 반영할지는 작업 조율 문제입니다.

[OpenAI의 Astra 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra)는 복잡한 추론·코딩·컴퓨터 사용을 주요 용도로 안내합니다. 기본 모달리티에서 출력은 텍스트이며 이미지 입력을 받습니다. 도구를 통한 이미지 생성 지원과 모델 자체가 영상 파일을 출력한다는 주장은 다른 이야기입니다. **이 워크플로에서 영상 제작 능력을 Astra 단독의 영상 생성 능력으로 해석하면 안 됩니다.**

다만 이 역할 분담만으로 결과의 완성도가 보장되지는 않습니다. 코드는 동작 테스트가 필요하고, 생성된 자산은 일관성과 권리를 확인해야 합니다. 공식 데모가 복잡한 작업을 보여준다는 것과 내 요구사항을 한 번에 만족한다는 것은 별개입니다.

## Plugin·MCP·Supercomputer는 서로 다른 입구입니다

### ChatGPT에서 시작하는 Plugin

Plugin은 ChatGPT 안에서 Higgsfield 도구를 쓰도록 추가하는 연결입니다. [Astra 소개 페이지](https://higgsfield.ai/gpt-astra)는 ChatGPT 데스크톱 앱 다운로드, Higgsfield Plugin 설치, 제작 시작의 순서를 안내합니다.

구체적인 연결 절차는 [공식 도움말](https://higgsfield.ai/creator-hub/help-center/integrations/how-do-i-connect-higgsfield-to-ai-agent) 기준으로 다음과 같습니다.

1. ChatGPT의 Plugins Directory 또는 Higgsfield MCP 페이지에서 Higgsfield Plugin 추가를 선택합니다.
2. Higgsfield를 추가하고 본인 Higgsfield 계정으로 로그인·인증합니다.
3. 새 대화에서 크레딧 잔액이나 최근 생성 목록을 요청해 실제 도구 호출이 일어나는지 확인합니다.
4. 생성 전에 모델·출력 조건·예상 크레딧을 확인하고 승인하도록 요청합니다.

**Higgsfield의 활성 유료 구독이 필요합니다.** ChatGPT 구독만으로 Higgsfield 생성 비용까지 해결되는 구조가 아닙니다. Astra 이용 가능 여부는 사용하는 ChatGPT 계정에서도 별도로 확인해야 합니다. OpenAI의 [출시 안내](https://openai.com/index/gpt-6-astra/)는 Plus·Pro·Business·Enterprise로의 제공과 기존 구독 사용량 내 이용을 안내하지만, 이를 모든 계정의 무제한 사용 보장으로 읽어서는 안 됩니다.

또 하나 주의할 점이 있습니다. 현재 연결 도움말은 **ChatGPT에서 오디오 생성과 Website Building 스킬을 지원하지 않는다**고 명시합니다. Games 2.0 발표의 연결 사례를 근거로 모든 클라이언트가 모든 Higgsfield 기능을 동일하게 지원한다고 쓰면 안 됩니다. 만들려는 작업이 실제 도구 목록에 노출되는지 먼저 확인하는 편이 좋습니다.

### 다른 에이전트에서 시작하는 MCP

MCP는 AI 에이전트가 외부 도구를 호출하도록 연결하는 공통 규약입니다. 비유하면 제작 도구를 꽂는 연결 규격이고, Plugin은 특정 앱에서 쉽게 추가하도록 만든 입구에 가깝습니다. MCP 자체가 생성 모델이나 무료 이용권은 아닙니다.

공식 도움말은 Claude의 Settings → Connectors → Add custom connector에서 다음 서버 URL을 추가하고 Higgsfield 계정으로 인증하도록 안내합니다.

```text
https://mcp.higgsfield.ai/mcp
```

다른 MCP 클라이언트도 지원 여부와 인증 방법을 확인해 연결할 수 있습니다. 다만 Higgsfield는 Claude Code·OpenClaw·Hermes 같은 환경에는 CLI 경로도 별도로 안내합니다. **모든 에이전트에 ChatGPT Plugin 설치 절차를 그대로 적용하지는 않습니다.** 이번 검증에서는 로컬 Hermes 설정을 바꾸거나 CLI를 설치하지 않았습니다.

레퍼런스 전달도 중요합니다. 공식 도움말은 채팅에 첨부한 파일을 Higgsfield 도구가 그대로 읽는 것으로 가정하지 말고, 별도의 Higgsfield 업로드 절차나 직접 이미지 URL 가져오기를 사용하도록 안내합니다. 업로드 후 파일의 역할을 ‘캐릭터’, ‘모션’, ‘스타일’처럼 지정해야 합니다. 고객 자료라면 이 단계가 외부 서비스로의 전송이라는 점부터 확인해야 합니다.

### Higgsfield 안에서 시작하는 Supercomputer

앱 간 연결 설정이 부담스럽다면 Higgsfield의 Supercomputer에서 시작할 수 있습니다. Games 2.0도 이 안에 있습니다. [공식 가이드](https://higgsfield.ai/blog/higgsfield-mcp-gpt6-astra-games-2)는 별도 ChatGPT 앱이나 Plugin 없이 이 경로에서 제작할 수 있다고 설명합니다.

처음에는 이쪽이 작업 흐름을 이해하기 쉽습니다. 반면 이미 코드 에이전트에서 프로젝트를 관리한다면, 기존 작업 맥락을 유지하면서 필요한 자산만 Higgsfield에 요청하는 방식이 더 잘 맞을 수 있습니다. 어떤 입구가 편한지와 어떤 모델·기능을 사용할 수 있는지는 따로 판단해야 합니다.

## Games 2.0에서는 무엇부터 정해야 할까

Hermes가 로그인하지 않은 공개 웹 화면에서 Supercomputer의 게임 메뉴를 열었을 때 `/supercomputer/gaming`으로 이동했고, 장르·스타일·설정·멀티플레이어 항목과 게임 둘러보기 영역이 표시됐습니다.

<Image src="/gpt-6-astra-higgsfield/01-games-public.png" alt="Higgsfield Supercomputer Games 공개 진입 화면의 장르 선택과 스타일·설정·멀티플레이어 항목" caption="2026년 9월 13일 공개 웹 화면 확인. 출처: higgsfield.ai/supercomputer/gaming. 계정 인증이나 생성 성공을 입증하는 화면은 아닙니다." />

공식 가이드는 Shooter·Platformer·Novella·Hypercasual·Racing·Horror 같은 게임 유형, Pixel Art·Minimalistic·ASCII·Voxel·Anime·3D 스타일, Medieval·Cyberpunk·Retro·Modern·Space·Fantasy 배경을 안내합니다. 이런 선택 항목으로 큰 방향을 정하고, 프롬프트에 실제 플레이 규칙을 추가하는 흐름입니다.

처음부터 ‘거대한 멀티플레이어 오픈월드’를 요청하기보다, 아래처럼 작은 완성 기준을 잡는 편을 권합니다. 다음은 **실행하지 않은 제작 요청 예시**입니다.

```text
게임 유형은 Platformer, 스타일은 Pixel Art, 배경은 Space.
멀티플레이어는 끄고, 한 개의 짧은 스테이지만 만든다.
좌우 이동과 점프, 수집물 3개, 출구, 실패 후 재시작이 필요하다.
기존 작품의 캐릭터나 로고는 사용하지 않는다.
먼저 구현 계획과 생성할 자산, 예상 크레딧을 보여준다.
승인 전에는 생성·추가 결제·배포·공개 게시를 하지 않는다.
```

생성 후에는 외형보다 **입력 → 상태 변화 → 성공·실패 → 재시작**이 이어지는지 먼저 봐야 합니다. 시작 버튼이 작동하는지, 충돌 판정이 맞는지, 다시 시작했을 때 이전 점수가 남지 않는지 확인하는 것입니다. 수정할 때도 ‘더 재미있게’보다 ‘점프 높이를 낮추고 시작 화면으로 돌아가는 버튼을 추가해 달라’처럼 바꿀 지점을 좁히는 편이 좋습니다.

멀티플레이어를 켠다면 별도 브라우저나 두 사용자 환경에서 참가·상태 동기화·연결 종료를 확인해야 합니다. 이번 조사에서는 이 테스트를 하지 않았으므로 동시 접속 품질이나 운영 규모를 평가하지 않습니다.

공식 문서에서 **Deploy는 링크로 플레이할 수 있게 하는 단계, Publish는 Games 마켓플레이스에 공개하는 단계**입니다. 둘은 같은 승인이 아닙니다. 링크 배포 역시 외부 접근이 생길 수 있으므로, 검수가 끝나기 전 자동으로 진행하지 않도록 나누는 것이 안전합니다.

## 3D와 영상은 ‘어떤 파일이 필요한가’부터 다릅니다

[Astra 활용 사례 페이지](https://higgsfield.ai/gpt-astra)는 로봇 3D 모델링과 리깅, 분해 가능한 기계, 인터랙티브 태양계, 모션 그래픽, 출시 영상 재현, 3D 격투 장면의 애니메이션 단편화 등을 보여줍니다. 리깅은 캐릭터나 물체를 움직이기 위한 뼈대와 제어 구조를 붙이는 작업입니다.

이 사례들은 제작 가능성을 보여주지만, 최종 결과가 내가 필요한 형식인지까지 설명해주지는 않습니다.

- **게임**이라면 조작 가능한 실행 결과와 규칙이 필요합니다. 예쁜 플레이 영상만으로는 충분하지 않습니다.
- **3D 자산**이라면 보기 좋은 렌더뿐 아니라 편집 가능한 메시, 재질, 리깅, 내보내기 형식을 확인해야 합니다. Unity·Unreal·Blender로 바로 넘길 수 있다고 이 글에서는 보장하지 않습니다.
- **영상**이라면 샷의 순서, 캐릭터 일관성, 길이·비율, 오디오, 편집 결과를 확인해야 합니다. ChatGPT 연결의 오디오 제한도 고려해야 합니다.

예를 들어 제품 소개 영상은 ‘완성 영상 하나’보다 `샷 구성 → 제품 레퍼런스 확인 → 대표 이미지 → 짧은 모션 테스트 → 필요한 샷만 추가 생성 → 편집·오디오 검수`로 나누는 편이 낫습니다. 얼굴이나 제품 형태가 첫 모션 테스트부터 무너지면, 긴 영상을 만들기 전에 수정할 수 있으니까요. 이는 공식 기능을 바탕으로 한 권장 흐름이며, 이번에 완주한 제작 실험은 아닙니다.

자동차 충돌 같은 데모도 시각적 시뮬레이션과 공학 검증은 구분해야 합니다. 그럴듯하게 부서지는 화면을 차량 안전성 계산의 근거로 사용할 수는 없습니다. CAD나 정밀 3D 작업이라면 치수·구조·내보내기 후 수정 가능성까지 확인해야 합니다.

## 가격은 구독료보다 ‘어디서 생성하나’가 중요합니다

2026년 9월 13일 [공식 Pricing](https://higgsfield.ai/pricing)의 개인 요금제와 월간·연간 토글을 확인한 값입니다. USD 기준이며 **VAT·현지 세금은 별도**, 연간 열은 월별 결제가 아니라 **연간 결제 조건의 월 환산 표시액**입니다.

| 개인 플랜 | 월간 결제 | 연간 결제 시 월 표시액 | 월 크레딧 |
| --- | --- | --- | --- |
| Starter | $19 | $19 | 270 |
| Plus | $59 | $47 | 1,200 |
| Ultra 기본 선택 | $129 | $99 | 3,000 |

Ultra는 더 큰 크레딧 선택지도 있어 위 값은 기본 선택 기준입니다. 가격표는 유료 개인 플랜의 Supercomputer 이용을 표시하지만, Starter의 모델·기능 범위는 제한적입니다. **Supercomputer 이용 표시를 Games 2.0의 모든 기능·모델이 해당 플랜에서 보장된다는 뜻으로 확대하면 안 됩니다.** 새 모델과 고급 기능은 순차 제공될 수 있다는 안내도 있습니다.

특히 눈에 띄는 조건은 이것입니다. **요금제의 무제한 모델과 무료 생성은 MCP/CLI·Canvas·Supercomputer에서 사용할 수 없습니다.** 연결된 에이전트의 생성은 기존 Higgsfield 크레딧을 표준 요율로 차감합니다. 웹 생성 화면의 Unlimited 배너만 보고 자동 제작 비용을 계산하면 틀릴 수 있습니다.

Supercomputer는 생성 단계뿐 아니라 **텍스트 요청에도 크레딧을 사용**하며, 프롬프트 복잡도와 선택 LLM에 따라 달라진다고 Pricing FAQ가 설명합니다. 생성 전 비용 표시와 승인이 있다고 해서 계획을 요청하는 모든 대화가 무료라는 뜻은 아닙니다.

Games 2.0 발표에는 게임당 확정 단가나 플랜별 최소 등급·게시 한도 수치가 명시돼 있지 않습니다. [기존 Games 가이드](https://higgsfield.ai/blog/higgsfield-ai-games)의 약 70크레딧부터라는 예시는 **Astra 기반 Games 2.0의 고정 견적이 아닙니다.** 실제로는 생성 단계와 수정 횟수에 따라 달라집니다. 게임 게시가 Apps·Websites와 월간 게시 한도를 공유한다는 기존 가이드의 조건도 있어, 결제 전 현재 계정의 한도를 확인해야 합니다.

별도 OpenAI API로 Astra를 직접 사용하는 경우는 또 다른 비용 체계입니다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra)의 Standard 텍스트 요금은 100만 토큰당 입력 $10·출력 $50이며, 긴 입력과 실행 모드 등에 추가 조건이 있습니다. 이는 Higgsfield의 게임 생성 요금도, Plugin 사용을 위해 반드시 별도로 내야 하는 고정 비용도 아닙니다.

**결국 비교할 값은 ‘한 번 생성 가격’보다 ‘검수에 통과한 결과물 하나의 비용’**입니다. 이미지 생성, 영상화, 실패한 시도, 수정, 에이전트 대화가 어디서 차감되는지 나눠 기록해야 합니다.

## 승인 프롬프트만으로 예산과 기밀이 보호되지는 않습니다

공식 연결 도움말은 세션별 기본 크레딧 상한이 없고, ‘X 크레딧 이상 사용하지 말라’는 요청이 **강제 한도가 아닌 프롬프트 수준의 지시**라고 설명합니다. 앞의 예시도 기술적으로 지출을 차단하는 장치가 아닙니다. 작은 작업부터 승인하고, 실제 사용량과 생성 ID를 확인하는 운영이 필요합니다.

결과가 늦게 보인다고 곧바로 같은 생성 요청을 반복하지 않는 것도 중요합니다. 도움말은 생성물이 보이지 않으면 사용량에서 실행 여부를 확인하고, 크레딧이 차감됐다면 생성 ID와 시간으로 지원팀에 문의하도록 안내합니다. 에이전트의 ‘완료했습니다’라는 문장보다 Assets의 실제 결과와 차감 기록이 근거입니다.

상업적 이용 역시 단순한 체크박스가 아닙니다. [이용약관](https://higgsfield.ai/terms-of-use-agreement)과 [소유권 도움말](https://higgsfield.ai/creator-hub/help-center/account-and-privacy/who-owns-my-generations-and-can-i-use-them-commercially)은 출력물의 상업적 이용을 제한하지 않는다고 설명합니다. 그런데 확인 당시 Pricing 비교표는 Free의 상업적 이용을 미포함으로 표시했습니다. **공식 표기 사이에 불일치가 있으므로 무료 플랜으로 고객에게 납품하려면 서면 확인을 받는 편이 안전합니다.**

상업적 이용 허용이 저작권 성립이나 독점성, 제3자 권리 비침해 보장까지 뜻하지도 않습니다. 얼굴·음성·브랜드·레퍼런스의 권리는 사용자가 확인해야 합니다.

기밀 자료는 더 보수적으로 다뤄야 합니다. [약관](https://higgsfield.ai/terms-of-use-agreement)과 [개인정보처리방침](https://higgsfield.ai/privacy-policy)은 일반 조건에서 입력·출력의 모델 학습·개선 이용을 설명하고, Enterprise Agreement 적용 고객에는 별도 학습 제외 조건을 둡니다. **작업을 비공개로 해두는 것과 학습에서 제외되는 것은 다릅니다.** 고객의 미공개 제품 이미지나 사내 자료를 넣기 전 계약과 데이터 처리 조건을 확인해야 합니다. 연결한 외부 AI 서비스의 정책도 함께 적용됩니다.
