### 목차

## 들어가며

**프로젝트와 작업 결과를 화면에서 보고 싶다면 데스크톱 앱**, 터미널에서 바로 시작하거나 반복 작업을 자동화하려면 CLI가 편합니다.

두 환경 모두 작업 폴더의 코드를 살펴보고 수정하거나 명령을 실행할 수 있습니다. 2026년 11월 5일 공식 문서와 Windows CLI `0.166.0`을 기준으로 설치부터 첫 요청과 결과 확인까지의 흐름을 비교했습니다.

## 앱과 CLI의 작업 방식

<Image src="/codex-app-vs-cli/00.png" alt="OpenAI 공식 소개 페이지의 ChatGPT 데스크톱 앱과 Codex 화면 예시" caption="OpenAI 공식 제품 소개에 나온 Codex 앱 화면 (learn.chatgpt.com/docs/app)" />

데스크톱에서는 **ChatGPT desktop app**을 열고 드롭다운에서 **Codex**를 선택해 코딩 작업을 시작합니다. [공식 앱 안내](https://developers.openai.com/codex/app)

| 비교 기준 | 데스크톱 앱의 Codex | Codex CLI |
| --- | --- | --- |
| 시작 위치 | 앱에서 프로젝트 폴더와 Codex 대화 선택 | 터미널에서 프로젝트 폴더로 이동해 `codex` 실행 |
| 작업 확인 | 프로젝트와 대화, 파일 미리보기 등을 앱 화면에서 확인 | 터미널 대화와 명령·변경 내용을 확인 |
| 익숙해질 부분 | 프로젝트 선택, 화면과 승인 항목 | 폴더 이동 명령, 터미널과 승인 항목 |
| 잘 맞는 상황 | 여러 작업을 화면에서 오가며 확인 | 기존 터미널 흐름과 스크립트에 연결 |

앱에서는 여러 프로젝트와 대화를 오가며 파일 미리보기를 확인하기 편합니다. 터미널에서 작업한다면 CLI를 기존 흐름에 붙이기 쉽고, 반복 실행이나 CI에는 `codex exec`를 쓸 수 있습니다. [공식 CLI 안내](https://developers.openai.com/codex/cli)

## 설치와 로그인

Windows에서는 ChatGPT 데스크톱 앱을 설치하고 로그인합니다. Windows 11을 권장하며 최신 업데이트를 적용한 Windows 10은 지원 범위가 더 좁습니다. 회사 PC에서 설치나 샌드박스 설정이 막히면 관리자 정책을 확인하세요. 앱은 기본적으로 PowerShell을 사용합니다. WSL2에서 작업할 때는 해당 환경의 인증과 세션을 확인하세요. [공식 Windows 앱 안내](https://developers.openai.com/codex/windows/windows-app)

CLI는 [공식 설치 안내](https://developers.openai.com/codex/cli)에서 Windows 탭을 선택해 현재 제공되는 설치 명령을 확인하는 것이 안전합니다. 설치 후 PowerShell을 새로 열어 다음을 입력해 설치 여부를 확인합니다.

```powershell
codex --version
codex --help
```

새 PowerShell에서도 명령을 찾을 수 없다면 설치가 끝났는지와 공식 안내의 PATH 설정을 확인합니다.

로컬 앱과 CLI는 ChatGPT 계정 또는 API 키로 로그인할 수 있습니다. ChatGPT 로그인은 구독과 워크스페이스의 이용 한도를 따릅니다. **API 키로 쓴 사용량은 OpenAI Platform에 별도로 청구되며 일부 기능이 제한됩니다.** 클라우드 Codex에는 ChatGPT 로그인이 필요합니다. [인증 문서](https://developers.openai.com/codex/auth)

조직 계정에서는 관리자 설정과 좌석 권한에 따라 사용 가능한 기능이 달라집니다. 플랜별 제공 범위와 한도는 로그인한 계정의 화면과 공식 안내에서 확인할 수 있습니다. [Codex 요금 안내](https://developers.openai.com/codex/pricing)

## 권한과 첫 작업 준비

Codex는 답변만 하는 채팅과 달리 파일을 읽고 수정하거나 명령을 실행할 수 있습니다. 처음에는 중요한 문서나 비밀키가 없는 **별도의 작은 작업 폴더**를 선택하고, 기존 작업은 백업하거나 Git으로 변경 전 상태를 남겨두세요. Git은 파일 변경 이력을 기록해 이전 상태와 비교할 수 있는 도구입니다.

[승인과 보안 문서](https://learn.chatgpt.com/docs/agent-approvals-security)에서 샌드박스는 실행 범위를 제한하고 승인 정책은 언제 사용자에게 묻는지 정하는 별도 설정입니다. 앱의 Windows 안내는 Codex에 메시지를 보내기 전 입력창 아래에서 `Ask for approval`을 선택해 샌드박스를 적용하도록 안내합니다. Full access는 프로젝트 폴더 밖까지 접근할 수 있어 실수로 데이터가 손실될 위험이 있습니다. 처음부터 전체 접근을 켜기보다 요청된 명령과 대상 경로를 읽고 필요한 경우에만 승인하세요.

CLI에서는 다음처럼 읽기 전용 샌드박스와 요청 시 승인으로 먼저 시작할 수 있습니다. PowerShell에서 **작업할 폴더로 이동한 뒤** 실행합니다.

```powershell
cd "C:\path\to\your-project"
codex --sandbox read-only --ask-for-approval on-request
```

경로를 자신의 작업 폴더로 바꾸세요. `on-request`에서는 샌드박스가 허용하는 명령이 추가 승인 없이 실행될 수 있습니다. 파일을 수정하는 단계로 넘어갈 때는 CLI의 `/permissions`에서 작업에 필요한 범위를 선택하세요.

## 첫 요청과 결과 확인

앱에서는 로그인 후 프로젝트나 폴더를 열고 Codex를 선택해 새 대화를 시작합니다. CLI에서는 위 명령으로 대화형 화면에 들어갑니다. 두 경우 모두 처음부터 파일을 바꾸게 하기보다 현재 상태를 설명받는 요청이 안전합니다.

```text
이 폴더의 파일을 먼저 살펴보고, 초보자에게 프로젝트 구조를 설명해줘.
파일을 수정하거나 명령을 실행하기 전에는 무엇을 할지 알려줘.
간단한 할 일 목록 페이지를 만들려면 어떤 파일을 바꿀지도 계획만 제안해줘.
```

답변에서 작업 폴더와 변경 예정 파일을 확인한 뒤 작은 변경부터 맡기세요. 삭제나 외부 전송을 승인할 때는 명령과 대상 경로를 확인합니다. 변경이 끝나면 파일 미리보기나 Git에서 수정 내용을 확인하고 페이지를 직접 열어 동작을 살펴봅니다.
