### 목차

## 들어가며

만들고 싶은 웹페이지는 있는데 검은 터미널부터 열어야 한다면 시작이 막막할 수 있습니다. Codex를 쓰는 방법은 하나가 아닙니다. **처음이라면 프로젝트와 작업 화면을 눈으로 살펴볼 수 있는 데스크톱 앱부터**, 이미 터미널이 편하거나 나중에 반복 작업을 자동화하고 싶다면 CLI부터 시작하는 편을 추천합니다.

둘 다 작업 폴더의 코드를 살펴보고 수정하거나 명령을 실행하도록 요청할 수 있습니다. 차이는 주로 작업을 지시하고 결과를 확인하는 자리입니다. 이 글은 2026년 11월 5일 공식 문서와 Windows의 CLI 버전 `0.166.0`을 확인해 비교했습니다. 앱과 CLI에서 같은 과제를 실행하거나 성능을 측정한 후기는 아닙니다.

## 앱과 CLI의 작업 방식

<Image src="/codex-app-vs-cli/00.png" alt="OpenAI 공식 소개 페이지의 ChatGPT 데스크톱 앱과 Codex 화면 예시" caption="OpenAI의 공식 제품 소개 화면 일부입니다. 이번에 예제 작업을 실행한 화면이 아닙니다. 출처: learn.chatgpt.com/docs/app" />

먼저 이름부터 구분해 볼게요. 현재 [공식 앱 안내](https://developers.openai.com/codex/app)는 제품을 **ChatGPT desktop app**이라고 부릅니다. 앱 안에서 ChatGPT와 Codex를 선택할 수 있고, 코딩 작업은 ChatGPT 드롭다운에서 Codex를 고르는 흐름입니다. 예전 자료에서 말하는 Codex 앱을 찾고 있다면 현재 안내의 이 경로를 확인하세요. ChatGPT의 일반 채팅이나 Work 모드와 Codex 선택은 같은 조작이 아닙니다.

| 비교 기준 | 데스크톱 앱의 Codex | Codex CLI |
| --- | --- | --- |
| 시작 위치 | 앱에서 프로젝트 폴더와 Codex 대화 선택 | 터미널에서 프로젝트 폴더로 이동해 `codex` 실행 |
| 작업 확인 | 프로젝트와 대화, 파일 미리보기 등을 앱 화면에서 확인 | 터미널 대화와 명령·변경 내용을 확인 |
| 익숙해질 부분 | 프로젝트 선택, 화면과 승인 항목 | 폴더 이동 명령, 터미널과 승인 항목 |
| 잘 맞는 상황 | 여러 작업을 화면에서 오가며 확인 | 기존 터미널 흐름과 스크립트에 연결 |

앱은 대화와 프로젝트를 한곳에 두기 좋아 처음 작업 위치를 파악하기 편합니다. 대신 화면의 여러 선택지를 익혀야 하고, 자동화 중심이라면 터미널로 돌아갈 일이 생길 수 있습니다. CLI는 텍스트 중심이라 처음에는 낯설지만, 명령을 다루는 사람에게는 기존 작업 흐름과 잘 이어집니다. [공식 CLI 안내](https://developers.openai.com/codex/cli)는 반복 가능한 스크립트나 CI에서 쓰는 `codex exec`도 소개합니다. 어느 쪽이 코드를 더 잘 만들거나 빠르다는 비교는 아닙니다.

## 설치와 로그인

Windows에서는 [공식 Windows 앱 안내](https://developers.openai.com/codex/windows/windows-app)의 다운로드 경로로 ChatGPT 데스크톱 앱을 설치하고 로그인합니다. 공식 문서는 Windows 11을 권장하고, 최신 업데이트된 Windows 10은 지원이 더 제한적이라고 설명합니다. 회사 컴퓨터라면 관리자 정책 때문에 설치나 샌드박스 설정이 막힐 수 있습니다. 앱은 기본적으로 Windows의 PowerShell 환경을 사용하며, Linux 도구가 필요한 경우 WSL2를 별도로 구성할 수 있습니다. 두 환경의 인증과 세션이 항상 공유된다고 가정하지 마세요.

CLI는 [공식 설치 안내](https://developers.openai.com/codex/cli)에서 Windows 탭을 선택해 현재 제공되는 설치 명령을 확인하는 것이 안전합니다. 설치 후 PowerShell을 새로 열어 다음을 입력해 설치 여부를 확인합니다.

```powershell
codex --version
codex --help
```

명령을 찾을 수 없다면 설치가 끝났는지, 새 터미널에서도 실행되는지와 공식 안내의 PATH 설정을 확인합니다. 여기서 버전이 표시되는 것은 설치 확인이지 첫 프로젝트 작업이 완료됐다는 뜻은 아닙니다.

[인증 문서](https://developers.openai.com/codex/auth)에 따르면 로컬 앱과 CLI는 ChatGPT 계정 로그인 또는 API 키 로그인을 지원합니다. ChatGPT 로그인은 해당 구독과 워크스페이스의 이용 조건·한도를 따르고, API 키는 별도의 OpenAI Platform 계정에서 사용량에 따라 과금됩니다. **ChatGPT 구독과 API 요금은 같은 잔액이 아닙니다.** 클라우드 Codex는 ChatGPT 로그인이 필요하고 API 키에서는 일부 기능이 제한됩니다.

이용 가능한 플랜과 한도는 바뀔 수 있고 조직 계정은 관리자 설정과 좌석 권한의 영향도 받습니다. [Codex 요금 안내](https://developers.openai.com/codex/pricing)와 로그인한 계정의 실제 화면을 함께 확인하세요. 무료 계정이나 특정 조직에서 이 글의 모든 기능을 사용할 수 있는지는 별도로 확인하지 않았습니다.

## 권한과 첫 작업 준비

Codex는 답변만 하는 채팅과 달리 파일을 읽고 수정하거나 명령을 실행할 수 있습니다. 처음에는 중요한 문서나 비밀키가 없는 **별도의 작은 작업 폴더**를 선택하고, 기존 작업은 백업하거나 Git으로 변경 전 상태를 남겨두세요. Git은 파일 변경 이력을 기록해 이전 상태와 비교할 수 있는 도구입니다.

[승인과 보안 문서](https://learn.chatgpt.com/docs/agent-approvals-security)에서 샌드박스는 실행 범위를 제한하고 승인 정책은 언제 사용자에게 묻는지 정하는 별도 설정입니다. 앱의 Windows 안내는 Codex에 메시지를 보내기 전 입력창 아래에서 `Ask for approval`을 선택해 샌드박스를 적용하도록 안내합니다. Full access는 프로젝트 폴더 밖까지 접근할 수 있어 실수로 데이터가 손실될 위험이 있습니다. 처음부터 전체 접근을 켜기보다 요청된 명령과 대상 경로를 읽고 필요한 경우에만 승인하세요.

CLI에서는 다음처럼 읽기 전용 샌드박스와 요청 시 승인으로 먼저 시작할 수 있습니다. PowerShell에서 **작업할 폴더로 이동한 뒤** 실행합니다.

```powershell
cd "C:\path\to\your-project"
codex --sandbox read-only --ask-for-approval on-request
```

경로는 자신의 폴더로 바꿉니다. 이 설정은 우선 코드를 읽고 계획을 확인할 때 적합합니다. `on-request`는 모든 동작을 매번 승인받는다는 뜻이 아닙니다. 샌드박스 안에서 허용된 명령은 추가 승인 없이 실행될 수 있으므로 실제 표시되는 권한도 확인해야 합니다. 파일 변경을 맡길 때는 CLI의 `/permissions`에서 제공되는 선택지를 확인하고 작업에 필요한 범위만 허용하세요. 환경과 조직 정책에 따라 선택 가능 항목이 다를 수 있습니다.

## 첫 요청과 결과 확인

앱에서는 로그인 후 프로젝트나 폴더를 열고 Codex를 선택해 새 대화를 시작합니다. CLI에서는 위 명령으로 대화형 화면에 들어갑니다. 두 경우 모두 처음부터 파일을 바꾸게 하기보다 현재 상태를 설명받는 요청이 안전합니다.

```text
이 폴더의 파일을 먼저 살펴보고, 초보자에게 프로젝트 구조를 설명해줘.
파일을 수정하거나 명령을 실행하기 전에는 무엇을 할지 알려줘.
간단한 할 일 목록 페이지를 만들려면 어떤 파일을 바꿀지도 계획만 제안해줘.
```

이 문장은 실행 결과가 아닌 요청 예시입니다. 답변에서 작업 폴더와 변경 예정 파일을 확인하고, 계획이 맞으면 필요한 권한을 검토해 작은 변경부터 요청하세요. 변경 후에는 앱의 파일 미리보기나 편집기, CLI가 보여주는 변경 내용과 Git 비교 결과를 확인하고, 실제로 페이지를 열어 원하는 대로 동작하는지도 살펴봅니다. 모르는 명령이나 삭제·외부 전송 요청은 그대로 승인하지 마세요.

앱에서 어디를 봐야 할지 모르겠다면 프로젝트와 대화가 보이는 화면부터 시작하고, 터미널 사용에 익숙해지면 같은 작업 폴더에서 CLI도 선택지로 검토할 수 있습니다. 반대로 CLI가 익숙한 사람은 굳이 앱으로 옮길 필요가 없습니다. 중요한 것은 화면의 종류보다 **어느 폴더에 어떤 권한을 주고 결과를 어떻게 확인할지**입니다.
