Python 코드를 조금 고쳤는데 아래 그래프는 예전 결과를 보여주고 있다면, 계산이 틀린 건지 셀을 다시 실행하지 않은 건지부터 확인하게 됩니다. 노트북을 쓰다 보면 코드뿐 아니라 **어떤 순서로 실행했는지**까지 신경 써야 하는 순간이 생기죠.

marimo는 이 문제를 줄이려는 Python 노트북입니다. 셀 사이의 관계를 파악해서 관련 결과를 다시 계산하고, 같은 파일을 코드 없는 대화형 앱으로도 보여줄 수 있습니다. **입력을 바꾸며 결과를 비교하거나 분석 도구를 공유하고 싶다면 marimo를, 기존 수업·연구·팀 환경이 Jupyter에 맞춰져 있다면 Jupyter를 먼저 고려하는 편이 좋습니다.**

AI도 선택 이유가 될 수 있지만, marimo만 AI를 쓸 수 있는 것은 아닙니다. 무엇이 다른지 이해하려면 먼저 노트북이라는 도구부터 구분할 필요가 있습니다.

## marimo의 역할과 활용처

여기서 노트북은 노트북 컴퓨터가 아니라 **코드, 설명, 실행 결과를 한 문서에 담는 작업 도구**입니다. 문서를 작은 실행 단위인 *셀*로 나누고, 데이터 읽기·계산·그래프 그리기를 나눠서 진행합니다. 결과 옆에 설명을 적을 수 있어서 분석 과정이나 실험을 전달하기에도 좋습니다.

marimo는 이런 노트북을 브라우저에서 편집하는 오픈소스 도구입니다. Python 환경에서 실행하며, pandas 같은 데이터 처리 라이브러리나 그래프 라이브러리를 함께 사용할 수 있습니다. 브라우저에 열린다고 반드시 클라우드 서비스인 것은 아닙니다. 내 컴퓨터에서 서버를 실행하고 브라우저를 편집 화면으로 쓰는 방식도 가능합니다.

<Image src="/marimo-vs-jupyter/01-editor.png" alt="설명 셀과 표본 수 입력, 결과 셀이 함께 있는 marimo 편집기" caption="Windows의 marimo 0.25.2 편집기. 개념 설명용으로 만든 작은 노트북입니다." />

활용 장면은 다음처럼 생각하면 쉽습니다.

- **데이터 탐색:** CSV를 읽어 표와 그래프를 만들고, 기간이나 분류 조건을 바꾸며 차이를 살펴봅니다.
- **실험과 시뮬레이션:** 표본 수나 매개변수를 바꾸면서 계산 결과를 비교합니다.
- **수업·기술 설명:** 코드와 해설, 조작 가능한 입력을 나란히 놓고 원리를 보여줍니다.
- **작은 분석 앱:** 작성자는 코드를 관리하고, 보는 사람은 입력을 선택하면서 결과를 확인하게 합니다.

실제 작업은 **설치 → 노트북 열기 → 셀 작성·실행 → 저장·공유** 순서입니다. [공식 설치 안내](https://docs.marimo.io/getting_started/installation/)에 따라 Python 환경에 marimo를 준비한 뒤, 터미널에서 `marimo edit notebook.py`로 파일을 열면 브라우저 편집기에서 작업합니다. 같은 파일을 앱으로 보여주는 명령은 `marimo run notebook.py`입니다. 이 글은 설치 튜토리얼보다는 두 방식의 용도와 도구 선택에 초점을 맞췄습니다.

완성된 업무용 웹 서비스를 자동으로 만들어주는 도구와는 다릅니다. 복잡한 권한 관리, 결제, 여러 사용자의 데이터를 저장하는 서비스가 목적이라면 별도의 설계와 배포 구성이 필요합니다. 또 AI가 코드를 도와주더라도 파일 경로, 데이터의 의미, 오류 메시지를 읽을 정도의 Python 이해는 여전히 유용합니다.

## 반응형 실행과 셀의 관계

marimo의 가장 중요한 특징은 **반응형 실행**입니다. 여기서 반응형은 휴대폰 화면에 맞춰 레이아웃이 바뀐다는 뜻이 아닙니다. 입력이나 앞선 계산이 달라졌을 때, 그 값을 사용하는 셀을 다시 실행한다는 뜻입니다.

위 화면은 한 셀에서 표본 수를 선택하고, 다른 셀에서 그 값을 표시하는 작은 예제입니다. 슬라이더를 30에서 40으로 바꾸자 결과 셀도 별도 실행 없이 40개로 갱신됐습니다. 분석이 더 복잡해지면 같은 입력을 쓰는 계산과 그래프도 이어져 있겠죠. marimo는 코드에서 어떤 변수를 만들고 읽는지 분석해 이 관계를 추적합니다.

중요한 점은 **화면에서 아래에 있는 셀을 무조건 모두 실행하는 방식이 아니라는 것**입니다. 바뀐 값에 의존하는 셀을 관계에 맞는 순서로 실행합니다. 코드를 수정한 셀을 실행하면 관련 셀이 따라 실행되고, 슬라이더 같은 UI 입력도 연결된 셀의 갱신을 일으킵니다.

Jupyter Notebook의 일반적인 실행 방식에서는 사용자가 실행한 셀의 코드가 *커널*, 즉 코드를 실행하고 변수 값을 기억하는 프로세스에 전달됩니다. 앞 셀을 고쳐 실행하더라도 그 값을 쓰는 다른 셀까지 기본적으로 모두 다시 실행되지는 않습니다. 셀을 지운 뒤에도 커널에 변수가 남아 있을 수 있어, 문서에 보이는 코드와 현재 메모리 상태를 구분해야 합니다.

그렇다고 Jupyter로 재현 가능한 분석을 할 수 없다는 뜻은 아닙니다. **커널을 재시작하고 처음부터 전체 실행하는 습관**, 패키지 버전과 입력 데이터 관리로 일관성을 확인할 수 있습니다. marimo는 그중 셀 실행 순서와 오래된 결과를 관리하는 부담을 줄이는 쪽에 가깝습니다. 외부 데이터가 달라지거나 난수를 고정하지 않았다면 marimo에서도 결과가 달라질 수 있습니다.

## 파일 관리와 앱 형태의 공유

marimo 노트북은 `.py` 파일로 저장합니다. 셀을 표현하는 marimo의 구조가 들어 있는 Python 코드이므로, 일반 텍스트 편집기로 읽거나 Git에서 변경한 코드를 비교하기 좋습니다. 저장한 노트북을 Python 스크립트로 실행하는 경로도 제공합니다.

Jupyter의 `.ipynb`는 코드뿐 아니라 출력과 메타데이터를 담을 수 있는 JSON 문서입니다. 실행 당시의 표나 그래프를 문서 안에 보존하는 데 장점이 있습니다. 반면 일반 텍스트 diff에서는 출력과 메타데이터 변화가 코드 수정에 섞일 수 있습니다. **Jupyter는 Git으로 관리할 수 없다는 말은 틀립니다.** 출력 정리나 노트북 전용 diff 도구 등 팀의 관리 방식을 함께 비교해야 합니다.

공유 방식에서도 차이가 있습니다. marimo는 같은 노트북을 편집기로 열 때와 앱으로 실행할 때를 구분합니다. 앱에서는 코드를 숨기고 결과와 입력 UI를 중심으로 보여줍니다. 분석용 Python 파일과 이를 조작하는 화면을 따로 구현하지 않아도 된다는 점이 편리합니다.

<Image src="/marimo-vs-jupyter/02-app.png" alt="코드를 숨기고 설명과 표본 수 슬라이더, 결과만 보여주는 marimo 화면" caption="같은 노트북의 코드 숨김 화면. 입력과 결과를 중심으로 보여주는 용도를 확인할 수 있습니다." />

다만 **코드를 숨긴 것과 인터넷에 안전하게 배포한 것은 별개**입니다. 다른 사람이 접속하려면 실행 환경과 접근 방법을 마련해야 합니다. 정적 HTML로 결과를 전달하는 것과 Python 계산이 계속 동작하는 앱을 운영하는 것도 다릅니다. 공식 [앱·노트북 구분 안내](https://docs.marimo.io/faq/#whats-the-difference-between-a-marimo-notebook-and-a-marimo-app)를 기준으로 필요한 공유 수준부터 정하는 편이 좋습니다.

Windows 11, Python 3.11.16, marimo 0.25.2 환경에서는 앞선 로컬 확인에서 슬라이더 변경에 따른 연결 결과 갱신, 별도 앱 실행에서 코드가 숨겨지는 동작, 저장한 파일의 스크립트 실행을 확인했습니다. 이 글의 화면은 같은 버전에서 개념 설명용으로 새로 준비했습니다. 장기 운영이나 배포 성능을 비교한 결과는 아닙니다.

## marimo의 AI 연동 방식

marimo의 AI 연동은 하나의 기능이 아닙니다. **편집기 안에서 도움받는 기능, 타이핑 중 코드 보완, 외부 에이전트와의 협업**을 나누어 보면 이해하기 쉽습니다. 아래 기능과 지원 범위는 2026년 10월 23일 공식 문서를 기준으로 정리했습니다. 이번에는 키가 없는 설정 화면까지 확인했으며, 유료 모델 호출이나 AI 답변 품질 테스트는 하지 않았습니다.

### 편집기 채팅과 셀 생성

편집기의 채팅 패널에서 노트북에 관해 질문하거나, 새 셀을 생성하고 기존 코드를 수정하도록 요청할 수 있습니다. 예를 들면 데이터가 들어 있는 노트북에서 “이 표를 월별로 묶어 비교하는 그래프를 만들어줘”라고 요청하는 식입니다. 이는 활용 예시이지, 실제 실행한 답변은 아닙니다.

공식 안내에서는 노트북 코드뿐 아니라 `@df`처럼 변수 이름을 지정해 데이터프레임의 열 정보 등 문맥을 추가하는 방법도 설명합니다. 별도 채팅창에 코드를 복사하는 방식보다 현재 분석 대상과 연결하기 쉽다는 점이 특징입니다.

채팅 모드에 따라 권한도 달라집니다. `Manual`은 대화와 직접 넣은 문맥을 사용하고, `Ask`는 노트북을 살펴보는 읽기 도구를 사용합니다. `Agent`는 셀 추가·수정·삭제와 오래된 셀 실행까지 다룹니다. `Code mode`는 커널 접근을 제공하는 별도 방식입니다. 단순히 답변을 받는 기능과 코드를 실행하는 기능을 같은 권한으로 생각하면 안 됩니다.

### 코드 보완과 모델 설정

코드 보완은 타이핑하는 도중 다음 코드를 제안하는 기능입니다. 채팅으로 설명을 듣거나 셀 전체를 고치는 기능과는 역할이 다릅니다. marimo는 채팅용 모델, 편집용 모델, 보완용 모델을 구분해서 설정할 수 있습니다.

<Image src="/marimo-vs-jupyter/03-ai-settings.png" alt="marimo AI 설정의 코드 보완 제공자와 Chat Model, Edit Model 항목" caption="marimo 0.25.2의 AI 설정. 모델 이름이 표시되어 있어도 키 설정이나 실제 호출 성공을 뜻하지는 않습니다." />

확인한 화면에서는 오른쪽 위 설정 버튼에서 `User settings`를 열고 `AI`로 들어가면 관련 항목을 볼 수 있었습니다. `AI Providers`는 연결할 제공자, `AI Models`는 모델을 설정하는 탭입니다. 처음에는 **어디에 연결할지와 어떤 작업에 쓸지를 먼저 정하고**, 공식 [제공자 설정 안내](https://docs.marimo.io/guides/configuration/llm_providers/)에 맞춰 필요한 패키지와 인증 조건을 확인하면 됩니다.

공식 문서에는 OpenAI, Anthropic, Google AI, AWS Bedrock 등의 연결과 Ollama·LM Studio를 통한 로컬 모델 사용이 안내되어 있습니다. GitHub Copilot과 OpenAI 호환 제공자를 쓰는 경로도 있습니다. 제공자가 지원된다는 것과 그 제공자의 모든 모델·도구 기능을 내 계정에서 쓸 수 있다는 것은 다릅니다. 모델 접근 권한과 기능 지원을 함께 확인해야 합니다.

### 외부 에이전트와 MCP

이미 Codex나 Claude Code 같은 코딩 에이전트를 쓰고 있다면 별도 연결도 생각해볼 수 있습니다. 현재 공식 문서는 실행 중인 노트북과 협업하는 경로로 `marimo pair`를 안내합니다. 에이전트가 변수와 셀을 살펴보고, 코드를 시험하거나 셀을 실행·수정하는 방식입니다. 단순히 `.py` 파일을 읽는 것보다 실행 중인 상태를 확인할 수 있다는 차이가 있습니다.

다만 연결 방식별 요구사항이 있습니다. 예를 들어 노트북 오류를 에이전트 대화로 보내는 메시지 기능은 Codex의 공유 데몬·큐 지원, Claude Code의 macOS/Linux 네이티브 inbox 등 별도 조건이 안내되어 있습니다. **Windows에서 marimo가 실행된다고 모든 에이전트 연결 기능까지 동일하게 지원된다고 보면 안 됩니다.** 실제 연결 전 [pair 안내](https://docs.marimo.io/guides/generate_with_ai/marimo_pair/)의 해당 에이전트 조건을 확인해야 합니다.

MCP는 AI 애플리케이션과 외부 도구를 연결하는 규약입니다. marimo에는 방향이 다른 두 기능이 있습니다.

- **MCP 서버:** 외부 AI 도구가 marimo 노트북의 상태·변수·오류 등을 조회할 수 있게 합니다. 현재 안내의 읽기 중심 인터페이스를 `pair`의 편집·실행 기능과 혼동하지 않는 것이 좋습니다.
- **MCP 클라이언트:** marimo 채팅에서 지원되는 외부 서버의 문서·도구를 이용합니다. 공식 문서는 `marimo`와 `context7` 프리셋을 안내하며, 임의의 사용자 지정 서버 설정은 아직 지원하지 않는다고 명시합니다.

[MCP 기능은 실험적 기능](https://docs.marimo.io/guides/editor_features/mcp/)으로 표시되어 있습니다. 연결 예제에 인증을 끄는 옵션이 있더라도 그대로 외부에 공개하지 말고, 노트북 접근 권한과 인증을 유지해야 합니다.

### AI 비용과 데이터 전송

marimo를 로컬에서 쓰는 비용과 연결한 AI의 비용은 별개입니다. API 키 방식이면 해당 제공자의 요금과 사용 한도를 확인해야 합니다. ChatGPT나 Claude의 채팅 구독을 가지고 있다는 사실만으로 marimo의 API 호출까지 포함된다고 가정하면 안 됩니다. 기존 에이전트를 `pair`로 사용하는 경우에는 그 에이전트의 인증 방식과 계약·한도가 적용됩니다.

로컬 모델도 선택지지만, 모델을 내려받고 실행할 메모리와 처리 성능이 필요합니다. 로컬이라는 이름만 믿기보다 실제 연결 주소와 모델 실행 위치를 확인해야 합니다.

**외부 AI에 연결하면 코드와 질문, 선택한 변수 정보나 도구로 조회한 데이터가 전송 대상이 될 수 있습니다.** 노트북은 내 컴퓨터에 있어도 AI 처리는 외부에서 일어날 수 있다는 뜻입니다. 회사 데이터·개인정보·API 키는 문맥에 넣기 전에 검토하고, 모델이 만든 코드는 실행 전에 읽어야 합니다. 자동으로 다시 실행되는 셀에 유료 API 호출이나 파일 저장이 들어 있다면 반복 비용과 부작용도 확인해야 합니다.

## Jupyter Notebook과의 선택 기준

비교할 대상은 기본적인 Python 노트북 작업입니다. Jupyter Notebook은 문서 편집 앱이고, JupyterLab은 파일·터미널·노트북 등을 함께 다루는 작업 환경입니다. Jupyter 생태계의 확장 기능을 Notebook 기본 기능과 섞어 비교하지 않는 것이 중요합니다.

| 비교 항목 | marimo | Jupyter Notebook·생태계 |
| --- | --- | --- |
| 셀 실행 | 변수 의존성에 따라 관련 셀을 자동 실행하거나 오래된 상태로 표시 | 사용자가 선택한 셀·전체 실행을 중심으로 제어 |
| 저장 파일 | 셀 구조를 포함한 `.py`, 코드 diff를 읽기 편함 | `.ipynb`, 코드·출력·메타데이터를 함께 담기 좋음 |
| 대화형 입력 | UI 입력과 셀 의존성을 기본 실행 모델에 연결 | ipywidgets의 함수 연결·이벤트 처리 등으로 구성 |
| 앱 형태 | 같은 노트북을 코드 숨김 앱으로 실행하는 경로 제공 | 목적에 맞는 배포·대시보드 도구를 별도로 검토 |
| AI | 편집기 보조 기능과 외부 에이전트 연결 제공 | JupyterLab의 Jupyter AI 같은 확장 선택지 존재 |
| 기존 작업과의 호환 | marimo의 변수 정의·의존성 규칙에 맞게 점검 필요 | 기존 `.ipynb` 자료·커널·확장 환경을 유지하기 유리 |

Jupyter도 슬라이더를 만들 수 있습니다. 공식 [ipywidgets의 `interact` 안내](https://ipywidgets.readthedocs.io/en/stable/examples/Using%20Interact.html)는 입력을 움직이면 연결된 함수를 호출하는 예제를 제공합니다. 차이는 대화형 UI의 유무가 아니라, **그 입력과 다른 셀의 관계를 기본적으로 어떻게 관리하느냐**에 있습니다.

AI 역시 marimo만의 독점 기능이 아닙니다. 현재 [Jupyter AI 공식 안내](https://jupyter-ai.readthedocs.io/en/stable/)는 JupyterLab에서 AI 에이전트와 대화하고, 노트북 편집·실행을 함께하는 확장을 설명합니다. 따라서 “AI를 쓰려면 Jupyter를 버려야 한다”는 결론은 맞지 않습니다. 이미 사용하는 환경의 확장 지원과 조직 정책부터 확인할 만합니다.

marimo를 새로 써볼 이유가 분명한 경우는 **입력 조건을 자주 바꾸며 여러 결과를 같이 갱신하는 분석**, 코드 변경을 중심으로 관리하고 싶은 노트북, 다른 사람에게 조작 가능한 분석 화면을 보여주는 작업입니다.

반대로 수업 자료와 제출 형식이 `.ipynb`이거나, 팀의 JupyterHub·커널·확장 환경이 갖춰져 있다면 옮기는 비용이 더 클 수 있습니다. R·Julia 등 다른 언어 커널을 쓰는 작업도 Jupyter 생태계를 먼저 검토할 이유가 됩니다. GPU 실험에서 중요한 것은 노트북 이름보다 GPU를 제공하는 실행 환경, 필요한 라이브러리, 계산을 언제 다시 돌릴지에 대한 제어입니다. marimo 자체가 무료 GPU를 제공하는 도구는 아닙니다.

## 전환 전에 살펴볼 제약

marimo의 자동 실행에는 코드 작성 규칙이 따릅니다. **여러 셀에서 같은 전역 변수 이름을 중복 정의할 수 없고**, 셀 간 의존성이 순환하지 않도록 구성해야 합니다. Jupyter에서 같은 `df`를 여러 셀에 걸쳐 계속 덮어쓰던 코드는 단계별 이름을 나누거나 함수로 묶는 식으로 정리해야 할 수 있습니다.

또 모든 상태 변화를 자동 추적하지는 않습니다. 공식 [반응형 실행 문서](https://docs.marimo.io/guides/reactivity/)는 리스트에 값을 추가하거나 객체 속성을 바꾸는 식의 변경이 다른 셀의 재실행을 자동으로 일으키지 않는다고 설명합니다. 변수를 정의한 셀에서 변경을 마치거나 새 변수로 결과를 전달하는 식으로 흐름을 분명하게 만드는 편이 좋습니다.

오래 걸리는 모델 학습이나 비용이 드는 API 요청도 주의할 부분입니다. marimo에는 자동 실행 대신 셀을 오래된 상태로 표시하는 *lazy* 설정, 셀 비활성화 등 실행을 통제하는 방법이 있습니다. 처음부터 전체 학습 노트북을 옮기기보다는 가벼운 분석 하나로 입력과 계산의 관계를 확인하는 편을 권합니다.

저라면 **기존 Jupyter 작업은 그대로 두고, 조건을 바꿔가며 설명해야 하는 작은 분석부터 marimo로 만들어보겠습니다.** 실행 순서를 기억하는 부담과 화면 공유 작업이 실제로 줄어드는지 확인하면 됩니다. AI 기능의 개수보다 지금 반복하는 작업을 얼마나 단순하게 만드는지가 더 좋은 선택 기준이라고 생각합니다.
