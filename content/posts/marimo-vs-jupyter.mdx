### 목차

## 들어가며

Python 코드를 조금 고쳤는데 아래 그래프는 예전 결과를 보여주고 있다면, 계산이 틀린 건지 셀을 다시 실행하지 않은 건지부터 확인하게 됩니다. 노트북을 쓰다 보면 코드뿐 아니라 **어떤 순서로 실행했는지**까지 신경 써야 하는 순간이 생기죠.

marimo는 이 문제를 줄이려는 Python 노트북입니다. 셀 사이의 관계를 파악해서 관련 결과를 다시 계산하고, 같은 파일을 코드 없는 대화형 앱으로도 보여줄 수 있습니다. **입력을 바꾸며 결과를 비교하거나 분석 도구를 공유하고 싶다면 marimo를, 기존 수업·연구·팀 환경이 Jupyter에 맞춰져 있다면 Jupyter를 먼저 고려하는 편이 좋습니다.**

## marimo의 역할과 활용처

Python 노트북은 **코드, 설명, 실행 결과를 한 문서에 담습니다.** 데이터 읽기·계산·그래프 그리기를 작은 실행 단위인 *셀*로 나누고, 결과 옆에 분석 과정을 설명할 수 있습니다.

marimo는 브라우저에서 편집하는 오픈소스 Python 노트북입니다. 내 컴퓨터에서 서버를 띄우고 pandas 같은 데이터 처리·시각화 라이브러리를 함께 쓸 수 있습니다.

<Image src="/marimo-vs-jupyter/01-editor.png" alt="설명 셀과 표본 수 입력, 결과 셀이 함께 있는 marimo 편집기" caption="marimo 0.25.2 편집기의 표본 수 슬라이더 예제." />

활용 장면은 다음처럼 생각하면 쉽습니다.

- **데이터 탐색:** CSV를 읽어 표와 그래프를 만들고, 기간이나 분류 조건을 바꾸며 차이를 살펴봅니다.
- **실험과 시뮬레이션:** 표본 수나 매개변수를 바꾸면서 계산 결과를 비교합니다.
- **수업·기술 설명:** 코드와 해설, 조작 가능한 입력을 나란히 놓고 원리를 보여줍니다.
- **작은 분석 앱:** 작성자는 코드를 관리하고, 보는 사람은 입력을 선택하면서 결과를 확인하게 합니다.

[공식 설치 안내](https://docs.marimo.io/getting_started/installation/)에 따라 Python 환경에 marimo를 설치하세요. `marimo edit notebook.py`로 브라우저에서 편집하고, `marimo run notebook.py`로 같은 파일을 앱으로 실행할 수 있습니다.

## 반응형 실행과 셀의 관계

marimo의 **반응형 실행**은 입력이나 계산이 바뀌면 그 값에 의존하는 셀을 다시 실행하는 기능입니다.

위 화면은 한 셀에서 표본 수를 선택하고, 다른 셀에서 그 값을 표시하는 작은 예제입니다. 슬라이더를 30에서 40으로 바꾸자 결과 셀도 별도 실행 없이 40개로 갱신됐습니다. 분석이 더 복잡해지면 같은 입력을 쓰는 계산과 그래프도 이어져 있겠죠. marimo는 코드에서 어떤 변수를 만들고 읽는지 분석해 이 관계를 추적합니다.

셀을 실행하는 순서는 변수의 의존 관계를 따릅니다. 코드나 슬라이더 입력이 달라지면 연결된 셀이 그 순서에 따라 갱신됩니다.

Jupyter Notebook의 일반적인 실행 방식에서는 사용자가 실행한 셀의 코드가 *커널*, 즉 코드를 실행하고 변수 값을 기억하는 프로세스에 전달됩니다. 앞 셀을 고쳐 실행하더라도 그 값을 쓰는 다른 셀까지 기본적으로 모두 다시 실행되지는 않습니다. 셀을 지운 뒤에도 커널에 변수가 남아 있을 수 있어, 문서에 보이는 코드와 현재 메모리 상태를 구분해야 합니다.

Jupyter에서 재현성을 확인할 때는 **커널을 재시작해 전체 셀을 실행**하고 패키지 버전과 입력 데이터를 기록하세요. marimo도 외부 데이터나 난수 시드가 바뀌면 결과가 달라질 수 있습니다.

## 파일 관리와 앱 형태의 공유

marimo 노트북은 `.py` 파일로 저장합니다. 셀을 표현하는 marimo의 구조가 들어 있는 Python 코드이므로, 일반 텍스트 편집기로 읽거나 Git에서 변경한 코드를 비교하기 좋습니다. 저장한 노트북을 Python 스크립트로 실행하는 경로도 제공합니다.

Jupyter의 `.ipynb`는 코드와 출력, 메타데이터를 담는 JSON 문서라 실행 당시의 표나 그래프를 보존하기 좋습니다. Git에서 코드만 비교하고 싶다면 출력을 정리하거나 노트북 전용 diff 도구를 사용할 수 있습니다.

공유 방식에서도 차이가 있습니다. marimo는 같은 노트북을 편집기로 열 때와 앱으로 실행할 때를 구분합니다. 앱에서는 코드를 숨기고 결과와 입력 UI를 중심으로 보여줍니다. 분석용 Python 파일과 이를 조작하는 화면을 따로 구현하지 않아도 된다는 점이 편리합니다.

<Image src="/marimo-vs-jupyter/02-app.png" alt="코드를 숨기고 설명과 표본 수 슬라이더, 결과만 보여주는 marimo 화면" caption="같은 노트북의 코드 숨김 화면. 입력과 결과를 중심으로 보여주는 용도를 확인할 수 있습니다." />

결과만 전달할 때는 정적 HTML, 방문자가 입력을 바꾸며 Python 계산을 실행해야 할 때는 앱을 고려하세요. 앱을 외부에 열려면 실행 환경과 접근 권한을 마련해야 합니다. 두 방식의 차이는 [marimo 앱·노트북 안내](https://docs.marimo.io/faq/#whats-the-difference-between-a-marimo-notebook-and-a-marimo-app)에서 확인할 수 있습니다.

Windows 11, Python 3.11.16, marimo 0.25.2에서 슬라이더로 결과를 갱신하고, 코드를 숨긴 앱을 열고, 저장한 파일을 스크립트로 실행하는 것까지 확인했습니다.

## marimo의 AI 연동 방식

marimo에서는 **편집기 채팅, 타이핑 중 코드 보완, 외부 에이전트 연결**을 각각 설정할 수 있습니다. 아래 지원 범위는 2026년 10월 23일 기준 공식 문서에 따릅니다.

### 편집기 채팅과 셀 생성

편집기 채팅에서는 노트북에 관해 질문하거나 셀을 추가·수정하도록 요청할 수 있습니다. 예를 들어 `이 표를 월별로 묶어 비교하는 그래프를 만들어줘`처럼 입력합니다.

공식 안내에서는 노트북 코드뿐 아니라 `@df`처럼 변수 이름을 지정해 데이터프레임의 열 정보 등 문맥을 추가하는 방법도 설명합니다. 별도 채팅창에 코드를 복사하는 방식보다 현재 분석 대상과 연결하기 쉽다는 점이 특징입니다.

채팅 모드에 따라 권한이 달라집니다. `Manual`은 대화와 직접 넣은 문맥을 사용하고, `Ask`는 노트북을 읽을 수 있습니다. **`Agent`는 셀 추가·수정·삭제와 갱신이 필요한 셀 실행까지 다룹니다.** `Code mode`는 커널 접근을 제공하는 별도 방식입니다.

### 코드 보완과 모델 설정

코드 보완은 타이핑하는 도중 다음 코드를 제안하는 기능입니다. 채팅으로 설명을 듣거나 셀 전체를 고치는 기능과는 역할이 다릅니다. marimo는 채팅용 모델, 편집용 모델, 보완용 모델을 구분해서 설정할 수 있습니다.

<Image src="/marimo-vs-jupyter/03-ai-settings.png" alt="marimo AI 설정의 코드 보완 제공자와 Chat Model, Edit Model 항목" caption="marimo 0.25.2의 채팅·편집 모델과 코드 보완 제공자 설정." />

확인한 화면에서는 오른쪽 위 설정 버튼에서 `User settings`를 열고 `AI`로 들어가면 관련 항목을 볼 수 있었습니다. `AI Providers`는 연결할 제공자, `AI Models`는 모델을 설정하는 탭입니다. 처음에는 **어디에 연결할지와 어떤 작업에 쓸지를 먼저 정하고**, 공식 [제공자 설정 안내](https://docs.marimo.io/guides/configuration/llm_providers/)에 맞춰 필요한 패키지와 인증 조건을 확인하면 됩니다.

공식 문서는 OpenAI, Anthropic, Google AI, AWS Bedrock, GitHub Copilot과 OpenAI 호환 제공자 연결을 안내합니다. Ollama와 LM Studio로 로컬 모델도 쓸 수 있습니다. 제공자를 고른 뒤에는 계정에서 쓸 수 있는 모델과 도구를 확인하세요.

### 외부 에이전트와 MCP

이미 Codex나 Claude Code 같은 코딩 에이전트를 쓰고 있다면 별도 연결도 생각해볼 수 있습니다. 현재 공식 문서는 실행 중인 노트북과 협업하는 경로로 `marimo pair`를 안내합니다. 에이전트가 변수와 셀을 살펴보고, 코드를 시험하거나 셀을 실행·수정하는 방식입니다. 단순히 `.py` 파일을 읽는 것보다 실행 중인 상태를 확인할 수 있다는 차이가 있습니다.

노트북 오류를 에이전트 대화에 보내려면 에이전트별 요구사항을 충족해야 합니다. 예를 들어 Codex는 공유 데몬·큐 지원, Claude Code는 macOS/Linux 네이티브 inbox를 확인해야 합니다. 연결 전 [pair 안내](https://docs.marimo.io/guides/generate_with_ai/marimo_pair/)에서 운영체제와 에이전트 조건을 확인하세요.

MCP는 AI 애플리케이션과 외부 도구를 연결하는 규약입니다. marimo에는 방향이 다른 두 기능이 있습니다.

- **MCP 서버:** 외부 AI 도구가 marimo 노트북의 상태·변수·오류를 조회하는 읽기 중심 인터페이스입니다. 셀 편집과 실행에는 `pair`를 사용할 수 있습니다.
- **MCP 클라이언트:** marimo 채팅에서 지원되는 외부 서버의 문서·도구를 이용합니다. 공식 문서는 `marimo`와 `context7` 프리셋을 안내하며, 임의의 사용자 지정 서버 설정은 아직 지원하지 않는다고 명시합니다.

[MCP 기능은 실험적 기능](https://docs.marimo.io/guides/editor_features/mcp/)으로 표시되어 있습니다. 연결 예제에 인증을 끄는 옵션이 있더라도 그대로 외부에 공개하지 말고, 노트북 접근 권한과 인증을 유지해야 합니다.

### AI 비용과 데이터 전송

API 키로 연결하면 AI 제공자의 API 요금과 한도가 적용됩니다. 기존 에이전트를 `pair`로 연결하면 그 에이전트의 인증 방식과 계약·한도가 적용됩니다.

로컬 모델을 선택할 때는 모델에 필요한 메모리와 처리 성능, 연결 주소와 실제 실행 위치를 확인하세요.

**외부 AI에 연결하면 코드와 질문, 선택한 변수 정보, 도구가 조회한 데이터가 제공자에게 전송될 수 있습니다.** 회사 데이터·개인정보·API 키는 채팅에 넣기 전에 검토하고, 생성 코드는 실행 전에 읽으세요. 자동으로 다시 실행되는 셀에 유료 API 호출이나 파일 저장이 있다면 호출 비용과 파일 변경이 반복될 수 있습니다.

## Jupyter Notebook과의 선택 기준

Jupyter Notebook은 노트북 편집 앱이고, JupyterLab은 파일·터미널·노트북을 함께 다루는 작업 환경입니다.

| 비교 항목 | marimo | Jupyter Notebook·생태계 |
| --- | --- | --- |
| 셀 실행 | 변수 의존성에 따라 관련 셀을 자동 실행하거나 오래된 상태로 표시 | 사용자가 선택한 셀·전체 실행을 중심으로 제어 |
| 저장 파일 | 셀 구조를 포함한 `.py`, 코드 diff를 읽기 편함 | `.ipynb`, 코드·출력·메타데이터를 함께 담기 좋음 |
| 대화형 입력 | UI 입력과 셀 의존성을 기본 실행 모델에 연결 | ipywidgets의 함수 연결·이벤트 처리 등으로 구성 |
| 앱 형태 | 같은 노트북을 코드 숨김 앱으로 실행하는 경로 제공 | 목적에 맞는 배포·대시보드 도구를 별도로 검토 |
| AI | 편집기 보조 기능과 외부 에이전트 연결 제공 | JupyterLab의 Jupyter AI 같은 확장 선택지 존재 |
| 기존 작업과의 호환 | marimo의 변수 정의·의존성 규칙에 맞게 점검 필요 | 기존 `.ipynb` 자료·커널·확장 환경을 유지하기 유리 |

Jupyter에서는 [ipywidgets의 `interact`](https://ipywidgets.readthedocs.io/en/stable/examples/Using%20Interact.html)로 슬라이더 입력을 함수에 연결할 수 있습니다. marimo는 입력값에 의존하는 셀을 찾아 갱신하는 흐름을 기본 실행 모델에 포함합니다.

[Jupyter AI](https://jupyter-ai.readthedocs.io/en/stable/) 확장을 쓰면 JupyterLab에서도 에이전트와 대화하고 노트북을 편집·실행할 수 있습니다. 기존 환경에 추가하려면 확장 지원과 조직 정책을 확인하세요.

marimo를 새로 써볼 이유가 분명한 경우는 **입력 조건을 자주 바꾸며 여러 결과를 같이 갱신하는 분석**, 코드 변경을 중심으로 관리하고 싶은 노트북, 다른 사람에게 조작 가능한 분석 화면을 보여주는 작업입니다.

수업 자료와 제출 형식이 `.ipynb`이거나 팀에서 이미 JupyterHub·커널·확장을 운영한다면 Jupyter를 유지하는 편이 쉽습니다. R·Julia 커널을 쓰는 작업에도 Jupyter가 맞습니다. GPU 실험에는 GPU를 제공하는 실행 환경과 필요한 라이브러리를 따로 준비하세요.

## 전환 전에 살펴볼 제약

marimo의 자동 실행에는 코드 작성 규칙이 따릅니다. **여러 셀에서 같은 전역 변수 이름을 중복 정의할 수 없고**, 셀 간 의존성이 순환하지 않도록 구성해야 합니다. Jupyter에서 같은 `df`를 여러 셀에 걸쳐 계속 덮어쓰던 코드는 단계별 이름을 나누거나 함수로 묶는 식으로 정리해야 할 수 있습니다.

또 모든 상태 변화를 자동 추적하지는 않습니다. 공식 [반응형 실행 문서](https://docs.marimo.io/guides/reactivity/)는 리스트에 값을 추가하거나 객체 속성을 바꾸는 식의 변경이 다른 셀의 재실행을 자동으로 일으키지 않는다고 설명합니다. 변수를 정의한 셀에서 변경을 마치거나 새 변수로 결과를 전달하는 식으로 흐름을 분명하게 만드는 편이 좋습니다.

오래 걸리는 모델 학습이나 비용이 드는 API 요청도 주의할 부분입니다. marimo에는 자동 실행 대신 셀을 오래된 상태로 표시하는 *lazy* 설정, 셀 비활성화 등 실행을 통제하는 방법이 있습니다. 처음부터 전체 학습 노트북을 옮기기보다는 가벼운 분석 하나로 입력과 계산의 관계를 확인하는 편을 권합니다.

조건을 자주 바꾸는 작은 분석을 marimo로 옮겨보면 셀을 다시 실행하거나 조작 화면을 공유하는 일이 얼마나 줄어드는지 비교할 수 있습니다.
