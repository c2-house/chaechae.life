### 목차

## 들어가며

회의록을 Google Docs에서 고쳤는데 AI 노트북에 다시 올려야 할까요? 예전 NotebookLM 사용법에는 “Google 문서를 수정해도 자동으로 반영되지 않으니 직접 동기화해야 한다”는 설명이 많습니다. **현재 Google Drive에서 가져온 소스는 자동 업데이트 대상입니다.** 다만 컴퓨터에서 올린 파일까지 같은 방식으로 연결된다고 생각하면 안 됩니다.

NotebookLM은 현재 **Gemini Notebook**이라는 이름을 사용합니다. [공식 사이트](https://notebook.google/)는 같은 제품이며 기존 노트북에 대한 접근도 유지된다고 안내합니다. 이 글에서는 2026년 10월 20일 확인한 웹용 공식 도움말을 기준으로, 자동 갱신의 범위와 실제 자료를 대조할 순서를 정리했습니다. 계정에 파일을 올려 동기화 시간을 측정한 실험은 아닙니다.

중요한 것은 “소스 목록에 파일이 있다”가 아니라 **노트북이 읽는 내용과 지금 사용할 답변에 변경사항이 들어 있는지**입니다. 원본, 노트북 안의 소스, 이미 만들어 둔 요약을 나누어 보면 확인할 곳이 분명해집니다.

## Google Drive 소스의 자동 동기화

Google은 [2026년 5월 26일 발표](https://workspaceupdates.googleblog.com/2026/05/keep-your-sources-up-to-date-with-automatic-Drive-syncing-in-NotebookLM.html)에서 Google Docs·Sheets·Slides의 변경사항을 수동으로 갱신하던 방식에서 자동 동기화로 바꾼다고 안내했습니다. 배포는 그날 시작됐으며 모든 계정에 즉시 적용되는 발표는 아니었습니다.

현재 [소스 추가 도움말](https://support.google.com/gemininotebook/answer/16215270?hl=ko&co=GENIE.Platform%3DDesktop)은 Google Drive에서 가져온 소스가 **몇 분마다 동기화되며, 노트북을 열면 원본 문서의 변경사항이 자동으로 업데이트된다**고 설명합니다. 자동 동기화를 켜는 별도 사용자 설정은 없다는 것이 발표 당시 안내입니다.

따라서 계속 수정하는 회의록이라면 매번 PDF를 내려받아 올리는 것보다, 지원되는 문서를 Google Drive에서 가져오는 방식이 관리하기 편할 수 있습니다. 다만 “몇 분마다”를 정확히 몇 초 안에 반영된다는 보장으로 읽으면 안 됩니다. 마감일이나 금액처럼 중요한 값을 사용할 때는 소스 내용부터 대조하는 편이 좋습니다.

필요할 때는 수동 갱신도 가능합니다. 웹에서 해당 노트북을 열고 **소스 패널의 문서 선택 → 소스 뷰어 → ‘클릭하여 Google Drive와 동기화’** 순서로 확인합니다. 영어 도움말의 버튼 이름은 `Click to sync with Google Drive`입니다. 이 경로는 공식 안내이며, 모바일 앱에는 기능 제한이 있을 수 있습니다.

## 파일 형식보다 가져온 경로

같은 문서라도 **어떻게 넣었는지**가 중요합니다. Google Docs 내용을 복사해 붙여넣었다고 해서 그 소스가 원래 Google Docs와 연결되는 것은 아닙니다. 원본이 Drive에 있다는 사실과, 노트북에서 Drive 소스로 가져왔다는 사실을 구분해야 합니다.

| 넣은 방식 | 확인할 범위 | 원본을 고친 뒤의 행동 |
|---|---|---|
| Google Drive에서 가져오기 | 공식 자동 동기화 대상 | 노트북을 열고 소스 내용 대조, 필요하면 수동 동기화 |
| 컴퓨터의 PDF·문서 파일 업로드 | 업로드한 파일의 내용 | 로컬 수정만으로 갱신됐다고 판단하지 말고 최신 파일을 다시 추가해 확인 |
| 텍스트 복사·붙여넣기 | 붙여넣은 내용 | 원본과 대조한 최신 텍스트로 소스를 다시 준비 |
| 웹페이지 URL로 가져오기 | 해당 HTML 페이지에서 가져온 텍스트 | 원문과 소스 뷰어를 대조하고, 오래된 내용이면 최신 페이지를 다시 가져와 확인 |

**Drive 자동 동기화 안내를 로컬 파일이나 웹 URL 전체에 확대 적용하지 않는 것**이 이 표의 기준입니다. 소스가 여전히 이전 내용을 담고 있다면 질문을 바꿔 반복하는 것만으로 해결되지는 않습니다.

웹 URL에도 수집 범위가 있습니다. 공식 도움말에 따르면 일반 HTML 페이지는 텍스트만 가져오며, 이미지·삽입 동영상·연결된 하위 페이지까지 함께 가져오지 않습니다. URL이 가리키는 대상이 PDF이면 PDF 소스로 취급합니다. 사이트 주소 하나를 넣었다고 사이트 전체가 계속 최신 상태로 수집되는 것은 아닙니다.

자료를 교체할 때는 새 소스의 내용을 먼저 확인하고, 질문에 사용할 소스를 선택하세요. 이전 판과 새 판을 모두 선택한 채 “마감일이 언제야?”라고 물으면 서로 다른 시점의 자료가 섞일 수 있습니다. 과거 판을 비교하려는 경우가 아니라면 최신 판만 선택하는 것이 확인하기 쉽습니다. 불필요한 소스 삭제는 그다음에 판단해도 됩니다.

## 변경사항을 확인하는 순서

자동 동기화가 됐는지 확인하려고 긴 보고서를 다시 요약시킬 필요는 없습니다. **원본에서 바뀐 문장 하나를 골라 소스와 답변의 근거를 차례로 대조**하면 됩니다.

예를 들어 직접 소유한 연습용 Google Docs의 문장을 다음처럼 바꿨다고 가정하겠습니다. 실제 업무 일정이 아닌 설명용 예시입니다.

```text
이전 내용: 자료 제출 마감은 11월 3일입니다.
바꾼 내용: 자료 제출 마감은 11월 5일입니다.
```

1. **원본 확인:** Google Docs를 다시 열어 바꾼 문장이 저장되어 있는지 확인합니다. 다른 이름의 복사본을 수정한 것은 아닌지도 봅니다.
2. **가져오기 경로 확인:** 노트북의 소스가 해당 Drive 문서인지 확인합니다. 예전에 내려받은 PDF를 업로드한 소스라면 Drive 원본과 같은 경로가 아닙니다.
3. **소스 내용 확인:** 노트북을 열고 해당 소스의 뷰어에서 변경된 문장을 찾습니다. 아직 이전 내용이면 잠시 뒤 다시 확인하고, 수동 동기화 항목이 제공되면 사용합니다.
4. **질문 범위 선택:** 소스 패널에서 확인하려는 문서만 선택합니다. 이름이 비슷한 이전 파일이 함께 선택되어 있지 않은지 봅니다.
5. **새 답변과 인용 대조:** 마감일을 새로 묻고 인용을 눌러 근거 문장으로 이동합니다. 원본과 소스 뷰어, 답변의 근거가 같은 내용을 가리키는지 확인합니다.

질문은 다음처럼 좁힐 수 있습니다.

> 선택한 소스에서 자료 제출 마감일을 찾아줘. 근거 문장을 인용하고, 마감일이 여러 개 있으면 각각 어떤 자료의 어떤 일정인지 구분해줘.

이 **확인용 요청 예시**에서 볼 것은 답변의 날짜만이 아닙니다. ‘11월 5일’이라는 답과 함께 인용한 문장도 실제 변경된 문장과 일치해야 합니다.

[공식 채팅 도움말](https://support.google.com/gemininotebook/answer/16179559?hl=en)은 인용을 선택하면 해당 구절과 문맥으로 이동할 수 있다고 설명합니다. [소스 도움말](https://support.google.com/gemininotebook/answer/16215270?hl=ko&co=GENIE.Platform%3DDesktop)에 따르면 아주 짧은 소스는 개별 구절 대신 문서 전체가 참조될 수 있으므로, 이때는 소스 전체를 직접 대조합니다.

소스 뷰어에는 새 내용이 있는데 답변만 예전 내용을 말한다면, 동기화보다 **선택된 소스와 질문의 범위**를 먼저 확인하세요. 반대로 소스 뷰어부터 이전 내용이면 답변을 다듬기 전에 원본 연결과 갱신 상태를 확인해야 합니다. 원본 파일 자체가 열리지 않는다면 다음의 권한 문제를 먼저 봅니다.

## 접근 권한과 빠지는 내용

Drive 동기화는 단순한 내용 갱신만의 문제가 아닙니다. 현재 도움말은 파일을 가져오려면 **보기 권한 이상**이 필요하며, 원본 파일이 삭제되거나 접근 권한을 잃으면 노트북에서도 해당 소스를 더 이상 보거나 사용할 수 없다고 설명합니다. 소유한 노트북과 공유 노트북 모두에 적용됩니다.

따라서 “전에 가져왔으니 권한이 없어져도 계속 읽을 수 있겠지”라고 생각하면 안 됩니다. 접근할 수 없는 자료는 소유자에게 권한을 요청하거나, 사용할 수 있는 대체 자료를 준비해야 합니다. 권한을 우회하려고 별도 복사본을 만들어 올리는 방식으로 해결할 문제는 아닙니다.

목록 표시에는 문서 간 표현 차이가 있습니다. 5월 발표는 Drive에서 삭제된 파일이 노트북에서도 제거된다고 설명하지만, **현재 도움말은 비활성 소스도 소스 한도에 포함되며 노트북에서 참조되지 않는다고 안내**합니다. 파일 삭제 후 목록에서 곧바로 사라지는지를 전제로 삼기보다, 소스의 접근 가능 여부와 비활성 표시를 확인하는 편이 안전합니다. 계속 필요한 자료라면 소스에 제공된 링크로 접근 권한을 요청하고, 더 이상 쓰지 않는 자료라면 노트북의 소스 목록에서 제거할 수 있습니다.

내용이 빠졌다고 모두 동기화 오류는 아닙니다. Google 파일의 **각주와 댓글은 가져오지 않는다**는 제한도 있습니다. 변경사항을 문서 본문이 아니라 댓글에만 남겼다면, 본문이 갱신되어도 그 댓글을 근거로 답하지 못할 수 있습니다. 중요한 결정이 본문에 확정된 내용인지부터 확인하세요.

또한 Gemini Notebook은 Drive의 원본 파일을 수정하거나 삭제하는 도구가 아닙니다. 분석을 위해 소스 뷰어에서 표시 형식이 달라질 수 있지만, 그것이 원본 문서의 형식을 바꾸는 것은 아닙니다.

## 최신 소스와 이미 만든 요약

소스 갱신을 확인한 뒤에도 과거 채팅 답변이나 저장해 둔 보고서를 곧바로 최신 문서로 취급하지 않는 편이 좋습니다. **소스가 바뀌었다는 사실만으로 이전 산출물의 내용까지 검토된 것은 아니기 때문입니다.**

최신 일정으로 보고서를 내보낼 예정이라면, 갱신한 소스를 선택해 새 답변을 받고 필요한 산출물을 다시 생성하거나 수정한 뒤 바뀐 부분을 대조하세요. Google의 [보고서 도움말](https://support.google.com/gemininotebook/answer/18323649?hl=en)도 생성된 보고서에 오류가 있을 수 있어 정확성을 검토하도록 안내합니다. 자동 동기화를 답변의 정확성 보증으로 받아들이면 안 됩니다.

저라면 자료의 목적을 먼저 나누겠습니다. **계속 바뀌는 회의록에서 현재 상태를 묻는 용도**라면 Drive 연결을 사용하고 중요한 답은 인용까지 확인하겠습니다. 반면 **특정 날짜에 무엇을 근거로 판단했는지 남기는 용도**라면, 보관 권한이 있는 범위에서 그 시점의 원본과 확인 날짜를 별도로 기록하겠습니다. 자동으로 바뀌는 소스는 과거 시점의 증거를 고정해 두는 보관 방식과 목적이 다릅니다.

파일을 많이 넣는 것보다 이 구분이 먼저입니다. 원본을 고쳤다면 소스 뷰어에서 반영 여부를 확인하고, 새로 사용할 답의 근거까지 대조하면 됩니다. 원본과 정리본을 따로 관리하는 방법은 [옵시디언에서 원본 자료와 정리 노트 관리하기](/blog/obsidian-second-brain-sources)에서도 이어서 볼 수 있습니다.
